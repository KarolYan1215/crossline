# 从零开始使用 Crossline

这份文档只回答一个问题：**拿到这个仓库之后，该按什么顺序做，才能走完一次真实的闭环**——
从 `git clone` 到被采访、批准里程碑、看见自己第一件事被验收。每一步只给最少必要的操作；"为什么这样设计"
留给 [README.md](../README.md)（架构总览）和 [docs/user-guide.md](./user-guide.md)（账号、离线、
Tailscale、备份等基础设施细节），本文只在关键处指路，不重复。

---

## 0. 先决条件

- Node ≥ 22，pnpm 11.19.0（仓库根目录 `package.json` 的 `packageManager` 字段锁定了版本）。
- Windows（脚本和路径约定按 Windows 写；其他平台能跑但 `scripts/*.ps1` 用不了）。
- 一个能收邮件的邮箱，**或**一个 Google 账号——第 2 步注册登录二选一，至少要有一个。

```powershell
git clone <你的仓库地址>
cd Multi-ID
pnpm install
```

---

## 1. 最小配置：让登录这件事能发生

web 和 worker 读环境变量的地方不一样，**复制方式也不一样**，混了会看起来"配了但不生效"：

```powershell
copy .env.example apps\web\.env
copy .env.example .env.local
```

- `apps/web/.env`：Next.js 只读它自己项目目录下的 `.env`，根目录放一份会被静默忽略。
- 根目录的 `.env.local`（会被 `.gitignore` 忽略）：`pnpm worker` 的进程反过来**只读仓库根目录**的
  `.env.local`/`.env`，完全不看 `apps/worker/.env`——这是 `apps/worker/src/index.ts` 里的既有行为，
  不是这份指南自创的约定。

打开 `apps/web/.env`，必填：

```
BETTER_AUTH_SECRET=<随机 32+ 字节字符串>
CROSSLINE_SUPERVISOR_CAPABILITY_SECRET=<另一个随机 32+ 字节字符串，跟上面不同>
```

再打开根目录的 `.env.local`，把**同一个** `CROSSLINE_SUPERVISOR_CAPABILITY_SECRET` 值也填进去——
两边必须完全一致，这是 web 签发、worker 校验同一个 capability token 用的共享密钥。漏了这一步，
worker 会打印 `worker.blocked: CROSSLINE_SUPERVISOR_CAPABILITY_SECRET_MISSING` 然后**静默地**
不启动 Codex supervisor（3211 端口），日历同步、`worker.tick` 之类其他后台任务照常跑，
只有 Analyze / 材料准备 / 里程碑闸门 / 第 11 步的 Codex 登录看起来永远连不上——很容易被误判成
"Codex 本身有问题"，其实只是这一个环境变量放错了文件。

然后**至少**打开下面两条登录路径中的一条——不打开任何一条，任何人都注册不了账号：

- **Google 登录**（更快，不用等验证邮件）：填 `CROSSLINE_GOOGLE_CLIENT_ID`/`CROSSLINE_GOOGLE_CLIENT_SECRET`。
  从零申请这两个值的完整步骤见 [user-guide.md §2](./user-guide.md#2-google-登录)。
- **邮箱密码注册**：`CROSSLINE_SMTP_HOST`/`PORT`/`USER`/`PASSWORD`/`FROM` 五项**必须全部**填上，
  少一个邮箱注册就整个不存在（不是"注册了收不到邮件"）。免费方案（Resend）的具体填法见
  [user-guide.md §1](./user-guide.md#1-首次注册邮箱密码)。

其余变量（Microsoft Graph、content-ops、Longbridge、Codex 模型档位）现在都留空——它们只解锁可选功能，
不影响你把下面的闭环走一遍。Codex（采访、分析、手册、闸门、尽调）在第 9 步接上；采访本身需要 Codex，
只想先看看界面的话，没接 Codex 也能手工创建任务。

---

## 2. 启动

两个终端窗口，各跑一个：

```powershell
pnpm dev      # web，http://127.0.0.1:3210
pnpm worker   # 后台：分析、手册、里程碑闸门、日历同步、尽调、转写、屏幕活动、夜间飞轮
```

采访、分析、手册、闸门、尽调、录音转写、日历同步和屏幕活动都由 `worker` 在后台做，所以
**建议一开始就跟 `pnpm dev` 一起跑**。只想先看看界面、手工创建任务的话，可以先不开。

打开 `http://127.0.0.1:3210`，会跳到 `/login`。

（长期挂在后台跑，用 `scripts\start-crossline.ps1` 代替这两个命令——前提是先 `pnpm build`
过一次；细节见 README「快速开始」一节。）

---

## 3. 注册并登录

- 点"没有账号？注册" → `/signup`，填邮箱、密码（≥8 位）、名字 → 收验证邮件 → 点链接 → 回 `/login` 登录。
- 或者直接点"使用 Google 登录"，走 Google 授权页。

登录成功后自动跳回首页 `/`。**这一步会在后台真正发生的事**（第一次建号）：系统给你建一个全新的、
空的 workspace——不会自动带出磁盘上任何旧数据。如果你之前手工跑过这个仓库、`data/` 目录下已经有
一份账本，那份数据依然在，只是新注册的账号看不到它，这是有意的隔离，不是 bug。

---

## 4. 第一次进来：先被采访

新账号是空的，首页会把你带到 `/onboarding`。第一屏先**设定主线**：写下几个身份（研究者、创业者……），拖出未来 12–24 个月的主次（不排的平行），最多两条标为硬约束（它们的固定日程是日历骨架、截止优先）。

接着是**添加材料**：简历、课表、课程大纲、项目说明，有多少放多少，然后点「读完材料，开始访谈」（没有材料就点「没有材料，直接开始」）。第一轮先从材料里读出能读的，只问还缺的。

**可开始标准。** 以下五条都满足之前，除访谈、设置和登录以外的页面都会回到访谈页，页面上写明「开始使用前还差 N 项」以及每项在哪里补；已有账号也一样：

1. 每条主线有一句描述；
2. 知道每周可用时间；
3. 硬约束主线的固定安排已知（或已上传含这些信息的文件）；
4. 每条主线至少一个当前项目，并知道截止日期或「没有截止」；
5. 每条主线的长期目标由本人采用（在右侧画像下点选定语后「采用」）。

这五条只认本人的回答或文件，不认系统的假设。五条满足后访谈页出现「开始使用」，首次看到的排期由此而来；画像访谈在同一处继续，没答的问题也会列在待决事项，可以在那里逐个回答。访谈分两段：前段（开场与规则、主线）收齐这五条，后段（现状、指南针、能量、细节）写画像。之后仍是一场分阶段的对话，不是表单：

- 每轮系统会一次问一批互不依赖的问题，逐条作答，并**过量给出候选答案**（你认出自己的情况比凭空回忆容易）。可以点选，也可以自己写。
- 到「主线」阶段（第二段），每条主线会有一段个性化描述和 6–12 个定语候选，点选后组成「成为 A 的、B 的<身份>」并采用；同时会问每条主线当前在做的项目和截止。答「不确定」的非必需项，系统当轮写成「假设：……」并说明可随时修改。
- 结束时生成一份画像报告（`/portrait`），可导出 PDF 或图片，分享版会隐去个人信息。
- 右侧是实时画像：已识别的项目、事实（每条带出处）、各主线之间的联系预览。事实可以点开改。
- 可以直接把**课程大纲、论文草稿、日程文件**拖进来。系统读完后会把文件里的日期整理成一张**批量卡片**，你一键确认或逐条剔除，确认后进入日历。
- 也可以上传**录音**。录音在本机转写（首次需要你同意下载约 255 MB 的语音模型，页面上有按钮并写明来源和大小）。
- 对话里提到的事实只有在你亲口说过或文件里有原文时才会标成「已确认」；系统自己推断的会标成「推断」，不会覆盖你已确认的。

这一步要先接好 Codex（见第 9 步），否则没有模型来问问题。

采访告一段落后，系统会在后台做两件事：

1. **AI 尽调**：对创业、自媒体、科研、投资各查一轮公开资料（比赛与孵化器的截止日、赛道上的真实账号、领域文献等）。**每个来源都由 worker 真的打开核对**，打不开或内容对不上的会被丢掉。结果是「基于这些事实，建议……」的卡片，你接受的才会进入下一步。
2. **里程碑草稿**：每条主线至少 3 个；**你说得具体的每个项目都有自己的一条链**（一条线下有几个项目，就各自排先后和截止，不会只剩最急的那个）；都带可量化目标和截止，且必须引用画像里的事实。每个里程碑必须是**一件到期那天能核对的事**（比如“ECE 555 期中考试取得 80 分以上”“提交 CAD 项目”），“保持某种状态”“稳定推进”这类写法会被拒收重写。里程碑是**一条主线一条主线分别生成**的：某条线信息太少或这次没生成成功，会明说是哪条、为什么，不影响其他线。它们都是草稿，在「待确认」里等你批准。同时会提出**不同主线之间的联系**（比如科研的图表流程可以复用到创业的演示材料），作为虚线连线出现在「主线」页，带依据和“什么情况说明它不成立”，你逐条采纳或不要。

## 5. 批准里程碑，然后收集任务

在 `/approvals`（顶栏「待确认」，有角标）能看到所有等你决定的事：里程碑草稿、计划差异、采访带来的调研建议和日期批次，每一项都列出来、点进去处理。里程碑草稿在「主线」页批准或修改。**分析和闸门只认已批准的里程碑**，所以不批准就不会有任何东西被替你推进。

回到 `/`（今日），在「快速收集」里用自然语言写一件真实的事（可以补充上下文或粘链接）。**没有身份下拉框、没有时长输入框**。

## 6. 任务：分析、手册、执行

打开 `/workbench`。你刚才那条收集是一张未分类的卡片：

- **不用点**：只要你已经批准了至少一个里程碑，worker 每个周期会自动分析新的收集（额度正常时，每个周期最多 3 条；分析过但被阻塞的不会自动重试，等你补充上下文后再点「分析」）。也可以手动点 **分析**：模型判断它属于哪条主线、拆成哪几步、要什么证据、估时区间，结果出现在「待确认」，批准后成为正式任务。
- 不想用 AI 的话，点「改为手工创建」自己填（人工创建本身就是批准动作）。
- 已批准且需要准备材料的任务，worker 会自动生成一本**手册**：一张流程图，每个节点有「做什么 / 分析 / 教程 / 来源」。来源都是真实打开过的公开网页，只有开放获取的论文才会下载全文。手册在任务详情页里看。
- 执行：开始 → 暂停（必须写中断原因，这段时间与工作时长分开记）→ 恢复 → 完成并提交证据。

## 7. 计划与日历

打开 `/plan`。日 / 周 / 月三种视图共用同一份计划：你的日历（只读导入）、文件里确认过的日期、以及排程器给任务排的时段。**排程是随时重算的，不是承诺**；改了「设置」里的可用时间，下次打开就按新的排。计划差异折叠在日历下方，有待处理项时会自动展开，整批批准。

## 8. 验收与复盘

- 没绑里程碑的任务：在 `/approvals` 点「验收」即可。
- 绑了里程碑的任务：由 Codex 判定这份证据是否兑现了任务自己承诺的交付（worker 每 15 分钟判一轮，也可点「现在判定」）。判 pass 就自动验收，**觉得判错了可以撤销**，退回证据复核且不丢证据。
- `/milestones` 看每条主线的流程图和各里程碑标准的达成情况；每周的自动验收、飞轮发现、候选关系批量批准都在这里和待确认里。

## 9. 接上 Codex

打开 `/settings`，在「连接与账号」里找到 Codex 卡片，点「请求 ChatGPT 授权」，在官方页面登录，回来会显示「已登录」。这是**这台机器独立的** ChatGPT 登录，不读取你桌面上其他 Codex 客户端的状态。接好之后：采访、分析、手册、闸门、尽调、飞轮才真的会跑；设置页的「模型用量」会显示每个功能近 7 天用了多少。

额度紧张时系统会自动把部分功能降一档模型（里程碑闸门和任务分析不降）；读不到额度时拒绝执行而不是当成 0%。

## 10. 可选：屏幕活动

首次进今日会问你要不要开。三档：不开；只记每天的活跃分钟数；或再加前台应用名与窗口标题。开了详细档之后，今日会显示「此刻状态」（专注 / 频繁切换 / 会议中 / 离开键盘 / 娱乐 / 说不准），日历里会画出「实际」做了什么。

要知道的几件事：窗口标题只存在这台电脑上，不会发给任何模型，14 天后自动抹掉；银行、密码管理器、无痕窗口**完全不记录**；可以随时暂停（1 小时 / 4 小时 / 到明天），可以加自己的「不要记录」词，可以在设置里查看系统存了什么、一键清除标题。

## 11. 移动端

用手机浏览器打开同一个地址（本机以外访问先按 [user-guide.md §4](./user-guide.md#4-tailscale-绑定私网跨设备访问) 接 Tailscale 私网）。屏幕窄于 680px 时，顶部导航换成底部的 tab 栏。
