# 从零开始使用 Crossline

这份文档只回答一个问题：**拿到这个仓库之后，该按什么顺序做，才能走完一次真实的闭环**——
从 `git clone` 到看见自己第一件事被验收。每一步只给最少必要的操作；"为什么这样设计"
留给 [README.md](../README.md)（架构总览）和 [docs/user-guide.md](./user-guide.md)（账号、离线、
Tailscale、备份等基础设施细节），本文只在关键处指路，不重复。

---

## 0. 先决条件

- Node ≥ 22，pnpm 11.19.0（仓库根目录 `package.json` 的 `packageManager` 字段锁定了版本）。
- Windows（脚本和路径约定按 Windows 写；其他平台能跑但 `scripts/*.ps1` 用不了）。
- 一个能收邮件的邮箱，**或**一个 Google 账号——第 2 步注册登录二选一，至少要有一个。

```powershell
git clone <你的仓库地址>
cd Multi-ID
pnpm install
```

---

## 1. 最小配置：让登录这件事能发生

Next.js 只读它自己项目目录下的 `.env`，根目录放一份会被静默忽略——所以是**复制两份**：

```powershell
copy .env.example apps\web\.env
copy .env.example apps\worker\.env
```

打开这两份文件，必填这两项（两份文件里必须填**同一个值**）：

```
BETTER_AUTH_SECRET=<随机 32+ 字节字符串>
CROSSLINE_SUPERVISOR_CAPABILITY_SECRET=<另一个随机 32+ 字节字符串，跟上面不同>
```

然后**至少**打开下面两条登录路径中的一条——不打开任何一条，任何人都注册不了账号：

- **Google 登录**（更快，不用等验证邮件）：填 `CROSSLINE_GOOGLE_CLIENT_ID`/`CROSSLINE_GOOGLE_CLIENT_SECRET`。
  从零申请这两个值的完整步骤见 [user-guide.md §2](./user-guide.md#2-google-登录)。
- **邮箱密码注册**：`CROSSLINE_SMTP_HOST`/`PORT`/`USER`/`PASSWORD`/`FROM` 五项**必须全部**填上，
  少一个邮箱注册就整个不存在（不是"注册了收不到邮件"）。免费方案（Resend）的具体填法见
  [user-guide.md §1](./user-guide.md#1-首次注册邮箱密码)。

其余变量（Microsoft Graph、content-ops、Longbridge、Codex 模型档位）现在都留空——它们只解锁可选功能，
不影响你把下面的闭环走一遍。Codex（AI 分类/材料准备/里程碑闸门/飞轮）单独在第 8 步讲，
**在那之前完全可以用手工路径体验产品**。

---

## 2. 启动

两个终端窗口，各跑一个：

```powershell
pnpm dev      # web，http://127.0.0.1:3210
pnpm worker   # 后台 tick：材料准备、里程碑闸门、日历同步、夜间飞轮
```

`pnpm worker` 现在可以先不开——手工创建的作业不经过材料准备，直接执行，`worker` 只有在你走到
第 8 步接上 Codex、或想要日历同步时才是必需的。但**开着也无害**，建议一开始就跟 `pnpm dev`
一起跑，省得后面忘记。

打开 `http://127.0.0.1:3210`，会跳到 `/login`。

（长期挂在后台跑，用 `scripts\start-crossline.ps1` 代替这两个命令——前提是先 `pnpm build`
过一次；细节见 README「快速开始」一节。）

---

## 3. 注册并登录

- 点"没有账号？注册" → `/signup`，填邮箱、密码（≥8 位）、名字 → 收验证邮件 → 点链接 → 回 `/login` 登录。
- 或者直接点"使用 Google 登录"，走 Google 授权页。

登录成功后自动跳回首页 `/`。**这一步会在后台真正发生的事**（第一次真正建号）：系统给你建一个全新的、
空的 workspace——不会自动带出磁盘上任何旧数据。如果你之前手工跑过这个仓库、`data/` 目录下已经有
一份账本，那份数据依然在，只是新注册的账号看不到它，这是有意的隔离，不是 bug。

---

## 4. 第一次进 Today：认识这个页面

刚登录会看到几样东西，都是首次访问自动生成的**示例内容**，不是你必须先完成的任务：

- 一个"要不要开启本机活动采集？"的横幅——**先点"稍后再说"**，下次还会再问，不影响任何其他功能。
- 四条示例 WorkOrder（科研/创业/自媒体/投资各一条），已经处于"可开始"状态，可以直接点"开始执行"玩一下
  ExecutionActions 的流程（暂停要写原因、完成要选是否带证据）——但它们不是真实工作，跳过也完全没问题。
- 页面顶部有一个 PROGRESS 区块（本周完成数 / 连续天数 / 各身份累计完成数），现在全是 0，
  这是真实统计，不是占位符——今天做点什么它就会变。

**做你的第一次真实收集**：在"快速收集"输入框里，用自然语言写一件真实想做的事（可以补充上下文，
或直接粘一个链接），点 "CAPTURE ↗"。**没有身份下拉框、没有时长输入框**——这两样接下来在 Workbench
里处理，不是这一步的事。

---

## 5. 去 Workbench：把这条收集变成可执行的作业

打开 "WORKBENCH"，你刚才那条收集会显示成一张 `CAPTURE` 卡片，未分类、未估时。这里有两条路，
选哪条取决于你是否已经接好 Codex（第 8 步）：

**路径 A · 已接好 Codex**：点 "Analyze · 分析"，等一会（后台真的在跑一次模型调用，
不是假装转圈），刷新后这条收集变成一个待批准的 AI 提案——去 Approvals 页看它、批准它，
然后回到这里，它就成了正常的 WorkOrder，走下面第 6 步。

**路径 B · 还没接 Codex，或这次就想跳过 AI**：点 "改为手工创建 →"，填这个小表单：

- 这件事要做什么（必填）
- 属于哪条主线（身份下拉，只有四条种子身份，选一个）
- 绑定的里程碑（**可以不选**——不是每件真实工作都非要挂在一个里程碑下面，这是刻意允许的）；
  下拉只会显示你刚才选的那条主线下面**属于它自己**的里程碑，换身份会自动清空这一项
- 类型（可不选，选了的话，将来这个 (身份, 类型) 组合积累到真实完成记录后，估时会自动变准；
  不选也完全能用，只是这一项永远吃不到个人历史校准）
- p25/p50/p85 估时（分钟，自己估一个大概区间）
- 完成时要交出的证据（每行一条，至少写一条，比如"一段结论记录"）

提交后这条作业直接进入"已批准"状态（人工创建本身就是批准动作，不会再让你对自己的决定二次确认），
卡片上会标"人工创建 · 未经 AI 分析"——不会假装它经过了分析。

---

## 6. 去 Plan：看它被排到了哪天

打开 "PLAN"。第一次打开会看到一条可展开的提示："以下是按默认时区/时段生成的预览，还不是你的真实
设置"——**不点开也完全能看真实内容**，下面的排程已经在用一组合理默认值（美中时区、留缓冲模式）算出来了。
想要更准，点开填一次真实时区、每周可用时段、排程模式；只填一次，以后都记得。

三个视图共用同一份计划：

- **B · 双轨时间轴**：上轨"现实"（日历导入 + 人工核心块），下轨"AI Ahead"（排程器算出的建议，
  没批准过，随时可能因为你改了可用时间而变）。你第 5 步创建的作业应该已经出现在某个时间段里。
- **C · 计划差异**：如果接了真实日历，这里会出现 Added/Moved/Removed/Conflict，可以批量批准或逐条排除。
  第一次用、没接日历的话这里通常是空的。
- **A · 日/周**：整周视图，翻页看接下来几天。

这一步是只读的——你不需要在这里做任何操作，回 Workbench 去真正执行。

---

## 7. 回 Workbench：执行、提交证据

找到刚才那个 WorkOrder（"可开始"状态），按顺序点：

1. **开始执行**——可选先做一次"开始前精力"自评（L/M/H），不做也行。
2. 中途如果要暂停，**必须填一句中断原因**（这段时间会跟真正的工作时长分开记录，不会被算成"做得慢"）；
   点"继续"恢复。
3. 做完点 **"提交完成与证据"**（填了证据位置+说明才会显示这个文案，都留空则显示
   "完成（记为无证据）"，milestone 绑定的作业不能用空证据验收，见下一步）。

---

## 8. 去 Approvals：验收

打开 "APPROVALS"，刚提交的证据会出现在这里，分两种情况：

- **没绑里程碑**：直接看到"验收证据"按钮，点一下，状态变 `accepted`，PROGRESS 区块的数字会跟着动。
  不想要这次结果也可以"退回并阻塞"（要填退回原因）。
- **绑了里程碑**：显示"等待里程碑闸门"，这一步需要 Codex 判定这份证据是否真的兑现了作业的交付承诺
  （不是判整个里程碑达成——里程碑本身的进展另外记录，在 Review 页看）。`worker` 每 15 分钟自动判一轮，
  也可以点"现在判定"立即触发（约一两分钟出结果，刷新页面看）。**这一步需要 Codex 已接好**——
  这是唯一一处手工路径也绕不开 AI 的地方，因为"证据够不够"本身就是需要判断的事。判过之后自动验收，
  觉得判错了可以撤销，退回证据复核且不丢证据。

---

## 9. 去 Review：看这周做了什么

打开 "REVIEW"。这里能看到：本周所有自动验收记录（逐条列出，不折叠成一个数字）、每条里程碑标准
目前的达成情况（每条独立判定，不是笼统的"完成度"）、候选关系（飞轮找到的、还没批准的跨身份关系）。
如果你只走了手工路径、没验收任何里程碑绑定的作业，这里大部分会显示空——如实反映真实状态，
不是页面坏了。

---

## 10. 给自己写第一条真正的里程碑标准

打开 "MILESTONES"，四条种子里程碑会显示"未声明达成标准 —— 闸门会拒绝它，直到你写下什么算达成"
的警告，旁边有"立即补充 →"按钮，点开直接进编辑态。写标准时：

- 至少一条应该衡量"结果"而不是"产出物"——只写"交一份文档"这种产出物，闸门可能靠写完文档就判过，
  而你真正想推进的目标一步没动。
- 如果用"判断"类型的标准，必须写清楚"什么情况判不过"（`failsWhen`）——"做得好"不是标准，
  "读者不追问就复现不了步骤"才是。

修改会写成新版本，不覆盖旧版本——闸门判过的那一版永远可以追溯回去看。

---

## 11. 接上 Codex：解锁 AI 分类 / 材料准备 / 里程碑闸门 / 飞轮

打开 "CONNECTIONS"，找到 "Codex sidecar" 卡片，点"请求 ChatGPT 授权"，跳到官方登录页，
用你的 ChatGPT 账号登录并授权，回到页面会显示"已登录"和账号邮箱。接好之后：

- Workbench 里新收集的卡片就能真的点"Analyze · 分析"了。
- 已批准的作业进入"材料准备中"状态时，`worker` 会自动调用 `crossline-material-preparer` 准备材料。
- 绑了里程碑的证据提交后，`worker`（或"现在判定"按钮）会真的调用 `crossline-milestone-gate` 判定。
- Review 页的"飞轮"（跨身份关系发现）会在夜间配额窗口刷新时自动跑一次，前提是那时候你没在用电脑。

这一步跟本机 3211 端口的 Codex app-server sidecar 通信，认证token 30 秒过期、按请求现签，
细节不需要你关心；只需要知道这是**这台机器独立的** ChatGPT 登录状态，不读取你桌面上其他
Codex/ChatGPT 客户端已经登录的状态。

---

## 12. 移动端

用手机浏览器打开同一个地址（如果只是本机，先看 [user-guide.md §4](./user-guide.md#4-tailscale-绑定私网跨设备访问)
把 Tailscale 私网接上，才能从手机访问到这台电脑）。屏幕窄于 680px 时，顶部文字导航会自动换成
底部四个图标+一个"更多"的 tab 栏，点"更多"展开 Milestones / Review / Connections。
