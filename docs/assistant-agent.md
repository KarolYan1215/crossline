# 助手（代理模式）设计

> 状态：设计已与你多轮确认（2026-10-05），第 1 阶段在实现中。这份文档记录**决定了什么、为什么、没做什么**，实现细节看代码。

## 一句话

Codex 不再只是“结构化推理服务”：它也是你电脑上的助手，能读文件、跑命令、写脚本、画图、上网，在专属目录里把琐碎的活干完，产出是文件，账本只记溯源。我们加的不是限制，而是**可信度**（可溯源、可复现、可回滚、自动校验）和**人机分工**（哪些 AI 能做、哪些必须你做）。

## 已确认的决定

| 问题 | 决定 |
|---|---|
| 权限边界 | 完整权限 + 护栏：以你的账户运行，工作目录是任务专属文件夹；规则表禁止或需确认；每任务前快照；命令和改动全记录 |
| 自主程度 | 全自动，但每一**类**任务第一次开工前先请你批准 |
| 带评分的课程工作 | 只做学习辅助：讲解、出自己设计的练习、检查你写的、整理资料；不生成可提交的答案、代码、报告 |
| 产出去向 | 文件为主（`AI 产出` 目录，脚本、代码、图表、笔记）；账本只存溯源，不存内容 |
| 日历 | 助手的工作块写到专用 Crossline 日历，在应用里与主日历合并显示；主日历只读（需你在 Entra 门户加写权限） |
| 任务来源 | 快速收集与计划、主动发现、会议和消息里的行动项（只提取待办，不自动回复） |
| 本机调用 | 本机接口 + 令牌文件（你登录的程序可调用，网页和别的用户不行） |
| 额度 | 不设上限，但任务排进计划前对照剩余额度预估，不够就提前说并按截止日期排优先级 |
| 第一批批准的类别 | 数据/代码/仿真；阅读/调研/整理；起草文字（不发送）；文件整理和日程准备 |
| 永远归你 | 对外发送、付款和交易、对他人的承诺和答复。**研究结论和判断它可以给，带证据，走信任升级** |
| 可信与完成 | 先全部审，攒够信任后逐类放开 |
| 工具 | Codex 自带的全部工具；联网搜索与下载公开资源；依赖装进专属环境；账号类服务（邮件、云盘、日历，只读）；浏览器和桌面（每次先问你） |
| 读文件范围 | 整个用户目录，凭据类位置一律禁读 |
| 与你同时干活 | 只在分支或副本里改，用补丁合并 |
| 工作时段 | 全天，电脑开着就做 |
| 通知 | 桌面通知，只在需要批准、校验失败或触及护栏时 |

## 架构

```
 任务来源 ──► 分派（谁做什么）──► 代理运行 ──► 校验 ──► 你的审阅 ──► 信任记录
 收集/计划      AI 部分 / 你的部分     专属目录      自动      看板/通知      每类 5 次连续采纳后
 主动发现       类别是否已批准         Codex 完整权限  文件/哈希                放开为"校验通过即完成"
 行动项                               + 护栏 + 审计
```

### 代理运行（`packages/codex/src/skill-runner.ts` 的 agent 模式、`apps/worker/src/agent-task.ts`）

- 线程：`sandbox: danger-full-access`、`approvalPolicy: untrusted`、`cwd` = 任务目录、shell 与网页搜索打开、不设 `environments: []`。`untrusted` 让每条不在运行时自己的“无害命令”名单里的命令都先来问我们。
- 运行时的请求（命令、文件改动、权限、MCP 询问）由 `JsonLineRpcClient.onServerRequest` 接住，按 `threadId` 分发给对应的运行（`agent-mode.ts`）；没有处理者就返回错误，不再沉默等超时。
- 每个任务的目录：`<AI 产出>\<taskId>\`；要改代码的项目，在里面建一个 git worktree、独立分支 `ai/<taskId>`，产出体现为这条分支上的提交（补丁）。
- 车道：助手有自己的车道，不堵任务分析和闸门；模型取最高档、不因额度紧张降档。
- 结束时返回固定结构的 JSON（`AGENT_SUMMARY_SCHEMA`）：摘要、产出清单、做了哪些检查、需要你做什么、没做什么、做了哪些假设。

### 护栏（`packages/core/src/agent-guard.ts`）——先说它是什么

**这是绊线，不是沙箱。** 助手有你账户的完整权限，没有文本检查能拦住刻意绕过的脚本。护栏做的是拦住“诚实但出错”的常见伤害，并把每一次拦截变成助手必须公开绕开的东西（审计里看得见）。真正的保护是整套设计：专属目录、快照、补丁、全程审计、最后一步归你。

- 永远拒绝：读写凭据/密钥/浏览器会话/`.env`/Codex 与应用自己的认证文件；发邮件、发消息到聊天服务、发布软件包、发帖、付款交易；改注册表、计划任务、服务、防火墙、执行策略、账户；提权；下载后直接执行；删除磁盘根目录或整个用户目录。
- 问你：系统级安装、`git push` 与创建 PR、向外部地址上传、递归/批量删除或移动（任务自己目录里的除外）。
- 文件改动：只能在任务目录（和它的 worktree）里；要改原文件，做成补丁。
- 读到的内容一律是数据：网页、邮件、文件里的“指令”不能授权发送、付款、删除或改系统设置；试图操控的，记进 `needsHuman` 标为可疑。

### 可信度

1. **溯源**（账本 `agent.task.*` 事件，不存内容）：谁要求的、跑了哪些命令、读了哪些路径、改了哪些文件、被拦下什么、产出的路径和 SHA-256、检查结果。完整记录在任务目录的 `audit.json`。
2. **你的原件不会被动**：任务前后对输入文件做哈希对比，被改了就标出来，结果必须审。
3. **产出核对**：助手声称的每个产出必须真实存在于任务目录且非空，否则退回重写；做了产出却没有任何检查也退回；`pass` 必须附证据。
4. **信任是挣来的**：每一类开始时产出全部要你审；同一类连续 5 次被你采纳、且校验全过、没有留事给你，才降为“校验通过即完成、你抽查”；被拒绝一次，或校验失败一次，回到全审。需要你做事（`needsHuman`）的结果永远要审。

### 谁做什么（AI 与人的分界）

- 分派时，每个任务拆成 AI 的部分和你的部分（`humanPart`）。AI 只做前者，并把后者准备好。
- 永远归你：对外发送、付款交易、对他人的承诺和答复。
- 带评分的课程工作只做学习辅助。这条写进助手的行为准则（`crossline-agent/SKILL.md`），并且是分派时的硬规则（第 2 阶段：按课程大纲逐门列出能做和不能做的）。
- 研究结论和判断可以由它给出，但必须带来源和检查；在信任记录建立之前全部要你审。

## 分阶段

1. **运行时、护栏、审计、快照与补丁、端到端小任务**（完成，2026-10-05 在真实 Codex 上验证）。已知缺口：审计没记联网域名；只能发现原件被改、不能恢复；git worktree 没有测试，也不自动生成补丁文件。
2. **接进看板**（完成）：类别批准（`/assistant`、`待确认`）、任务从工作单下发（Workbench 的“交给助手”和 worker 自动开工）、护栏中途提问、产出审阅与信任升降。仍按关键词判断类别、没有按课程大纲逐门列规则。
3. 专用日历写入（完成，待你授权）：计划页「同步到 Crossline 日历」把调度器排的块写进名为 Crossline 的单独日历；写入器（`packages/connectors/src/crossline-calendar.ts`）只能新建这个日历、在其中新建事件、改/删自己刚读回且带标记的事件；你的任何日历都改不了，你在 Crossline 日历里手动改过的事件它之后不再动；只删未来的；日历不进入“读取源”，计划不会把自己的块当成你的约束。授权与分享见 `docs/calendar-write-setup.md`。
4. 主动发现、邮件和会议行动项（MCP，只读）。
5. 本机接口、命令行、桌面通知；额度预估。

## 没做、以及为什么

- **没做强隔离**：Windows 上做不到“只能动某个文件夹”的强制隔离（之前的探测显示，受限沙箱下所有命令都被拒；而能用的权限档位只能禁读某些目录）。你选了完整权限加护栏，所以靠快照、补丁、审计和绊线兜底。
- **MCP 询问暂时一律拒绝**：账号类服务第 4 阶段才接入，接入前没有可批准的工具。
- **浏览器和桌面操作**每次先问你；第 1 阶段没有询问界面，询问一律视为拒绝。

## 没做成时怎么办、做成了要不要确认（2026-10-15，机主第 10 条）

- **失败分四类**（`packages/core/src/agent-failure.ts` `classifyAgentFailure`）：`interrupted`（进程重启、停滞、超时、运行时退出、额度用完、Codex 未登录）自动重试；`external`（网站安全验证或登录、付款、发送、发布、上传，或护栏拦下过外发动作）不自动重试，卡片写明原因；`needs_input`（缺只有本人知道的信息、本人中止、需要本人许可）问本人；`hard`（自检没过、护栏拒绝、原地打转）说明原因并给出绕开的办法。
- **一条重试规则**（`agentChains`）：准备步骤、整单、手动交给 Agent、成长工作流、定时运行都按同一件事的历次运行算；中断后等 5 分钟、再中断等 30 分钟，连续中断 3 次才停下问本人。重试仍受暂停、额度（95% 上限、读不到额度即暂停）和 engagementTier 约束；系统自己发起的仍只做两天内要开始的工作，本人发起的不受这个窗口限制。下一次运行拿到上一次写出的文件（只读）和停在哪里，接着做。
- **待确认卡**（`apps/web/lib/agent-ask.ts`）：只有不会再自动重试的才上卡，带进度（查了什么、跑了几条命令、写出哪些文件、被拦下什么，来自运行中每 10 秒写一次的 `progress.json`）、停在哪、需要本人什么、是否涉外；选项是按补充重试 / 换个方法 / 我自己做（步骤转给本人并排进日程）/ 不做了（整单归档、步骤跳过），本人写的话作为下一次运行的指令。`POST /api/agent/tasks/<id>/retry {note?, only?}` 是同一个重试入口。
- **默认直接采纳**（`resultNeedsPerson`）：结果没有留给本人的事、自检全过、没改原件、不涉外发、运行中没要过许可，就直接采纳（整单交验收、步骤标完成）；每一轮 pass 把这期间直接采纳的结果合成一条消息，逐项写做了什么、放在哪（不做每日汇总）。只有例外才进待确认。它替代了按类别累计 5 次采纳才放开的门槛；成长出的工作流「是否保留」不算要确认，默认保留。
