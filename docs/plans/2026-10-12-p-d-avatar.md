# P-D 形象定制与浮窗：实施计划

> 依据：`docs/loop-and-scout.md` §7「卡通形象由本人定制」「形象代替小助手作为浮窗」两条、§7 跑通标准「形象」一行、§12 P-D。
> 执行方式：按任务顺序做，每个任务先写失败的测试，再写最少的实现，再跑验证命令。标 **【真实 Codex】** 的任务会花本人的模型额度，只在本人同意后运行，绝不作为测试的副作用。

**目标**：本人在画像写完后填一张独立小表单（衣服颜色、性别、MBTI 可选、一句外貌可选），系统据此画出站立图（探针通过时再加坐姿图）；形象与画像报告版本脱钩；全站浮窗由这个形象代替「小助手」按钮，用纯 CSS 表现待机、思考、说话、点头、挥手五种状态；没有形象时浮窗与现在完全一致。

**架构**：
- **偏好**：设置 `portrait.character.prefs`（`CharacterPrefs`，校验与 MBTI→姿势/表情映射在 `packages/core/src/character-prefs.ts`）。只有插画器、偏好路由和设置卡读写它，由一条发现式测试守住。
- **形象状态**：设置 `portrait.character`（`{ fingerprint, props, images: { stand?, sit? }, status, note, at }`），文件 `<dataDir>/portrait/<workspace>/character-<fingerprint>-<pose>.png`。指纹 = 偏好（含重画次数）的 sha256 前 12 位，与报告版本无关。
- **生成**：`apps/worker/src/portrait-illustrator.ts` 改为 `createCharacterIllustrator`，只由新的监督路由 `POST /v1/portrait/character` 触发（保存表单或点「重画」），`writePortrait` 不再画图。出图方式（同线程两回合 / 一张两格拼图切开 / 只画站立）由 Phase 0 探针决定，写成常量 `CHARACTER_DRAW_MODE`。
- **浮窗**：`apps/web/app/assistant-widget.tsx` 先读 `GET /api/portrait/character`；没有站立图时渲染现在的标记不变，有则渲染 `apps/web/app/avatar-float.tsx`。状态由纯函数 `apps/web/app/avatar-state.ts` 决定，动画全部在 `apps/web/app/avatar-float.css`。

**约束**：
- pnpm（Node ≥ 22）；单测 `pnpm vitest run <file>`；类型 `pnpm --filter <pkg> typecheck`；收尾 `pnpm verify`（typecheck + test + build + e2e）。
- **不提交**，除非本人明确要求；下文的「建议提交点」只是可以停下来提交的位置。提交时用 `GIT_AUTHOR_*`/`GIT_COMMITTER_*` 环境变量（见记忆），不跳过钩子。
- YAGNI：不做「是否同一人物」的自动判定；不生成举牌图（徽标由页面画）；不加图像库，除非探针选中拼图方式（那时才给 worker 加 `sharp`）；不给 API key 登录单独做探测，生成失败即走兜底。
- UI 文案遵守 `docs/copy-style.md`（第三人称、无游戏化、12px 以上、7:1 对比度）；代码注释英文。
- 安全边界不变：不收照片，不画真人肖像，图里不出现文字和标志；偏好不进访谈线程、不进 profile 事实、画像 writer 看不到。

## 风险

- **两种出图方式都不稳定**：按规则退到只画站立图，坐姿回落站立；浮窗照常工作，只是夜间不换姿势。
- **`num_last_images_to_include` 取到的不是上一张**：`tool.rs` 注明它是「尽力而为」，会包含窗口内较新的无关图片。Skill 线程每次新开、只有一张前图，风险低；探针会如实暴露。
- **拼图的中线不干净**：人物跨过中线时切开会断肢。判定规则要求本人看对照页确认；只按宽高比通过不算。
- **方形背景当浮窗**：`CHARACTER_STANDARD` 的米色方底加色圆，在页面右下角是一张小卡片。用圆角与细边框接受它；不另画透明底版本（YAGNI），若本人看了不满意再议。
- **偏好里的外貌描述被用来绕过规则**（要求画名人、加文字）：40 字上限、拒绝链接，提示词把它放在规则之后并写明不得覆盖；插画器 SKILL.md 重申不画真人肖像。仍是文本约束，不是硬保证。
- **API key 登录或访客运行时没有图像工具**：不单独探测，生成失败即 `status: "failed"`，浮窗保持原样，表单显示失败原因。
- **视觉基线**：Linux 基线只能在 Linux 上生成；Windows 与 Linux 两套都要更新，漏一套会让另一平台的 `pnpm verify` 失败。
- **与 P-C 冲突**：`portrait-type.ts`、`portrait-view.tsx` 两份计划都改；Task 0.0 要求 P-C 先合并。
- **额度**：每次保存表单或重画都花一到两张图；按钮旁写明「会重新生成」，不自动重画。
