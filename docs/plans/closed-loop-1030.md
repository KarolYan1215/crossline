# 执行闭环与实测容量（2026-10-30，本人定）

背景：通宵评测发现「规划强、执行闭环没闭上」——模拟里计划兑现 17–39%，真实账号 16 天完成 0 步、计时 0.6 分钟。这主要是设计问题，不是模拟误差：容量按自报 72 小时排，系统只认本人主动提交的信号（计时、确认），任务要本人点最后一步才交上去，每块确认一次是对注意力的一次出价。被动实测（「电脑前的一天」、按类别的屏幕活动、Codex/Claude Code 用时）已经在账本里，却被明确标为「不用于排程」。

竞品对照：Sunsama 用本人设的每日工作量上限，计时只作「计划 vs 实际」展示（[help](https://help.sunsama.com/docs/usage-guides/daily-planning)）；Reclaim 统计专注时长但没有资料显示它反馈到容量（[review](https://pipeline.zoominfo.com/sales/reclaim-ai-features)）。参考类预测：用过去同类的实际结果代替直觉估计，知道偏差并不能消除偏差（[Planning fallacy](https://www.Wikipedia.org/wiki/Planning_fallacy)）。按实测容量排程并用被动信号闭环，是 Crossline 可以做而竞品没做的。

## 1. 实测容量（取代自报）

- **实测的工作分钟**，按天：以下几类信号在时间上取并集（同一分钟只算一次）：
  1. 计时会话与块确认（完成 / 部分）——本人主动给的，可信度最高；
  2. 屏幕活动中工作类别的时段（本机设备上传，按类别、无标题）；
  3. Codex / Claude Code 使用时段（已开启的使用记录）；
  4. 授权文件夹里任务所属项目的文件新增或改动（作为证据和时刻标记，计入其前后最近的工作时段，不单独凭空加分钟）。
- **容量** = 近 28 天、同类日（工作日 / 周末分开）实测工作分钟的中位数 × 1.25；每天至少 60 分钟。
- **缺失不是 0**：一整天没有任何信号（电脑没开、没计时、没确认）记为缺失，不进中位数。
- **冷启动**：已连电脑的账号，从第一天起用屏幕活动的工作类别分钟作实测（「电脑前的一天」已有 10 天数据）；完全没有信号的账号按自报打 5 折，直到有 5 个有信号的同类日。
- 自报不再参与计算，只在页面上并列显示：「所述 72 h/周 · 实测近 28 天 19 h/周 · 按实测排」。
- 用到它的地方：每天排程的上限、每周承诺的超载判断（需求 > 实测周容量 15% 即触发）、完成预测与风险（因此风险在截止前就会出现）。

## 2. 被动推断块是否做了

- 一块时段里，工作类别分钟（含 Codex 用时）占块长 ≥60%，且类别与任务主线相符或为通用工作类，记为「做了（推断）」，计入实测；<20% 记为「可能没做」；之间记「部分（推断）」。
- 白天不再逐块询问（`block_confirm` 只保留给明天或更早到期、且推断为「可能没做」的块，并在推送上直接给 ✓做了 / ✗没做 两个按钮，不用打开 app）。
- 收工页预填所有推断结果，一键「都对」，或逐块改。推断的块在页面上标「推断」。

## 3. 任务自动收口

- 本人的步骤全部做完、只剩助手步骤或等待步骤时，按「点完成即验收」自动交上去，发一条消息，24 小时内可撤销；需要评分的仍在之后问结果。
- 一键「按预估完成」：计时或推断工作分钟不到预估 70% 的块记「部分」，步骤不勾掉、剩下的继续排。

## 4. 截止：第一遍就排对

- 排程与预测改用实测容量后，有截止的工作按实测排不下时，在截止前至少 2 天提示（加时段 / 降标准 / 推截止——仅自定截止可推），不再等过期。
- 已开始、截止已过：
  - **外部截止**（课程、他人或平台给的日期）：不由系统决定，问本人确认硬约束——还能补交吗、实际最后期限是哪天；给了日期就按它排，不能补交则归档（可恢复）。
  - **自定截止**：自动顺延到实测容量下的保守完成日 + 2 天，通知一次；最多两次，第三次问本人。

## 5. 准备与小修

- 带材料合同的任务，助手在第一块开始前 24 小时内准备材料（与助手准备步骤的 48 小时窗口同一套触发）。
- 收工页标题「今天开始过的块」改为「今天排过的块」。
- 「来不及」推送的选项加「推迟截止」（仅自定截止）与「去本周承诺」。
- 风险卡被别的回答顺带解决时，提示改为「情况已变化，这条不用处理了」。
- 周日打开本周承诺时默认看下一周；本周只剩当天时不再拿当天容量去比整周需求。
- 教程按熟悉度调整已在 10-30 上线（`familiarity.ts`），本方案不再改。

## 6. 验证

- 单元测试：实测分钟并集与缺失、容量中位数、冷启动、推断阈值、自动收口、逾期两类、预测提前预警。
- 用 30 天模拟（`scripts/month-sim.ts`）重跑三种策略：目标是计划兑现率 ≥70%、每周承诺在超载周触发、截止前预警先于过期。
