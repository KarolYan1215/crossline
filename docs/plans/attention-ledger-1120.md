# 注意力账：整个系统逐项「有 vs 没有」（2026-11-20，多轮确认中）

本人 2026-11-20 定的总原则：

> 整个系统的核心目的是最高效地利用人类有限的注意力，所有设计都围着这个来。每一个设计都要对比「有这个 vs 没有这个」，人是否能获得注意力盈余。越能省下注意力的机制越重要。

本文盘点系统里每一处花本人注意力的地方，以及每一处替本人省注意力的地方，逐项给出「有 vs 没有」的对比和提议。入账这一块（邮件、去重、步骤粒度、访谈近期任务）的细节在 `near-term-and-mail-bar-1120.md`，这里只引用。

盘点依据：2026-11-20 读代码，结合 `docs/walkthrough-ledger.md`（W-n 指其中的条目）。

## 一、怎么算注意力

### 1. 单位

各类动作花的注意力不一样，按代价从高到低排：

| 级别 | 动作 | 为什么贵 |
|---|---|---|
| 打断 | 推送、桌面通知、弹出 | 本人正在做的事被切断。被打断后平均要 20 多分钟才回到原任务（Mark et al., CHI 2008）；切换后上一件事的残留会拖累下一件（Leroy 2009） |
| 打字回答 | 要写一句话的提问 | 要回忆、组织语言 |
| 决定 | 在几个选项里选 | 要权衡，要承担后果 |
| 一键 | 确认、知道了 | 便宜，但累积起来不便宜；每张卡都要先读懂 |
| 读 | 一行提醒、一个数字 | 最便宜，但同一件事在几处说，每处都要读 |

把通知集中成一天几次推送，比随到随推更好：注意力更集中，压力更低（Fitz et al., Computers in Human Behavior 2019）。

### 2. 账怎么记

对每个机制问三句：

1. **没有它，本人要做什么？** 这是它省下的。
2. **有它，本人要做什么？** 读、点、答、被打断，这是它花的。
3. **系统已有的信息够不够让它自己决定？** 够的话，问本人就是纯成本。

### 3. 目标（提议，待本人定）

- 打断：每天 ≤ 3 次，只为「现在不处理就来不及」的事。
- 决定：每天 ≤ 5 个，集中在一个地方，一次做完。
- 打字回答：每周 ≤ 3 个。
- 系统替本人做的事：不打扰，留一个可撤销的记录，在一处能查。

系统已经测着「决定用时」「计划变动」（`packages/core/src/plan-churn.ts`，设置页的效果卡），但没人看。改成每周对照上面的目标。

## 二、最省注意力的机制（保留并加强）

按省下的注意力从多到少排。这些是系统存在的理由，改动时优先保护。

| 机制 | 没有它，本人要做的 | 现状 | 提议 |
|---|---|---|---|
| 看板本身（一个账本，跨主线） | 反复陈述同类事项，在几个工具间对照 | 已有 | 保留。账本简报（入账设计 3.1）让每个模型都看到它 |
| 自动排程，写进日历 | 每天决定什么时候做什么，手抄进日历 | 已有，修过多次（W-48、W-293 等） | 保留。日历成为本人主要看的界面（见 P1） |
| 语音输入、录音整理 | 打字、记笔记 | 语音没测试，没走查 | 保留。语音也能用来回答提问 |
| 输入框（小帮手）一句话入账 | 填表 | 可靠，约 60 秒 | 保留 |
| 默认生效，24 小时可撤销 | 逐条批准 | 已有 | **推广成通用模式**：能用推荐答案的，先做、留撤销，不先问（见 P3、P9） |
| 文件、日历、邮件自动读入日期 | 手动输入日程和截止 | 已有，重复问题见入账设计 | 保留，加去重 |
| 教程和材料提前备好 | 自己查资料 | 已有，只在请求时显示 | 保留 |
| 过期时间自动后移、回来后自动整理 | 每天清理 | 已有 | 保留 |
| 计时自动停、只剩助手步骤时自动关任务 | 停计时、关任务 | 已有 | 保留，扩展到块确认（见 P2） |

## 三、逐项「有 vs 没有」与提议

编号 P1–P14。每项写现状、有它 vs 没有它、提议。待本人逐项定。

### P1 每个工作块开始前 15 分钟的提醒（`block_start`）

- **现状：** 每个工作块都推，算作紧急，不计每日上限；推迟后最多再推两次。每天 3–8 次。是全系统最大的打断来源。
- **有它：** 本人不用记几点开始。代价是每天 3–8 次打断，每次都可能切断正在做的事。
- **没有它：** 工作块已写进本人的日历（`auto-publish`），日历 App 自己会提醒。本人看日历就知道下一块。
- **提议：** 日历已同步的块不再推，交给日历 App 的提醒。只推两种：当天第一块，以及排程在本人最后一次看过之后变了的块。都计入每日上限。

### P2 块确认的循环（`block_confirm`、收工页、`missed_block`、早报、回归页）

- **现状：** 「这一块做了没有」这一件事，在五处问：块结束时的提醒、晚上的收工页、第二天的 `missed_block`、早报里的两行、离开 48 小时后的回归页。
- **有它：** 系统知道实际进度，估时和排程更准。
- **没有它：** 系统已经能推断：计时记录、提交的进度、`inferBlockOutcome`、只剩助手步骤时自动关任务；没做的块本来就会自动后移。
- **提议：** 默认由系统推断，不问。只在两种情况下问一次：推断不出来，且这个任务三天内截止。问的地方只有一处（今日页的一行），收工页保留为本人想用时可以用的页面，不再推送。`missed_block` 不再出卡，直接后移，在早报里说一行。

### P3 系统 48 小时后会自己按推荐答的提问（`risk_digest`、`milestone_risk_review`、`missed_block`）

- **现状：** 先问本人，48 小时没答就按推荐答（`answer-all.ts:59`、`rituals.ts:192`）。
- **有它：** 本人有机会在系统动手前否决。
- **没有它：** 系统直接按推荐做，本人在记录里看到，可以撤销。
- **提议：** 直接做，不先问。做完在早报（或每周一次）里说一行，可撤销。理由：既然 48 小时后照样会做，先问只是把注意力花在一个本人多半会点「同意」的地方。例外：外部截止的里程碑过期，仍然问（2026-11-05 本人定的）。

### P4 没有东西要决定的提问（`background_paused`、`calendar_sync_failed`、`interview_open`、表单进度）

- **现状：** 算作提问，计入角标。`background_paused` 还是「现在」级，会紧急推送，而卡片上写着「不需要操作」。
- **有它：** 本人知道后台停了。
- **没有它：** 本人什么也不用做，状态照样会恢复。
- **提议：** 改成页面顶部的一条状态，不计角标，不推送。只有需要本人动手的（比如重新登录日历）才是提问。

### P5 后台的各种通知（`sayToPerson`，约 25 种）

- **现状：** 自动化结果、自动批准、自动后移、合并、记账周报、邮件安全提醒、回复草稿等。推送时不检查每日上限和免打扰时段（`notify.ts:237–271`）。大多数只能点「知道了」，说的是已经做完的事。铃铛每条弹出 8 秒，留红点。
- **有它：** 本人知道系统做了什么。
- **没有它：** 系统照样做；本人在想知道时去查。
- **提议：** 只有要本人动手的才推送，且计入上限、遵守免打扰。其余全部进一处「系统做了什么」的记录，早报里汇成一行（「昨晚系统做了 6 件事，可撤销」）。铃铛不弹出。邮件安全提醒（账号被登录等）例外，照推。

### P6 精力询问（`energy_check`）和摄像头

- **现状：** 模型不确定、且上次报告超过 3 小时就问，不限次数，不计上限；今日页还有一个低精力时的自评。摄像头在每一页挂载。
- **有它：** 排程能把难的事放进精力好的时段。
- **没有它：** 系统用画像里本人说的时段，加上计时和完成记录推断（W-291 已经改成以本人所说为准）。
- **提议：** 询问每天至多一次，计入上限；画像和记录够用时不问。摄像头：没有证据显示它改变过排程（盘点里两次提到都只是「符合 10-14 的决定」）。是否保留由本人定（这是 2026-10-14 的明确决定，不能当作重构顺手删）。

### P7 机会（`opportunity_offer` 及后续）

- **现状：** 一个机会最多有 5 个接触点：约 8 个选项的提议卡和资格问题、预览、准备好可以申请、表单进度、结果。另外早报、截止当天的推送、周复盘、机会页都会提。W-14 一次跑了 27.7 万 token，留下 13 条要决定的建议。
- **有它：** 本人不会错过和主线有关的机会。
- **没有它：** 本人自己看到的机会，用输入框一句话加进来。
- **提议：** 套用入账设计的注意力门：只有直接服务某个里程碑的机会才出现，出现在周复盘一处，一次决定「做 / 不做」。做的话，后续由系统准备，只在要本人提交时问一次。早报、推送、机会页不再重复提。

### P8 要打字回答的提问（`step_question`、`prep_question`、`capture_blocked`、`agent_blocked`）

- **现状：** 批准 19 个里程碑后出了约 60 个步骤问题；每个要写一句话。
- **有它：** 计划基于事实，不是猜的。
- **没有它：** 模型先按最合理的假设做，把假设写在任务上，本人看到不对时改。
- **提议：** 默认假设并写明（W-51 已经部分这样做）。只有满足两条才问：缺这个事实会让任务做错，而且本人之外没有任何来源能给。每个任务至多一个问题；能给选项的给选项，不让本人打字。步骤粒度收到交付物后（入账设计 3.3），问题本身也会少很多。

### P9 日历和数据的整理类提问（`event_merge`、`calendar_line_unclear`、`source_project`、`travel_minutes`、`event_propose`、`ledger_duplicate`）

- **现状：** 每种都有推荐答案，很多已经按推荐先做了（路程已假设 30 分钟），但仍出一张卡。
- **有它：** 本人能纠正系统的猜测。
- **没有它：** 系统按推荐做，错了本人在用到时会发现并改。
- **提议：** 全部按推荐先做，进「系统做了什么」的记录，可撤销，不出卡。合并和归属由模型带账本简报判断（入账设计 3.4）。

### P10 同一件事在几处说

盘点找到 10 组重复。代表性的几组：

| 同一件事 | 出现的地方 |
|---|---|
| 「到了吗」 | 等待到期的提问、邮件到达的提醒、早报、紧急推送 |
| 截止的压力 | `latest_start`、里程碑风险、截止推送、今日的「排不下」、开始提醒里的「可能来不及」、计划页「未排进」 |
| 里程碑草稿 | 今日提醒、今日空状态、待确认的链接、角标、早报 |
| 待验收 | `evidence_manual` 提问和待确认页的「待验收」 |
| 机会 | 提议卡、早报、推送、周复盘、机会页 |

- **提议：** 一件事只有一个家。
  - 需要决定的事：家在待确认（今日页显示前几条）。角标只数这一类。
  - 需要知道的事：家在早报（推送）或今日页的一行，二选一，不两处都说。
  - 系统做了的事：家在「系统做了什么」的记录。
  - 详情：家在各自的页面，只在本人点进去时出现。
- 每加一个界面元素，先说清它的家在哪、和哪一处重复。

### P11 访谈

- **现状：** 6–7 个阶段，轮数不限，每轮至多 5 个问题加 3 张观察卡要评，画像要逐项确认。设置向导写「约 30 分钟」。是全系统最大的一次性开销。
- **有它：** 画像（精力时段、动机、价值、职业方向）、每条主线的项目和截止、固定日程。
- **没有它：** 系统不知道本人的主线和截止，排不出东西。
- **对比：** 访谈里真正让今日页能工作的，是主线、项目、截止、近期任务、固定日程（开始标准）。动机、价值、职业推导、观察卡，是长期价值，但不影响第一周。
- **提议：** 访谈分两段。第一段只收开始标准（目标 10–15 分钟），问完立刻进今日页，本人马上看到第一周的排程。画像和职业推导改成之后零散地补：每次一两个问题，挂在本人本来就会看的地方，或者本人想聊时再聊。观察卡默认不要求评分。

## 四、还能省注意力的地方（盘点之外的提议）

1. **让日历成为主界面。** 排程已经写进本人的日历。本人一天里主要看日历，Crossline 只用来做决定和看为什么。这样 P1 的提醒、今日页的时间线，都可以让位给日历 App。
2. **一天两个固定的接触点。** 早上一次（早报：今天的事、要决定的事、系统昨晚做了什么），晚上一次可选（收工）。其余时间只有「现在不处理就来不及」才打断。依据见一.1（集中推送）。
3. **决定集中做。** 待确认页一次做完，每张卡都有推荐答案，「全部按推荐」要列出它覆盖了哪几条（W-176 未修）。
4. **从撤销里学。** 本人撤销了某一类系统动作，就记进账本简报的「偏好」段，下次模型看得到，同类不再做或改成问。这比写规则更省：本人只是撤销，不用解释。
5. **从产出判断完成。** 本人把作业放进输出文件夹或交付目录时，系统读到就当作完成，不再问「做完了吗」。
6. **语音回答提问。** 打字回答（P8）改成可以说一句话。
7. **今日页少放数字。** 同屏多个计数，读的人要对照哪个是哪个（W-103、W-173、W-276、W-290、W-294）。只保留要本人做决定的那一个数。
8. **每周量一次注意力。** 把一.3 的目标做成效果卡的一行：本周打断几次、决定几个、打字回答几个，和上周比。改动是否省了注意力，以这一行为准。

## 五、批判性分析

1. **先做后告诉，错误会更晚被发现。** P3、P9 让系统先做。错了的话，本人可能到用到时才发现，比被问时纠正的代价大。对策：撤销记录集中在一处、24 小时内可撤销；每类动作的撤销率进每周的注意力行，撤销率高的类别退回到先问。
2. **少打断可能错过真正要紧的事。** P1 依赖日历 App 的提醒；本人如果关了日历提醒，就什么都收不到。对策：设置向导检查日历是否同步；当天第一块照推。
3. **访谈分两段，画像会变浅。** 职业推导和动机放到之后，可能永远不补。对策：补的问题挂在本人本来会看的地方，并且有明确的完成度；若一个月后仍很少，回头评估画像到底被用到多少。
4. **删功能有沉没成本的阻力。** 飞轮、关系、回归页都花过很多工夫。判断标准只看「有 vs 没有」，不看花了多少。
5. **「一个家」的规则会被新功能慢慢破坏。** 对策：写进 `CLAUDE.md` 的通用规则，每加一个提醒、提问、推送，说清它的家和它省下的注意力。
6. **摄像头和精力是本人明确决定过的。** 本文只列证据，不替本人改。

## 六、多轮确认

### 第 1 轮（2026-11-20 本人已答）

- A1 开始提醒（P1）：**交给日历 App。** 已同步的块不推，只推当天第一块和改过的块，计入上限。
- A2 块确认（P2）：**默认推断，少数才问。** 推断不出且三天内截止才在今日页问一次；收工页保留不推；没做的直接后移。
- A3 先问后做 vs 先做后告诉（P3、P9）：**确认可撤销后直接做，做完在小帮手和通知里汇报，附一键撤销。** 即：先确认这个动作真能撤销（不能撤销的仍然先问），再做；做完后在小帮手对话里说一句，并发一条通知，两处都带「撤销」按钮。
- A4 后台通知（P5）：**只推要动手的。** 其余汇成早报一行，铃铛不弹出，账号安全提醒照推。

### 第 2 轮（2026-11-20 本人已答）

- A3 补充，「通知」指什么：**铃铛列表，加汇总推送。** 自动做完的事进铃铛列表（带撤销）和小帮手对话；推送不逐条发，汇总成一条（「系统做了 N 件」），点开逐条撤销。铃铛不弹出。
- 访谈（P11）：**保持现状。** 不分两段，画像深度优先。近期任务照入账设计加进开始标准。
- 精力（P6）：**询问每天至多一次，摄像头保留。**
- 精简（P12）：
  - **每周承诺（保 / 推 / 砍）：去掉逐行决定。** 系统按排程直接定，超载时只问一次「砍哪件」。
  - **回归页：精简，不删除**（本人中途更正）。
  - 飞轮图、主线间关系：本人没选，保留。

### 第 3 轮（2026-11-20 本人已答）

本人对总原则的修正：

> 总体设计而言，不需要让用户完全不操作或极少操作。注意力不是要全部省掉，而是要放在值得的、关键的地方。

因此一.3 的数字目标只作参考，判断标准改为：每一次要本人花注意力的地方，是不是关键的地方（影响里程碑、会产生后果、只有本人能定）。

- 回归页：**只列要紧的**，即不处理会影响里程碑或产生后果的。本人一上线就自动整理：过期的更新，需要重排的重排。
- 完成与验收：**一键完成，系统验收。**
  - 本人可以给某个项目指定结果文件夹；系统也从已授权的文件夹里读新增文件，作为交付物。
  - 没有电子版的交付物另做处理。
  - 去掉重复的「算数」卡。
- 机会（P7）：
  - **类型拓展**：不只比赛、招聘、讲座，加上新动态、文献等，结合本人当前在关注的内容。
  - **接触点里只和「找机会」有关的部分整合到一处。**
  - 早报、周复盘、机会页保持现状，**不再推送**。
- 打字提问（P8）：**先判断假设会不会做错或白做。**
  - 尽可能给选项。
  - 每个任务不限数量。
  - 先保关键任务的质量，再考虑注意力。
  - 本人要求详细设计怎么做（见第七节，待写）。

### 第 4 轮（2026-11-20 本人已答）

- 一件事一个家（P10）：**定，按类分家**，并写进 `CLAUDE.md` 作为通用规则。
  - 要决定的事：家在待确认。今日页显示前几条，角标只数这一类。
  - 要知道的事：家在早报或今日页的一行，二选一。
  - 系统做了的事：家在铃铛列表。
  - 详情：家在各自的页面。
- 推迟问原因、关计时问「这步完成了吗」：**可选，不拦。**
  - 推迟直接生效，原因是可选的一键标签（没时间 / 等别人 / 不想做）。
  - 关计时带「完成 / 还没」两个按钮，不点就按推断。
- 自动化建议卡、邮件回复草稿：**都过注意力门。**
  - 只为和里程碑相关、且重复出现的事建议自动化。
  - 回复草稿只给要本人回、且服务主线的邮件，不再二次提醒。
- 画像页、记账页：**都留，只修显示。** 记账页在数据不够时不显示储蓄率和月底预测。

### 第 5 轮（2026-11-20 本人已答）

- 日历作主界面：**两边并存。** 今日页时间线照旧，日历是副本。
- 从撤销里学：**记进偏好，模型看得到。**
  - 每次撤销记一条「这类不要」，进账本简报的偏好段。
  - 某类撤销多了，就退回先问。
  - 原因可选一键，不强制。
- 语音回答：**要，每个输入框都可以说。** 走现有听写。
- 「值得花注意力的关键处」，四条全选，写进账本简报给所有模型：
  1. 影响里程碑；
  2. 会产生外部后果（截止、对外承诺、钱、账号安全）；
  3. 只有本人能定；
  4. 不可撤销。

### 第 6 轮（2026-11-20 本人已答，第七节已按此改）

- 问题什么时候送到本人面前：**周复盘集中处理，开始前一两天提醒。**
- 没答之前，依赖它的步骤：**按代价分。** 会让交付物变差或有对外后果的就等；只是可能白做一点时间的，先按假设做。
- 结果文件夹里出现像交付物的新文件：**检查结果，确定是就直接完成**，可撤销。
- 动态和文献的数量：**不设上限，只靠注意力门。**

## 七、三块详细设计（第 3 轮之后，待确认）

### 7.1 什么时候问本人：先算「错了的代价」

**现状（读代码，2026-11-20）：**

- 步骤规划 Skill 一次至多写 5 个问题，格式是 `{id, text, why, options}`（`packages/core/src/steps.ts:143`）。
  - 第一个选项同时充当推荐和假设。
  - 没有「错了的代价」这个字段。
  - 排序只看「答案会改变计划多少」（Skill `SKILL.md:54`）。
- 谁会被问由代码定：
  - 只有按规则算重要的任务，即作业配对或里程碑权重 ≥ 60（`step-planner.ts:246-259`）；
  - 每个任务至多 2 个问题（`PERSON_QUESTIONS_PER_TASK`，`step-planner.ts:446`）；
  - 模型自己判断的重要性被忽略（`:403-409`）；
  - 模型看不到权重，也不知道它的问题会不会送到本人面前。
- 其余问题按第一个选项假设，记成「假设：…」，任务对话框里可以改（`step-planner.ts:457-472`）。
- 另外三类提问：
  - `prep_question`：只能打字，每张卡 2 句；
  - `capture_blocked`：只能打字；
  - `agent_blocked`：已有选项。

**设计：**

1. **每个问题都带上「假设错了会怎样」，由模型判断，代码只核对格式。**

   ```
   {
     id, text, why,
     options: [...],              // 2–6 个具体答案，最可能的在前
     assume: <options 之一>,       // 不问时按它做
     neededBy: <stepId>,          // 哪一步开始前必须知道
     ifWrong: {
       waste: <分钟>,             // 按假设做了、后来要返工的时间
       harm: none | quality | deadline | external,  // 交付物变差 / 赶不上截止 / 对外后果
       fixable: before_step | after_submit | never   // 什么时候还来得及改
     },
     ask: true | false
   }
   ```

2. **问不问由模型按「关键处」四条定，写在 Skill 里，不写在代码里。** 判断原则：
   - 假设错了会白做较多时间，或交付物变差、误截止、对外出错，就问；
   - 只有本人知道的事实（偏好、方法、别人的要求），而且材料里查不到，就问；
   - 否则按假设做，把假设写在任务上。
   - 不设每个任务的数量上限。
3. **模型看得到它需要的：**
   - 账本简报（主线、里程碑、权重、截止）；
   - 「关键处」四条；
   - 本人过去对同类问题的回答，以及改过的假设（从撤销里学）。
4. **问的时机：周复盘集中处理，开始前一两天提醒（第 6 轮本人定）。**
   - 一周里产生的问题都进周复盘的一栏，本人一次答完。批准里程碑时不再一次全部倒出来（W-54 的「约 60 个」就是这样来的）。
   - 问题挂在 `neededBy` 那一步上。到那一步开始前一两天还没答，就在今日页提醒一次，答案仍然可以在周复盘那一栏给。
   - `fixable: never` 且 `harm ≠ none`，而且等不到下次周复盘的，直接进待确认。
5. **没答之前怎么办：**
   - 不依赖这个答案的步骤照常做；
   - 依赖它的步骤：`harm` 为 `quality` 或 `external` 时，等答案；只是 `waste` 时，按假设先做。
   - 到 `neededBy` 还没答，就按 `assume` 做，并在铃铛里说一声（可撤销）。
6. **形式：**
   - 先给选项，推荐的那个标出来；
   - 最后一个选项是「其他」，可以打字或说一句（第 5 轮：每个输入框都可说）；
   - 同一项目的几个问题合成一张卡，保留「都按建议」。
7. **另外三类：**
   - `prep_question`、`capture_blocked` 也改成模型先给 2–4 个候选答案，加「其他」，不再只能打字。
   - `agent_blocked` 已有选项，不动。
8. **代码只核对：**
   - `assume` 在 `options` 里；
   - `neededBy` 指向存在的步骤；
   - `ask: true` 时 `ifWrong` 不能全是 none。
   - 不合格的退回模型重做，不由代码改写。
9. **删掉：** `PERSON_QUESTIONS_PER_TASK`、`IMPORTANT_WEIGHT` 这条重要性规则、「重规划时新问题一律假设」。最后这条改成：同一个问题不再问第二次，新出现的关键问题照样问。
10. **评测：** 用真实的「假设错了白做」样例做回放夹具，例如 W-286 让本人上传凭据、W-51 重复问。

**批判：**

- 模型自报的 `waste` 和 `harm` 会偏乐观（外部依据 Xiong et al.）。
- 对策：
  - 评测集按真实返工记录校准；
  - 本人改过的假设计入偏好，同类以后倾向于问；
  - 本人每周能看到「按假设做了哪些」，在铃铛列表里。

### 7.2 结果文件夹与系统验收

**现状：**

- 按「完成」就立刻 `evidence.accepted`：不验收，不要求证据（2026-10-15 的决定，`crossline.ts:1881-1924`）。
- 待验收、「算数」卡、里程碑门（`crossline-milestone-gate`）只剩在旧路径上。
- 授权文件夹每次轮询都读新增文件（`source-folders.ts`），但：
  - 文件夹只有「属于哪几条主线」，没有「属于哪个项目」，也没有「结果放这里」；
  - 新文件不会被当作交付物。

**设计：**

1. **一键完成照旧，立即生效。** 验收不再是本人的一步，而是系统事后做的检查。
2. **结果文件夹：**
   - 每个项目可以指定一个结果文件夹，在项目卡上一行，可以从已授权的文件夹里选，或者选一个新的；
   - 没指定的，系统从授权文件夹的新增文件里，由模型判断属于哪个任务。依据是文件名、内容开头、修改时间与块的时间，再加账本简报。
3. **验收由模型做，读交付物本身：**
   - 输入：任务的完成标准、里程碑标准、交付物文本（PDF / 文档提取）、账本简报；
   - 输出：`pass | gap | cannot_read`，附引语。
   - `pass`：只记录，不打扰。
   - `gap`：只有当这个任务影响里程碑，或会有外部后果（关键处四条）时，才在待确认问一次，并给选项：「已经交了，结束」「我补一下」「这条标准不适用」。其余只记录。
   - `cannot_read`：只记录。
4. **新文件可以直接完成任务（第 6 轮本人定）：** 模型检查新文件。确定它就是某个任务的交付物，而且符合完成标准时，直接把任务记为完成。按第 1 轮 A3 的方式，在小帮手和铃铛里说一句「看到 X，已把 Y 记为完成」，附一键撤销。不确定的只当作证据附上，不完成。
5. **没有电子版的交付物**（纸质作业、线下考试、面试、口头汇报）：
   - 完成标准由模型在步骤规划时标出 `offline: true`；
   - 完成时一键，可选拍照上传；
   - 系统不做内容验收，改为等外部结果：成绩邮件、Canvas / Gradescope 通知、对方回信。这些经由入账判断（入账设计 3.2）以 `update` 落到这个任务上，作为后验证据。
6. **删掉：** `evidence_manual`「算数」卡；待验收只保留 `gap` 且属于关键处的那几条。
7. **边界：**
   - 只读本人授权的文件夹；
   - 敏感文件和凭据照旧永不读入；
   - 不向外发送任何内容。

### 7.3 机会与动态

**现状：**

- 机会类型 11 种（`opportunity-tags.ts:15`），文献只在尽调话题里有。
- 候选来源：每条主线由模型生成的关注点（招聘看板、截止列表、devpost、活动站），每周的侦察，尽调，以及邮件分拣。
- 本人收藏的话题、小红书收藏已有读取器，但机会和尽调都没用（0 处引用）。
- 找机会相关的接触点：
  - `opportunity_need` 卡（建议新关注点）；
  - `opportunity_offer` 卡（约 8 个选项）；
  - 早报「新机会」；
  - 截止当天的推送；
  - 周复盘「本周机会」「视野外」。
- 准备和申请相关的接触点（预览、可申请、表单进度、结果）属于执行，不属于找。

**设计：**

1. **类型拓展为三类，看待方式不同：**

   | 类 | 例子 | 本人要做的 |
   |---|---|---|
   | 机会 | 比赛、招聘、奖学金、会议投稿、讲座、项目 | 决定做 / 不做 |
   | 动态 | 本领域的新进展、实验室或公司公告、政策变化、工具或数据集发布 | 读，或不读 |
   | 文献 | 和当前里程碑、在做的研究直接相关的新论文 | 读，或存起来 |

2. **「本人当前在关注的」由账本简报加以下信号组成，模型统一看：**
   - 近期里程碑和在做的任务；
   - 收藏话题（含小红书收藏，第一次接入）；
   - 本人最近通过输入框或录音说起的东西；
   - 邮件里订阅的通讯，经入账判断为 `note` 且 `serves` 不为 none 的；
   - 「少来这类」的偏好。
3. **来源：**
   - 已有的关注点和网页搜索；
   - 文献加公开的只读接口（arXiv、Semantic Scholar），只查不写。
   - 动态和文献不新建账号、不登录。
4. **注意力门：**
   - 机会：同入账判断的 `serves`，只留服务某个里程碑或主线目标的。
   - 动态和文献：再加一条「和本人当前在做的事直接相关」。不设数量上限，只靠注意力门（第 6 轮本人定）。
5. **接触点整合（只整合「找」）：**
   - 建议新关注点（`opportunity_need`）不再出卡：系统直接建，进铃铛可撤销（第 1 轮 A3）。
   - 机会、动态、文献合并到周复盘的一栏「机会与动态」。
     - 每条一行：为什么和本人有关、截止、链接。
     - 机会给「做 / 不做 / 少来这类」，动态和文献给「有用 / 少来这类」。
   - 早报的「新机会」改为「新机会与动态 N 条」，链接到这一栏。
   - 不再推送，包括截止当天的推送；已选「做」的机会，截止由它的任务自己的排程和提醒负责。
   - 执行相关的接触点（预览、可申请、表单、结果）不动，它们是本人选「做」之后的任务。
6. **反馈：**
   - 「少来这类」「有用」记进偏好，模型看得到；
   - 某类一个月没人点「有用」，自动降频。

**批判：**

- 动态和文献容易变成新的信息流，和「只给关键处」相反。
- 对策：
  - 不设上限（本人定），所以门要严；
  - 只给和当前里程碑直接相关的；
  - 一个月的「有用」率进每周的注意力行，低了就收紧。

## 八、实现前的竞品与资源调研（2026-11-20）

每一批开工前查过的做法，以及它对本设计的影响。

| 批 | 别人怎么做 | 对本设计的影响 |
|---|---|---|
| 1 通知 | Reclaim 的块提醒用 Google 日历自己的提醒，并提醒用户别两处都开，以免重复；Motion 手机端不推任务提醒；Sunsama 只推收工。iOS 只让「Time Sensitive」（一小时内）和 Critical 穿过摘要和专注模式。Fitz et al. 2019：一天集中三次推送，注意力和掌控感更好；每小时一次推送和不集中没有差别 | A1 交给日历 App，与 Reclaim 一致。汇总只放进早报（一天一次），不做每小时汇总 |
| 2 先做后告 | Raskin：「要的是撤销，就别用警告」。Microsoft HAX G9「便于纠正」。Reclaim：手动拖过的会议锁定，不再挪；Motion 被抱怨「手动放好的又被挪走」。撤销的逆操作要在执行时就记下 | 先做的动作在写入时记下逆操作；本人手动改过的不再自动改（已有锁定，沿用）；同类被撤销多次就退回先问 |
| 3 入账去重 | 主流产品都不扫整个收件箱变任务：Motion 靠转发，Akiflow 靠星标，Sunsama 靠拖拽。Copilot「Prioritize my inbox」用本人写的自然语言规则。实体匹配用「从短候选里选一个或都不是」，真实匹配越靠后越不准（Wang et al., COLING 2025） | 候选由代码圈好、最可能的排前面、最多 8 条；入账判断带「为什么」，本人可见；注意力门比任何竞品都严，是我们的差异 |
| 4 提问 | 只在多种合理理解会导致不同做法时才问（Zhang & Choi, NAACL 2025）；现有方法在小细节上问太多、关键处问太少（SAGE-Agent 2025）；Cursor 2.4 起提问不阻塞，代理边等边做 | 7.1 的 `ifWrong` 与「按代价分」一致；同一任务的几个问题合成一个最小问题 |
| 5 交付物 | GitHub 2025 年加了关闭「合并即关 issue」的开关，因为合并不等于完成；Linear 在 PR 被回滚时自动重开 issue | 新文件确认是交付物就直接完成（本人定），另加两条：交付物文件被删或被替换成空文件时自动撤回完成；完成记录写明「由文件 X 判定」 |
| 6 文献动态 | Semantic Scholar 研究推送用正负例；它的 API 许可**不允许商用**，要另申请。arXiv 元数据 CC0，接口每 3 秒一次。Feedly 的「少来这类」不说原因就学不到多少 | 文献先走 arXiv 和网页搜索，不接 Semantic Scholar API（托管 beta 将来收费，许可不清）；「少来这类」带一个可选原因 |

## 九、实现记录

- **第 4 批（提问与粒度，2026-11-21）：**
  - 7.1 的字段、代码核对、退回重做、不设上限、按 `ask` 分流都已实现；周复盘「本周要回答的问题」一栏，用到前两天进待确认，到当天未答按假设做并在铃铛说一声。
  - 本人步骤按交付物粒度；所有开着的任务各重排一次；重排时锁定的时间块和已报进度跟到新步骤上。
  - 每个输入框可说：补上了提问卡的单行输入、主线关注、洞察纠正、个人设计、给 Crossline 的话。账号、网址、密钥类输入不加。
  - **没做：** 依赖未答问题（harm 为 quality/external）的步骤等答案再排；`prep_question`、`capture_blocked` 先给候选答案。记在 `docs/claude/architecture.md`。
- **第 5 批（结果文件夹与验收，2026-11-21）：**
  - 授权文件夹里授权之后出现或改过的文件，由模型对照未完成和两周内完成的任务判定：交付物 / 证据 / 无关，达标 / 有缺口 / 读不出；引文必须逐字出自文件，代码核对后才记。
  - 交付物且达标 → 任务直接记为完成，当天对话里说一次，带撤销；撤销记进偏好。没有里程碑、停在待验收的任务由系统直接验收，同样可撤销；旧的「算数，验收」卡去掉。
  - 已完成任务的交付物有缺口，只在关键处（关联里程碑，或缺口有外部后果）问一次：已经交了 / 我补一下 / 这条标准不适用。
  - 文件夹卡片上可设「成果文件夹」归某个项目，新文件只对照该项目的任务。步骤规划给每个任务标 `offline`（没有电子交付物），这类任务不在文件夹里找。
  - 按第八节调研补的一条：两周内交付文件被删除或清空，自动撤回完成并说一次；文件夹内移动、改出有内容的新版、本人排除的不撤回。
  - **没做：** 线下任务的可选拍照留证。
- **第 6 批（机会与动态，2026-11-21）：** 记录在 `docs/opportunity-agent.md` §19。
  - **三类：** 机会 / 动态 / 文献。动态和文献要落在里程碑上才给。
  - **来源：** arXiv 公开接口，加收藏话题和近两周说过的话作兴趣信号。
  - **触点：** 派生的监视项直接启用，顶栏撤销菜单里可撤销。机会、动态、文献集中到周复盘「机会与动态」，一周内到期的机会仍上待确认。早报只报条数。
  - **反馈：** 「有用 / 少来这类」，后者可选填原因。一个月没人点「有用」的类自动降频，可撤销。
  - **没做：** 订阅通讯作为信号；「有用」率进每周注意力行。
- **走查（2026-11-21）：** 在临时实例上从本人视角走了周复盘「机会与动态」、待确认、撤销菜单和授权文件夹的「成果文件夹」。
  - **分流对：** 远期机会、动态、文献进周复盘；4 天内截止的仍在待确认。
  - **撤销对：** 自动启用的监视项可撤销，撤销后监视项退休。
  - **成果文件夹：** 选择能保存。
  - **修了三处：** 动态和文献卡的文案；「本周机会」统计不再算动态和文献；周复盘卡去掉「明天再问」。见 `docs/opportunity-agent.md` §19。
