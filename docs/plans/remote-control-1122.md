# 手机遥控这台电脑（2026-11-22 设计，本人已确认；R1–R3 已实现）

本人要的是：电脑开着时，在手机上调用这台电脑的 shell 和其他本机功能（能执行命令的助手 `crossline-agent`、授权文件夹、录音转写、报名表单）；电脑离线时，手机照常用托管站（app.crossline.lol）。

远程执行命令是一条新的对外路径，碰 `CLAUDE.md` 的安全边界，所以第 7 节逐条写授权、撤销、审计和越界拒绝。本人 2026-11-22 按第 10 节的推荐确认，R1–R3 随后一起实现；第 11 节记实现与设计不同的地方和代码位置。

## 0. 结论先说

- **连接：不用 Tailscale，走已有的算力节点连接。** 电脑主动连 `wss://app.crossline.lol/node`（docs/compute-node.md），手机只开托管站。电脑不开入站端口，手机不装别的东西，蜂窝网络也能用。
- **账本：托管站是唯一主账本。** 电脑仍是设备模式（docs/device-mode.md）加算力节点。远程会话的记录写进托管账本；电脑另记一份本机审计日志，服务器改不了。本地版（14892，独立账本）不参与。
- **新东西只有两样。** 一是「电脑会话」：手机上开一条在电脑上跑的助手线程，可以连续对话，也可以直接打命令。二是「手机签名」：手机浏览器里生成一把密钥，在电脑屏幕上确认配对；电脑只执行带有效手机签名的远程指令。这样服务器即使被攻破，也不能借这条路在电脑上执行命令。
- **默认全关。** 电脑上的「允许从手机遥控」开关只在电脑本机设置，服务器改不了。
- **电脑离线：** 托管站照常工作，电脑会话不可开。不排队执行：电脑上线时推送「电脑已上线」，由本人再点一次开始。

## 1. 借鉴的 remote 模式

| | Claude Code Remote Control | Codex「随处使用」（2026-05，预览） | 本设计 |
| --- | --- | --- | --- |
| 谁连谁 | 本地会话只发出站 HTTPS，向 Anthropic API 注册并等待任务，不开入站端口 | 经 OpenAI 的中继层，机器不直接暴露在公网 | 电脑连托管站的 `/node`（已有），托管站做中继 |

参考：[Claude Code Remote Control 文档](https://code.claude.com/docs/en/remote-control)、[OpenAI：Work with Codex from anywhere](https://openai.com/index/work-with-codex-from-anywhere/)、[9to5Mac 的报道](https://9to5mac.com/2026/05/14/openai-brings-codex-control-to-chatgpt-for-iphone-and-android/)。

两者的公开文档都没有说手机端是否签名。在它们那里，中继由模型厂商运营，信任它是前提。Crossline 的中继是本人自己运营的一台小服务器，开放注册，被攻破的代价更具体。所以多加一层手机签名（第 5 节）。

## 2. 现在已经有的，和缺的

已经有（不重做）：

- **出站长连接**：`apps/worker/src/node/`，心跳 15 秒，45 秒无回音判离线。
- **配对与令牌**：设备令牌或配对码，节点令牌绑定一个工作区。
- **节点上的 shell 助手**（P3）：`danger-full-access` + `untrusted`，任务文件夹，输入输出按哈希同步。每条命令的审批请求回到服务器的守卫（`agent-guard.ts`）。守卫判为「问」的写进账本，在待确认回答，10 分钟不答即拒（`ledgerAsk`）。
- **节点上的浏览器**：收藏读取、报名表填写，可见窗口，最后一步由本人点。
- **设备模式**：屏幕活动、授权文件夹、本机录音转写，结果经发件箱发给托管站。
- **网页推送**：发到手机。

缺的：

1. 手机上**直接发起**电脑上的工作。现在只能把账本里的任务「交给 Agent」，助手是否落到电脑上由系统决定，不能连续对话，也不能指定在哪个文件夹工作。
2. **直接执行命令**：没有。
3. **审批到手机**：守卫的「问」只在待确认里列出，没有推送，界面也不是为逐条命令设计的。
4. **服务器被攻破时的防线**：docs/compute-node.md「还没做」里写明，被攻破的服务器可以批准任何命令。节点能自己守的只有任务文件夹、审批策略和开关。
5. **从手机取电脑上的文件**：设备模式只把授权文件夹的文字发上去，原文件、没读入的文件、文件夹清单都拿不到。
6. **手机录音交给电脑转写**：设计里有（docs/compute-node.md A4），没做。
7. **报名表的最后一步**：只能在电脑前点。

## 3. 手机怎样连到电脑

```
手机浏览器 ──https──> app.crossline.lol（托管站：页面、账本、守卫、推送）
                           │ worker 的节点网关（已有）
                           ▼ 一条 wss，电脑主动连
                    这台电脑：设备模式 worker + 节点中继
                      ├─ codex app-server（本人自己的 ChatGPT 登录）
                      ├─ 远程会话管理（新）：校验手机签名，管会话文件夹，本机审计日志
                      └─ 授权文件夹、转写器、浏览器（已有）
```

**选托管站中继，不选 Tailscale：**

- Tailscale 要手机装客户端，还要 https 来源（docs/local-installer.md「已知限制」）。
- 设备模式下，本机网页除 `/device` 外都重定向到托管站，手机直连本机也没有页面可用。
- 中继已经存在，离线判断、重连、文件分块、审批回传都现成。手机只认一个网址：在线时多出「这台电脑」，离线时就是普通的托管站。
- 代价是每条消息多一跳服务器。命令输出要经过服务器，所以第 7 节限制了哪些内容可以回传。

**哪台电脑：** 这个账号已配对、开着「作为算力节点」、并且本机打开了「允许从手机遥控」的那台。可以是常驻版的设备模式 worker（127.0.0.1:3210），也可以是独立节点安装包。同一账号有几台时，手机上按主机名选。

## 4. 两本账怎样处理

- **托管站为主账本**，照 docs/device-mode.md 不变。远程会话的消息、命令、审批、结果摘要都写托管账本（`remote.*` 事件），手机在任何地方都看得到。
- **电脑不写托管账本**，只经节点连接回答。会话产出的文件按已有的 `pullResults` 拷回托管站，进「Agent 产出」。
- **电脑另记本机审计日志**（第 7.3 节），只追加，带哈希链。它不是第二本账，只是服务器碰不到的那份记录。
- **本地版（14892）不参与。** 它是一本独立账本，完整模式，不和托管站同步。要是让它也接受遥控，记录就会分散在两本账里，正是设备模式要避免的。本人在电脑前用本地版，在手机上用托管站加遥控，两者互不相干。（若本人想让本地版代替常驻版当遥控目标，见第 10 节第 1 条。）

## 5. 手机签名

### 5.1 配对一部手机

1. 电脑本机页面（设备模式的 `/device`，或独立节点的 `127.0.0.1:47391`）的「从手机遥控」卡片：点「添加手机」，显示一个 8 位配对码，10 分钟有效。
2. 手机打开托管站 设置 →「这台电脑」→「用这部手机遥控」，输入配对码。手机浏览器用 WebCrypto 生成一把 ECDSA P-256 密钥（`extractable: false`，存在 IndexedDB），把公钥和配对码经托管站发给电脑。
3. 电脑页面显示这把公钥的指纹（6 组 4 位数字），手机上显示同一串。本人核对一致，在**电脑上**点「确认」。确认只能在电脑本机页面做，服务器替不了。
4. 公钥存在电脑的 `<data>/device/remote.json`：标签、指纹、添加时间、最后使用时间。不进账本，不进镜像，服务器只知道「这台电脑登记了几部手机」。

清掉手机浏览器的网站数据，密钥随之丢失，要重新配对。这是有意的：密钥不能导出，所以也不能被复制走。

### 5.2 签什么

手机发出的每一件「要在电脑上执行」的事都签名：

```json
{ "kind": "session.start | message | command | approve | deny | folder.read | form.submit | session.stop",
  "computer": "<节点主机名>", "session": "<会话 id>", "nonce": "<随机 16 字节>",
  "payload": { "要执行的内容本身" }, "issuedAt": "...", "expiresAt": "issuedAt + 5 分钟" }
```

（实现：手机签的是这段 JSON 的原文 `body`，电脑按原文验签再解析，所以内容就在签名里，不另传；批准一条命令时 `payload` 里是那条命令的 sha256，电脑拿自己手上的命令比对。防重放用 `nonce`：电脑把收过的 nonce 存到过期为止，重启后也认得。）

电脑校验以下各项，任何一项不过就拒绝，并写进本机审计日志：

- 公钥在 `remote.json` 里；
- 签名有效；
- 没过期；
- `nonce` 没收过（防重放）；
- `payload` 和实际要执行的内容逐字节一致；
- `computer` 是自己。

服务器只是转交，改一个字节签名就失效。

### 5.3 它能防什么，不能防什么

- **能防**：服务器被攻破、托管站的会话 cookie 被偷。只拿到其中之一，都不能让电脑执行一条远程指令，因为没有手机里那把密钥。
- **不能防**：手机本身被别人拿到并解锁。这时攻击者能做本人在手机上能做的一切。补救是在电脑上移除那部手机（第 7.2 节）。
- **只管远程会话这一条路。** 已有的「无人值守」shell 助手（P3：系统派发的助手任务、工作流生长）不经过手机，签名管不到它。所以电脑上的开关改成三档（第 7.1 节），本人可以只开远程、不开无人值守。

## 6. 手机上能做的事

### 6.1 电脑会话（助手）

托管站新页面「这台电脑」（`/computer`，也是小帮手里的一个线程类型），手机视口优先：

- **顶部**：电脑在线或离线、主机名、最后在线时间、正在进行的会话。
- **开始会话**：选工作文件夹，选审批方式，签名后开始。
  - 工作文件夹只能从电脑本机设定的「遥控可用的文件夹」里选；默认只有会话自己的临时文件夹 `<任务根>/remote-<id>`。
  - 审批方式两种：「每条命令都问我」，或「会话文件夹内的命令自动执行，其余问我」。默认前者。
- **对话**：本人发消息（签名），电脑上的 Codex 线程执行。手机上流式显示每条命令、改了哪些文件、输出的前几十行，复用 `onLive` 和小帮手的工具步骤（`tool-steps.tsx`）。
- **审批卡片**：需要问的命令，推送到手机（只有这一类算「紧急」，夜间也推），卡片上是完整命令、工作目录、守卫给的理由。本人点「执行」或「不执行」，两者都签名。5 分钟不答即拒，告诉助手「本人暂未批准」。
- **停止**：随时停止，签名。电脑立即中断这个回合并结束它启动的进程。
- **结束**：会话到期（默认 1 小时，最长 8 小时，开始时选）或本人结束。产出文件拷回托管站，进「Agent 产出」。

助手用节点上本人自己的 ChatGPT 登录运行，模型请求直接从电脑到 OpenAI，不经服务器的模型网关，所以服务器篡改不了模型的回答。第三方模型（provider）不开电脑会话，因为它们的请求要经服务器网关加 key。

### 6.2 直接命令

会话里以 `!` 开头的消息不交给助手，原样作为一条 PowerShell 命令在当前工作文件夹执行：

- 签名的 `payload` 就是命令文本本身。
- 执行前同样过守卫：
  - 守卫判「拒」的（凭据路径、发送、付款、改系统、删根目录、下载后直接执行）照样拒绝，即使是本人打的。原因是输出要经过服务器：在手机上读 `.ssh` 等于把它交给服务器。
  - 判「问」的，弹一次确认卡片，签名后执行。
  - 其余直接执行。
- 限制：一次一条；10 分钟超时；输出只回传前 64 KB，账本里只存前 4 KB；每小时最多 60 条。
- 实现上不经 Codex：节点用自己的子进程执行（`command/exec` 仍在节点白名单之外），工作目录固定，环境变量照 `NODE_RUNTIME_FLAGS` 去掉密钥类。

### 6.3 授权文件夹

只在设备模式的电脑上有（授权文件夹存在本机暂存账本里；独立节点没有授权文件夹）。

- **列清单**：手机上按文件夹浏览，可以看名字、大小、日期。
- **读一个文件**：文字类在手机上直接显示；其余（PDF、图片、音视频）拷到托管站，以原文件打开。单个最大 20 MB。
- **存进 Crossline**：作为资料归到某个项目，即 `source_documents`。

规则：

- 列清单不签名，只读元数据，规则照设备模式。读内容要签名（`folder.read`），因为原文件会离开电脑。
- 排除规则、私密文件、凭据文件照 `source-folders.ts` 在**电脑上**执行；这些文件不列出、不可读。
- 路径只能在授权文件夹之内，不跟随链接，`..` 拒绝。
- 写入、删除、移动都不提供。要改文件，就在电脑会话里让助手做，由会话的审批管。

### 6.4 录音转写

不涉及执行，不签名。手机上传的录音先到托管站。

- **电脑在线**、打开了「替手机转写录音」（电脑本机开关，默认关）、本机有转写器时：托管站把音频经节点连接发过去，电脑转写后只回文字（docs/compute-node.md A4）。
- **其余情况**：照旧由托管站夜间转写。
- 两条路都以录音的 sha256 为键（`recording.transcribed`），不会转两次。
- 电脑在转写中途离线的，托管站收回，夜间再转。

### 6.5 报名表单

节点上填表已有，最后一步现在停在「等本人提交」，只能在电脑前点。

- **新增**：手机上看这份表的截图（填好后两分钟内截的）和每个字段的值，点「提交」（签名，`form.submit`，`payload` 为截图哈希加字段值哈希）。电脑在可见窗口里点提交按钮，回传提交后的截图。
- **付费的永远不行**：任何需要付款的表单，手机上不出现「提交」，`CLAUDE.md` 的付款边界不变。
- 截图过期、字段在截图之后变过的，电脑拒绝，要求重新截图。

### 6.6 不做的

- 远程看电脑屏幕、操作鼠标键盘（远程桌面）。
- 远程开摄像头、麦克风。
- 远程改电脑上的 Crossline 设置：遥控开关、手机列表、遥控文件夹、shell 档位只在电脑本机改。
- 唤醒休眠的电脑（网络唤醒）：需要路由器配合，不在本设计里。
- 别人的手机遥控本人的电脑。手机密钥绑在电脑上，只有本人在电脑前能加。

## 7. 安全边界：授权、撤销、审计、越界拒绝

### 7.1 授权（五层，全部满足才执行）

1. **托管站登录**：本人账号的会话。
2. **节点配对**：已有。电脑的节点令牌绑定本人的工作区，「作为算力节点」两边都开。
3. **电脑本机开关**：本机页面的「shell」从现在的「开/关」改为三档，存在电脑本机（`<data>/device/node.json` 或独立节点的配置），服务器改不了：
   - **关**（默认）：没有 shell，也没有电脑会话。
   - **只从手机遥控**：只开电脑会话，每件事要手机签名；系统派发的助手任务不在这台电脑上跑 shell。
   - **无人值守**：除电脑会话外，还允许现有的 P3 助手任务（工作流生长、剪辑、外部任务）。等于今天的「开」。
   现在开着「开」的电脑，升级后读作「无人值守」，行为不变。
4. **手机密钥**：配对时在电脑屏幕上确认（第 5.1 节）。
5. **逐件签名**：开始会话、每条消息、每条直接命令、每次批准、读文件、提交表单（第 5.2 节）。

逐次确认的分工：

| 动作 | 守卫判定 | 手机上 |
| --- | --- | --- |
| 开始会话（文件夹、审批方式、时长） | — | 签名，一次 |
| 发消息给助手 | — | 签名（发送即签，不另确认） |
| 助手的命令，审批方式「每条都问」 | 允许 / 问 | 每条都弹卡片，签名批准 |
| 助手的命令，审批方式「会话文件夹内自动」 | 允许，且只涉及会话文件夹 | 不问；电脑再判一次，见下文 |
| 助手的命令，审批方式「会话文件夹内自动」 | 问，或涉及文件夹以外 | 弹卡片，签名批准 |
| 任何命令 | 拒 | 不弹卡片，直接拒绝，手机上显示拒绝理由 |
| 直接命令 `!…` | 允许 | 签名（发送即签） |
| 直接命令 `!…` | 问 | 再弹一次确认，签名 |
| 读授权文件夹里的文件 | — | 签名 |
| 提交报名表（免费） | — | 看截图后签名 |
| 付费、发送邮件、对外发布 | — | 永远没有这个按钮 |

「会话文件夹内自动」也要在电脑上能判，不能只信服务器：节点自带一份守卫（`packages/core/src/agent-guard.ts` 只依赖 i18n，打进独立节点包，打包白名单加这两个文件）。电脑只有在自己的守卫也判「允许」、并且命令里出现的绝对路径都在会话文件夹内时，才不要手机签名；否则没有签名的「执行」一律改成「不执行」。

### 7.2 撤销

| 谁 | 在哪 | 效果 |
| --- | --- | --- |
| 本人 | 手机：会话页「停止」/「结束」 | 中断回合、结束进程、关会话（签名） |
| 本人 | 电脑：本机页面或托盘「断开遥控」 | 立即结束所有电脑会话；档位不变 |
| 本人 | 电脑：档位改为「关」或「无人值守」 | 立即结束所有电脑会话；不再接受新的 |
| 本人 | 电脑：手机列表里「移除」 | 这把公钥立即失效，它签的东西一律拒绝 |
| 本人 | 托管站：撤销节点或设备令牌 | 15 秒内断开节点（已有），会话随之结束 |
| 本人 | 托管站：退出所有登录 | 手机进不了托管站，也就发不出指令；公钥仍在电脑上，要另外移除 |
| 系统 | 会话到期（1–8 小时） | 自动结束 |
| 系统 | 节点断开超过 10 分钟 | 会话结束 |

手机丢了：在电脑上移除那部手机，再在托管站退出所有登录。两步做完前，拿着手机的人还要能解锁手机、并有托管站的登录，才能发指令。

### 7.3 审计

两份记录，各管一半：

- **托管账本**（手机上看得到，「这台电脑」页的「历史」）：
  - 记 `remote.session.started|ended`、`remote.message`、`remote.command`、`remote.approval`、`remote.folder.read`、`remote.form.submitted`、`remote.refused`；
  - 每条带会话 id、签名的手机（指纹的前 8 位）、时间、守卫规则、退出码、输出前 4 KB、改动文件的列表和哈希；
  - 保留 90 天；
  - 删除账号时随工作区一起删（`purgeWorkspace` 按 `workspace_id` 删，自然覆盖）。
- **电脑本机日志** `<data>/device/remote-audit.jsonl`：
  - 每行一件事，包含收到的原始签名和校验结果（拒绝的也记）；
  - 每行带上一行的 sha256（哈希链），事后改其中一行，后面的链就对不上；
  - 本机页面上可以看，可以导出；
  - 不经节点连接发出去，服务器读不到也改不了；
  - 保留 180 天。

对照：托管账本说「电脑执行了 X」，本机日志里必须有一条签名对得上的 X。本机页面提供一个「核对」按钮：对最近 7 天，列出托管账本有、本机日志没有的条目（经节点连接取托管站的事件，只读）。

### 7.4 越界拒绝（逐条，电脑上执行，返回给手机的代码）

| 情况 | 代码 |
| --- | --- |
| 档位不是「只从手机遥控」或「无人值守」 | `REMOTE_DISABLED` |
| 没有签名、签名无效、公钥不在列表里 | `REMOTE_SIGNATURE_INVALID` |
| 签名过期（超过 5 分钟） | `REMOTE_SIGNATURE_EXPIRED` |
| `nonce` 已收过（重放） | `REMOTE_REPLAYED` |
| 签名的内容和要执行的内容不一致 | `REMOTE_PAYLOAD_MISMATCH` |
| 签的是别的电脑 | `REMOTE_WRONG_COMPUTER` |
| 工作文件夹不在本机「遥控可用的文件夹」里 | `REMOTE_FOLDER_REFUSED` |
| 读文件的路径在授权文件夹外、是链接、含 `..`，或命中排除、私密、凭据规则 | `REMOTE_PATH_REFUSED` |
| 守卫判「拒」：凭据路径、发送、付款、改系统、提权、下载后执行、删根目录 | `REMOTE_GUARD_DENIED:<规则>` |
| 线程不是 `untrusted`、`cwd` 不是会话文件夹、回合想改沙箱或审批 | `NODE_SHELL_REFUSED`（已有） |
| 同时已有一个会话（每台电脑同时一个） | `REMOTE_BUSY` |
| 直接命令超过每小时 60 条 | `REMOTE_RATE_LIMITED` |
| 表单需要付款，或截图过期、字段已变 | `REMOTE_FORM_REFUSED` |
| 会话已结束或过期 | `REMOTE_SESSION_CLOSED` |

托管站自己也先挡一遍（会话 cookie、同源检查 `isCrossSiteWrite`、账号绑定、守卫），但电脑不依赖这一层。

### 7.5 要更新的 `CLAUDE.md` 安全边界

实现时在「Safety boundaries」加一条：

> 从手机遥控电脑：只经算力节点连接，电脑只执行带有效手机签名的远程指令；手机密钥只能在电脑本机确认添加；档位、手机列表、遥控文件夹只在电脑本机设置；守卫的「拒」不可被签名覆盖；付款没有遥控入口。放宽其中任何一条要本人另行决定。

## 8. 离线时怎样降级

- **在线判断**沿用节点心跳：15 秒一次，45 秒无回音判离线。手机页面显示「电脑在线」或「电脑离线（最后在线：…）」。
- **离线时**：
  - 「这台电脑」页只显示历史和状态，「开始会话」、读文件夹、提交表单都不可点。
  - 页面上写明：其余功能都在托管站照常可用；助手可以用托管站的工具模式（能联网查、能写文件，不能执行命令）。
  - 提供「电脑上线时通知我」：电脑一上线就推送一条，本人点开再开始。**不排队执行**。离线时签好的指令几分钟后就过期，排队等于让电脑在没人看着的时候自己动。
- **会话进行中断线**：
  - 手机显示「电脑断开，等待重连」。
  - 节点 10 分钟内重连：会话一直在电脑上跑着（它的运行时是电脑自己起的，不靠这条连接），断开期间的进度先存在电脑上，连上后先补发给托管站。
  - 超过 10 分钟：会话结束（`session.ended`，原因 `away`）。产出留在电脑的会话文件夹里。
- **托管站本身不可用**：手机什么都做不了，电脑上正在跑的回合跑完当前命令后停下等待，不自行继续。电脑前的本人照常用本地版。
- **其他本机功能**：录音转写回到托管站夜间转写；报名表停在「等本人提交」，电脑上线后手机上再出现；文件夹不可浏览。

- **签名**：无签名、错签名、过期、重放、内容不符、别的电脑、移除的手机，各自返回对应代码，并写进本机日志。

## 10. 本人的决定（2026-11-22：六条都按推荐）

1. **遥控目标是哪台。** 推荐常驻版的设备模式 worker（3210），它已是托管站的设备和算力节点。若本人以后只开本地版（14892）、不开常驻版：本地版可以另起一个只做节点、不碰账本的中继，但遥控的记录在托管账本，本地版的账本里看不到。要不要做这一条？
2. **直接命令（第 6.2 节）要不要。** 推荐要，放在 R2。不要的话，「调用 shell」只能经助手。
3. **守卫的「拒」对本人自己打的直接命令也生效。** 推荐生效（输出要经过服务器）。若本人希望对自己打的命令放宽，只能放宽「改系统设置」一类，凭据路径和付款不放宽。
4. **报名表在手机上提交（第 6.5 节）。** 推荐做，只限免费的。
5. **会话默认审批方式。** 推荐「每条命令都问我」，本人每次开会话时可以改成「会话文件夹内自动」。
6. **只给本人，还是每个配对了自己电脑的账号都能用。** 机制本来就按账号、按电脑分开（方案 C 的电脑只给自己的账号跑），推荐都能用，但默认关；第一期只在本人的电脑上实测。

## 11. 实现记录（2026-11-23）

和上文不同的地方：

- **防重放用 `nonce`，不用 `seq`**（第 5.2 节已改）。`seq` 要求手机和电脑都记住每个会话的计数，手机换页面或重开就对不上；nonce 只要电脑记到过期。
- **电脑会话的运行时由电脑自己起**，不是服务器派来的线程：服务器没有一条能把回合送进这个运行时的路，所以电脑的开关在「只从手机遥控」时，服务器的 P3 shell 助手照旧拿不到这台电脑（只有「无人值守」给 P3）。因此断线不用 `thread/resume`，会话本来就一直在电脑上（第 8 节已改）。
- **审批全在电脑上判。** 运行时的每个审批请求先过电脑自己那份守卫：「拒」直接拒，手机看不到也覆盖不了（`approval.refused`）；「会话文件夹内自动」只在 `confinedTo` 判定命令里的路径都在会话文件夹内、且守卫不判「问」时自动执行，其余推到手机等签名。
- **托管站不可用时**，电脑上的会话不停：「每条都问」时下一条命令等不到批准，5 分钟后被拒；「会话文件夹内自动」时文件夹内的命令照常执行。
- **产出不拷回托管站。** 产出留在电脑的会话文件夹，手机上看到改了哪些文件（只传路径的哈希和文件名）。要拿走，经授权文件夹「存进 Crossline」。
- **手机页面的 e2e 截图没有加。** 手机视口下的状态是用临时实例和假 supervisor 看的（在线、配对、开始会话、后台服务没连上）；`design-audit` / `copy-audit` 没有扩。
- **配对时指纹留在手机屏幕上**，直到本人在手机上点「电脑上已确认」，避免看不到数字就跳过核对。
