## 一、深度和被认可：把推断分成三级

### 问题

观察卡的「准」率是这套访谈一直在调的指标：第十七、十八次回放 80 张卡里「准」7 张，于是规则一路收紧。d3f04d416f 里还在的有：「补充不替换」（访谈 Skill 规则 4）、一张卡一个论断、结论范围和证据一样大（观察卡一节「『准』从哪来」）；画像撰写仍禁止「点破」和「反转」，要求证据写在同一句。访谈 Skill 规则 11 已经改成「客观、理性、平静，不冒犯、不回避」，不再点名禁止「其实你……」，但禁止比喻和金句仍在。每一条单独看都合理，合起来的效果是：卡片越来越容易被认，也越来越接近本人已经知道的东西。

Sharma 等（ICLR 2024）的结论在这里同样适用：用人的偏好去优化输出，会系统地偏向附和对方已有的看法，有时以牺牲真实为代价。拿「准」率当目标，就是在训练访谈附和本人。

另一方面，评得「部分对」也不全是推断错了。Finn 的治疗性评估把反馈按离本人自我看法的距离分三级：一级证实本人已有的看法，二级小幅修正或延伸，三级与自我看法差得远、容易被当场拒绝。Finn 与 Tonsager 发现，轻度不一致的反馈影响最大，完全一致和差得很远的都更小；Swann 与 Hill（1982）发现，不一致的反馈只有在本人没机会当场驳回时才会改变自评。参考稿的写法正好吻合：本人是读完整份文档、隔了一段时间才逐条打分的，而不是一句一句当场点「不准」。

### 设计

1. **每条假设标一个级别**（`level: 1 | 2 | 3`），由整理线在写假设时给出，标准是离本人自述有多远：
   - 一级：本人自己说过的规律，换了说法；
   - 二级：本人说过的两件事之间的联系，或在本人给的原因之外多出的一层；
   - 三级：和本人对自己的解释相反，或重新解释本人给某种行为起的名字（「止损」「中期主义」）。
2. **级别决定去处。**
   - 一级不出卡：本人知道，换个说法写上卡只是复述。它进账本，报告里作为背景用。
   - 二级是观察卡的主体，照现在的方式当场评「准 / 部分对 / 不准」。
   - 三级不上卡，也不在对话里说。它们只进报告私人的后半部分，排在最后（Finn 的顺序：先一级，再二级，最后三级），每份报告最多三条。报告里三级的段落不让当场点「不准」，而是给一个「过几天再评」：三天后提醒一次，那时本人读的是整篇叙事，而不是孤立的一句。
3. **卡片加一个维度。** 「准 / 部分对 / 不准」之外，加一问「这个你以前想到过吗：想到过 / 没想过」。深度的指标改成「准或部分对，并且没想过」的比例；单独的「准」率不再作为调规则的依据。
4. **改两条规则，不是删。**
   - 访谈规则 4（补充不替换）只管两样东西：**感受和动机的自述**（焦虑、喜欢、为什么想做）仍以本人为准。本人给一类**行为**起的名字和解释（「这是止损」「这是按情境选择」）可以被重新解释，前提是写出另一种解释依据的事实。
   - 画像撰写里的「不点破、不反转」：保留对**修辞**的禁止（「其实」「原来」「说到底」、比喻、反转句式），不再禁止**内容**上的重新解释。访谈规则 11 现在的写法（不冒犯、不回避）已经是这个意思，画像撰写跟上即可。参考稿就是这样写的：平铺直叙地说出与本人自述相反的结论，没有一个「其实」。

### 护栏

- 三级只在私人部分，永远不进可分享的前半部分和分享卡。
- 访谈里触发过「安全」处理（低落、自伤念头）的，报告不写三级。
- 三级的每一条要有两个以上互相独立的来源（不同场景的回答、文件、调研结论）；证据留在账本里，报告不印出来（见四）。
- 级别是整理线的判断，可能判错：一条二级被当成三级，后果只是晚一点被评，代价小；反过来，三级上了卡被当场否定，代价大。拿不准时往高一级放。

### 批判

- 不让三级当场被否，可能被读成操纵。所以报告里写明这些是「离你的自述最远的几条，读完全文再评」，并且本人随时能评；只是页面默认不在每句话后面放按钮。
- 「没想过」也是自评，有人会为了显得有自知之明点「想到过」。它只用来比较不同版本的访谈，不对单个人下结论。

## 二、把「不准」当材料

### 问题

现在 `rated: "off"` 的假设被标成 `refuted`，「不再提」（`profile-points.ts:176`），画像撰写也不能用它。这样做防住了重复断言，也丢掉了参考稿第 6 节的那一层：本人判「不准」的论断集中在哪一类，更正时用的是哪种句式。

### 设计

保留规则「被否定的内容不再断言」，另加一层**对评分本身的描述**。它由代码统计，模型只负责解释：

1. **评分分布**（代码算）：按维度（D0–D9）和整理线给的主题，统计每类假设的「准 / 部分对 / 不准」。某一类至少有 4 条评过、其中「准」为 0 且「不准」过半，而其他类的「准」明显更多时，记一条 `ratingPattern`。
2. **更正的类型**（整理线标注）：每条「部分对」「不准」的附言归成四类之一：
   - 否认事实；
   - 承认事实、否认它的意义（「后来已重测」「后果可控」）；
   - 补一个例外；
   - 用更高一层的目标把两种相反的行为都解释成手段（「都需要」「统一」「一切以目标为导向」）。
   第二和第四类反复出现，本身就是一条规律。
3. **画像撰写怎样用**：只写分布和更正方式这两个事实，以及它们说明本人在维护什么；不写「你否认是因为它是对的」，也不借这一节重新提出被否认的内容。

### 批判

这里最大的风险是心理分析里「阻抗」解释的老问题：本人否认，就说明说中了。这种推理永远不会错，也就什么都没说。所以有两条硬限制：

- 结论只能是关于**评分行为**的（哪类被否、怎样更正），不能是关于**被否内容**的真假。
- 样本不够就不写。一场访谈通常只有十几到二十几张卡，多数时候达不到阈值，这一节就空着。参考稿能写，是因为本人一次评了几十条。

## 三、从字段到叙事：先自由写，再拆成字段

### 问题

`PortraitReport` 有 cover、type、problem、compass、energy、lines、gap、insights、formulation、careers 等十几个字段，每段都有字数上限；JSON schema 在一次运行里一起生成。结果是十几块互相独立的短文本，没有一条贯穿全篇的线。参考稿的力量在第 10 节：用一条原则（裁决权）把前 9 节串起来；而且这条原则是第二版推翻第一版（效率）后才找到的。

Tam 等（EMNLP 2024）发现，严格的格式约束（尤其是 JSON 约束解码）会降低推理质量；常见的缓解办法是先自由推理和写作，再单独做一步格式转换。

16 型（「某神秘光头」）和「不贴标签」的规则互相矛盾。上一份方案的 D12 已定「系统不生成」，但 d3f04d416f 的画像撰写 Skill 和 `PortraitReport.type` 还没改，这一步和本节一起做。

### 设计

画像改成两步：

**第一步：叙事（新 Skill `crossline-portrait-narrative`，自由文本，不给 outputSchema）**

- 输入和现在的画像撰写相同，加上一、二两节新增的级别和评分分布。
- 先在草稿里列出 2–3 条候选的统领原则，逐条检查它能解释几节；选能解释最多节的那条，并写出它没解释到的部分。这一步对应参考稿从「效率」到「裁决权」的那次推翻。
- 正文：每节一个论断作标题，下面是连贯的段落；最后一节把各节接到统领原则上，以一个本人自己要回答的问题收尾。
- 人生叙事单独成一节，按时间写：人生的几章、转折、本人当时和现在分别怎样讲它们、下一章本人怎样设想。这一节写的是本人的故事，不是对本人的评价。
- 称呼按本人在「称呼」里选的。

**第二步：拆成字段（现有的 `crossline-portrait-writer` 改成读叙事）**

- 输入多一份叙事全文，任务变成从叙事和账本填现有的字段：雷达、能量图、主线、职业方向。不新增叙事里没有的论断。
- 按 D12 去掉 `type` 和 16 型的段落；本人自己带来的类型测试结果，按自述出现在叙事里。

**页面**

- `portrait/page.tsx` 私人的后半部分新增「叙事」一页，放在图表之前。
- 本人可以在叙事的任意一段标「不对」并写一句，进 `rejectedClaims`，下次重写时生效（现有的机制）。

### 批判

- 成本：多一次长运行。现在画像撰写的超时已是 60 分钟；叙事和拆字段串行，结束到出报告的时间会变长。可以先出图表部分，叙事随后补上，页面写明「叙事还在写」。
- 两步之间可能不一致（叙事说 A，字段写 B）。第二步的规则是「只从叙事和账本取」，再加一个代码检查：字段里出现的人名、数字、日期必须在叙事或账本里出现过。
- 统领原则可能是硬拗出来的。草稿里要求写「这条原则解释不了哪几节」；解释不了一半以上的，就不写统领一节，只写各节。

## 四、两层：账本带证据，叙事不带

### 问题

现在每张卡要两条逐字引文、外部网址、证伪条件，画像每个说法也要能追溯，并按渠道数分「可能 / 肯定」。这些对**核对**有用，对**阅读**是噪声。参考稿把两件事分开了：`01` 主档案和 `03` 原话证据库存证据，`10` 洞察版只有论断，声明「不标证据来源和置信度，不确定的地方用『可能』『大概』」。D13 已经把右栏和画像上的「依据 N 条」和置信度去掉了，但画像撰写 Skill 仍要求证据写在说法的同一句里，所以报告正文还是带证据的写法。

### 设计

- **账本层不变**：`profile.points` 现在是 24 维的自由笔记（`dimension` 为 M1–M24，带原话、材料或文献 `literature`，互相矛盾的用 `contradicts` 两条都留）；`hypotheses` 照旧带引文、证伪条件和评分；代码对引文的逐字核对（IR-001、IR-003）照旧。这一层是更新画像、处理「不对」反馈和审计的依据。
- **叙事层不印证据**：不出现引号里的原话、网址、「置信度」「把握」「证据」这类词、编号。不确定用句子里的「可能」「大概」表达，不加单独的标签。
- **追溯在后台**：叙事 Skill 在每段末尾输出不显示的要点 id 列表（`<!-- points: p3,p7 -->` 之类，渲染时剥掉），代码检查这些 id 存在，并且每段至少挂一个。本人标一段「不对」时，知道是哪几条要点出了问题。
- **代码检查叙事**：超过 15 个字的逐字引文、URL、「置信度」等词出现就退回一次。
- **观察卡**：卡上的证伪小字保留（它告诉本人怎样核对，是卡片有用的原因）；引文继续留在数据里供代码核对，页面上默认收起。这一条要先问本人：卡片是否也要去掉引文。

### 批判

不印证据，读者就没法当场判断一句话站不站得住，报告更容易被当成定论。这个风险靠两件事抵消：叙事里保留「可能」「大概」这类自然的限定；每段都能被标「不对」，而且标了真的会改。如果两个都不做，去掉证据就是把模型的推断包装成事实。

## 五、叙事阶段：问事件，问前后，要旧文件

### 问题

d3f04d416f 的 `stages/narrative.md` 已经重写：从量表读数和材料出发，按章节走，每章一个具体场景和本人事后的解释，苏格拉底式追问到一条本人自己的规则，再问高峰、低谷、转折和下一章。这比旧版好。还缺的是三件事：场景**之后**本人做了什么；同一件事**当时和现在**两次解释的差别；结果由**谁**裁决。这三件分别是参考稿第 1、4、2 节的材料。画像框架（`profile-framework.ts`）列了 McAdams 的能动 / 交融、救赎 / 污染，但整理线没有逐场景编码。本人随时可以按「结束并出报告」，人生故事可能还没讲。

### 设计

1. **每个关键场景按事件问到底**（McClelland 的行为事件访谈，源自 Flanagan 的关键事件法）：什么时候、发生了什么、你当时做了什么，然后追问三件事：
   - **之后一周**：那之后几天你做了什么，有没有写下新的计划、目标或清单？这是参考稿第 1 节的材料。
   - **当时和现在**：当时你怎么看这件事，现在怎么讲它？两次解释的差别是参考稿第 4 节的材料（「申请失败后不得不做的选择」变成「必经之路的跳板」）。
   - **谁定的**：这件事的结果、期限由谁决定？对应参考稿第 2 节，区分自设和外部的裁决。
2. **要旧文件，不只是简历。** 准备页的上传已经支持 AI 历史对话（D14：ChatGPT 的 `conversations.json`、Codex rollout、Claude Code `.jsonl`，只抽本人的话和逐段摘要）。本稿只加两点：
   - 上传处点名请本人交两类容易被忽略的东西：过去写过的计划、目标清单、年度复盘；简历和个人主页。它们是「当时怎么说」的原件。
   - 导入的 AI 对话不只当背景读。整理线对它做三件事：按时间排出本人立下的计划和目标，和它们后来是否再出现；找同一件事前后两次的说法；统计分档和排名用词。对话导入的同意和范围按 D14 不变，产出只进私人部分。
3. **整理线标显著性**（psychobiography 里常用的标记：首次出现、反复出现、独特、强调、否认、遗漏、口误或前后矛盾、没讲完的）：每条回答过一遍，命中的片段写进假设的依据。参考稿第 5 节的「分档用词」就是「反复出现」这一标记。
4. **叙事编码**：每个场景由整理线标能动 / 交融、救赎 / 污染、意义建构，写进 D8。
5. **结束按钮**不拦人，只多说一句话：人生故事少于三个场景时，按钮旁写「人生故事还没讲，报告里的叙事会很短」。报告里的叙事一节按材料多少写，材料少就短，不补。

### 批判

- 行为事件访谈仍然是自述，回忆有偏差；它只是比「你一般怎样」更接近实际发生的事。研究上的效度来自盲编码，这里的编码者是模型，没有盲。
- 访谈变长。每个场景多追问三件事，叙事阶段大概多 6–10 轮。参考稿的本人愿意花几个小时；多数用户不会。追问只在本人答得具体时继续，答「记不清」就停（现有规则 5）。
- AI 对话里本人给 AI 的指令往往比本人平时更绝对（参考稿第 7 节就提到这一点），按指令的语气推性格会偏。整理线要把「对 AI 下指令」和「本人自己的笔记」分开读。

---

## 六、规则：从补丁到少数原则加评测

### 问题

d3f04d416f 已经做了一轮收缩：规则登记表 `packages/core/src/interview-rules.ts` 从 99 条在用降到 92 条（55 条代码检查，35 条写在 Skill 里，1 条在子运行），退役的从 22 条增到 40 条；访谈 Skill 从 35.7KB 压到 22.8KB。但整理 Skill 从 46.4KB 涨到 52.5KB，画像撰写 25.9KB 没动，三个合计仍约 101KB，每轮还有阶段清单和画像框架。IFScale（Jaroslawicz 等，2025）发现，指令越多，同时遵守全部指令的比例越低，最好的模型在 500 条时约 68%；后续研究把一部分下降归因于指令之间的冲突。

这里的冲突是具体的：「多出一层推断」「给本人没想到的东西」和「补充不替换」「结论范围和证据一样大」「不点破」互相拉扯。多数检查退回的是形式（引文来自哪几条回答、`reply` 是否重复卡片），模型的注意力被这些占掉。

### 设计

1. **代码检查分两类。**
   - **事实和安全**（引文逐字、日期窗口、不编造日期、隐私、安全）：保留现在的退回。
   - **风格和深度**（卡片引文不全来自最近两条回答、一张卡一个论断、`reply` 不重复卡片等）：从「退回」改成「记分」，写进每轮的审计，不打断这一轮；回放评测里看分数。
2. **Skill 文本压到原则级。** 访谈 Skill 的核心控制在约 10KB：七八条原则，每条一个理由、一个例子。具体的回放事故和数据（「第十七、十八次回放 80 张卡……」）移到 `docs/onboarding-agent-session.md`，Skill 里不留。整理和画像 Skill 同样处理。
3. **每条规则要靠评测留下来。** 建一个回放评测集：
   - 本人的真实访谈记录，以参考稿为标准：数第一轮可达的那一半（见〇）里，画像命中了几条；
   - `crossline-eval-persona` 生成的几个不同人物，避免只对本人一个人调。
   每个指标（深度：「准或部分对且没想过」的比例；准确：「不准」率；事实错误数；轮数）在删一条规则前后各跑一次，没有可测作用的规则删掉，并在登记表里标 `retired`，写上评测结果。

### 批判

- 把风格检查改成记分，过去回放里修掉的问题（重复问、把访谈的重复写成本人的特征）可能回来。所以先在评测集上跑，确认这些问题的频率没有回升再上线；回升的那几条恢复为退回。
- 用本人的参考稿当标准有两个偏差：参考稿用了第一轮拿不到的材料（只比可达的那一半）；它是一个人的画像，调得太贴会过拟合。人物评测集是为了抵消后者，但模型生成的人物又比真人更「好读」。真实用户的「没想过」比例最终要看上线后的数据。

---

## 实施顺序

改动之间有依赖，按这个顺序：

1. 回放评测集（六之 3）：之后每一步都要靠它判断有没有变好。
2. 假设分级和三级的去处（一）、「不准」当材料（二）：整理线和卡片的改动。
3. 叙事 Skill 和两步画像（三）、叙事不印证据（四）：新 Skill、`portrait-writer.ts`、`portrait/page.tsx`。
4. 叙事部分的追问和整理线的编码（五）。
5. 规则收缩（六之 1、2）：在评测集上逐条做；整理 Skill 是重点。

需要本人决定的：

- 三级推断是否默认不让当场评「不准」；
- 观察卡是否也去掉引文。
