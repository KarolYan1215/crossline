# P-A 闭环主线：实施计划（2026-10-12）

依据：`docs/loop-and-scout.md`（已定稿）§12 的 P-A：第 0 步 → §1 → §2 → §3 → §13（含 §8 登录）→ §4 → §5。本计划只覆盖 P-A；P-B…P-F 另写。

## 目标

让排期**默认生效并到达本人的日历**、执行**被一键记下**、决定**收敛到当天必须定的**、代理和教程**只为 48 小时内要做的事**生成。外部日程是硬约束，系统的工作块是软约束；锁定只来自本人的动作。

## 架构摘要

- **去掉计划批准**：`plan_changes` 表与 `approvePlanVersion`/`resolvePlanChange` 整条链删除，`plan_versions` 只留一行「当前现实」，日历同步直接改它。迁移 14 与 `importSnapshot` 都把旧 `plan_changes` 行转成 `plan.change_archived` 事件。写 Crossline 日历不再看 `plan.status`。
- **一个冻结模型**：设置项 `schedule.frozen` = `[{ blockId, start, end, reason: "pinned"|"keep"|"commit"|"locked", until? }]`（ISO 时刻），取代 `schedule.pins` 与 `schedule.keep`；规划器按**块**冻结（减去该段分钟），不再把带冻结块的任务整个移出求解。
- **与提供方无关的改动判定**：写入器只回报读回的「标题 + 起止时间」，`classifyCalendarEdits` 判定 时间变了=锁定 / 只改标题=保留标题 / 删了=不再重建 / 任务完成=强删残留。Graph 写入器与新的 Google 写入器共用。
- **排程引擎两档**：页面只跑简单排法（`solver: "none"`）；网页进程里的 `worker_threads` 线程只做 HiGHS 求解（20 s），结果按「排程输入哈希」缓存在 `schedule.optimal`；发布只用最优解（60 s 兜底回退）。
- **完成确认**：块到计划结束 → `block_confirm` 提醒（电脑与手机都发）→ 只打开确认小页 → 小页 POST 写一条已关闭的 execution；最后一步走 `completeWorkOrderExecution`。
- **日历**：读改经本地 Codex 的 apps（专用线程 + `mcpServer/tool/call` + 只读白名单 + 独立 5 分钟定时器），去重键 iCalUID + 原始开始时间并记 `sourceKeys[]`；写改为自建 Google 写入器（`calendar.app.created`，令牌由 Better Auth 存 `auth.db`）。五阶段迁移，Graph 最后删。

## 技术约束

- pnpm 工作区（Node ≥ 22），测试 vitest，单文件 `pnpm vitest run <file>`；类型 `pnpm typecheck`；全量 `pnpm verify`（typecheck + test + build + e2e）。
- 包直接导出 TS；`tsconfig.base.json` 开着 `strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`。
- web 库文件带 `import "server-only"`，vitest 用 `vi.mock("server-only", () => ({}))`；脚本用 `scripts/pending-horizon.ts` 里的 `register(...)` 写法绕过，并只读**账本副本**（SQLite online backup）。
- 每个新的变更路由第一行调用 `isCrossSiteWrite`（`apps/web/app/api/csrf-protection.test.ts` 会自动发现并断言 403）。
- 新增 `schedule.` 设置项自动进入撤销（`apps/web/lib/undo.ts` 的 `UNDOABLE_SETTINGS`）；`schedule.optimal` 只由后台写，不在 `withUndo` 内。
- **不提交**：本人要求之前不 `git commit`。每个任务组末尾写「建议提交点」，由本人决定。git 提交需用 `GIT_AUTHOR_*`/`GIT_COMMITTER_*` 环境变量（见 auto-memory）。
- 标记：**【真实运行】** = 需要真实账本副本或真实 Codex 运行时；**【本人操作】** = 只有本人能做（OAuth 同意、云控制台、学校账号）。其余任务都能在测试里完成。
- Ponytail：能删就删、复用现有函数；不为第二个调用方预留抽象。

## 风险

- **日历写入没有人工闸门**（§9 最后一条）：删除计划批准后，写入边界是唯一保护。1.7、1.16、4.12 都保留并补了边界测试（只写 Crossline 日历、只改本应用建且未改过的、只删未来、预排块不写）；任何改写入器的提交都要先跑这些测试。
- **apps 依赖 OpenAI**：工具名、参数和限额会变；4.5 在启动时校验并报带名字的阻塞。访客运行时能否用 apps、UW 账号能否连上（任务 0.7）是未知数，结论不利时访客/工作账号如实提示「读不到」，不阻塞其他阶段。
- **线程在 Next 生产构建里加载失败**：2.4 先探路，失败就走设计稿的退路（worker 进程求解、网页只读缓存），2.5 的缓存与哈希不受影响。
- **块 id 随重排漂移**：块 id 带段号，冻结项保留自己的 id、新段跳号（1.12）；仍可能出现锁定段与发布记录对不上的边角情况，由「本人改过的事件不再碰」兜底。
- **两个冻结块互相重叠**会让规划器的 `validBlocks` 判失败并回退简单排法；`locked_conflict` 只处理锁定块与硬约束的重叠，锁定块之间的重叠记入后续。
- **迁移 14 不可逆**：迁移前已有 `<db>.v13.bak` 强制备份（`#runMigrations` 现有行为），且旧行全部转成事件；恢复旧备份走 1.2 的转换。
- **Google 客户端审核**：`calendar.app.created` 若需审核，审核前上限 100 用户；桌面客户端的回调在私网域名下可能不可用（4.10 核实）。
- **视觉基线**：1.8（去掉差异提示）与 1.17（今日页摘要）会改截图；Windows 基线本地重录，Linux 基线需在云端会话重录。
- **通知叠加**：完成确认一块一问且绕过页面在前台的判断（电脑与手机都发），由 `notify.level` 的日上限与「连续忽略三次静音三天」统一封顶；夜间只计入早报。
- **7 天影子比对的等待**：阶段 4 的 4.8 起要等 4.7 跑满 7 天；这期间可以并行做 4.9–4.12 与阶段 5、6（它们不依赖读切换）。
