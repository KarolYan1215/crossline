# 其余页面设计草稿（2026-10-28）

今日页和全站外框正按参考稿重做（另一路）。本目录给出其余页面的静态草稿，外框与规范与参考稿一致：

- 背景 `#F6F4EF`，侧栏 `#EFECE6`，卡片 `#FCFBF8`，边框 `#E6E1D8`，墨色 `#1F2420`

## 1. 调研结论

资料以 2025–2026 年的官方帮助中心、文档和更新日志为主，链接都实际打开过。Meta Muse 没有公开的界面文档，相关内容只来自媒体报道。

| | Things 3：Area → Project 的轻层级，项目内用 Heading 分阶段（[Things](https://culturedcode.com/things/features/)） | 步骤分组不必另造层级 | 任务详情步骤按阶段分组（后续再做） |
| | Todoist：分开打算开始的 date 和有后果的 deadline（[Deadlines](https://www.todoist.com/help/todoist/features/introduction-to-deadlines-in-todoist-uMqbSLM6U)） | `notBefore` 与 `dueDate` 在界面上没有区分 | 截止用旗形图标，「排在」用日历图标 |

| | Akiflow Inbox：组头显示「N 项 · 约 X 分钟」（[Inbox](https://product.akiflow.com/en/help/articles/5284502-your-inbox)） | 先让人知道清空要多久 | 待确认页头「本周 7 项 · 预计 6 分钟」 |
| | Sunsama 规划代理：改动列成可逐项保留或丢弃的复核表（[Daily Planning](https://help.sunsama.com/docs/usage-guides/daily-planning/)） | 默认生效的事要能逐项撤销 | 右栏「最近自动生效」逐项撤销 |
| 设置 | Notion Calendar：每个账户一行，可单独设置或断开；视图类偏好直接在视图里改（[Settings](https://www.notion.com/help/notion-calendar-settings)） | 现在的设置页长 6,600px | 「连接一行」的统一排法 |
| | Reclaim Hours：按天勾选时段，「Copy to all」复制到所有日子（[Hours](https://help.reclaim.ai/en/articles/3600766-set-your-working-meeting-personal-custom-hours)） | 现在画时段网格要拖很多格 | 计划页「复制到工作日」 |
| | Linear 设置分段，侧栏不常用的项收起（[更新日志](https://linear.app/changelog/2024-12-18-personalized-sidebar)） | 模块要分组，并且能搜索 | 设置页搜索与状态总览 |
| AI 助手面板 | Reclaim Preview Mode：改动先暂存，按新增 / 移动 / 取消列出，逐项丢弃后再应用（[Reclaim 2.0 FAQ](https://help.reclaim.ai/en/articles/15280604-reclaim-2-0-faq)） | 与我们的 impact 预览和撤销可以统一成一套 | 所有「预览影响」共用一个前后对比层 |
| | Manus：运行中芯片（阶段 + 进度），自动化有运行记录和试运行（[Automations](https://manus.im/docs/automations.md)） | 助手在跑什么，现在只在设置里能看到 | 小帮手顶部芯片，可停止 |
| | Meta Muse：对外动作必经审批，权限按服务分读 / 写（[Fullstack 分析](https://www.fullstack.com/labs/resources/blog/inside-metas-muse-permissions-tools-and-personal-ai)） | 与「对外最后一步归本人」一致，界面要把这句话说清楚 | 步骤上的「对外 · 本人操作」标签；设置里每个连接标「只读」 |
| 引导访谈 / 画像 | Sunsama 引导只问三件事，剩下的配置变成看板上一张任务（[Setup](https://help.sunsama.com/docs/getting-started/setting-up-your-account/)） | 和「开始标准五项、其余随时补」一致 | 访谈右栏只显示开始标准；其余问题放在左栏「待答」 |
| | Reclaim：建议首周只设时段和 1 个目标（[FAQ](https://help.reclaim.ai/en/articles/15280604-reclaim-2-0-faq)） | 首周应少问 | 维持现规则 |

**不照搬的做法**
- Todoist Karma 的积分与逾期扣分：游戏化，并且会惩罚长周期主线正常的顺延。
- 单字母快捷键作为唯一入口：中文输入法下容易被吞。快捷键只作补充。
- Things 式极简：会丢掉时长、排程和日期轴。
- Motion 式黑箱重排：冻结块和变更摘要要保留。
- Amie 的社交层：对单人看板没有用，还有隐私成本。

## 2. 逐页批判（现状）

严重度：高 = 影响理解或操作；中 = 增加摩擦；低 = 观感。截图为桌面 1440×900 和手机 390×844。

## 3. 草稿说明

| 文件 | 要点 |
|---|---|
| [today.html](today.html) | 页头：大日期、时钟、周历条（每天一条负荷细条，有截止的日子带旗）。中间是日 / 周 / 月日历：变更摘要一行，下一项默认打开块弹层，弹层里有开始、完成、推迟、锁定、交给助手、打开任务。右列依次是今日精力、今日概览四格、「4 件需要处理」（本周紧急，行内一键）。底部是大输入框，飞轮图谱折叠起来。 |
| [milestones.html](milestones.html) | 页头放「本周刻度 / 跨主线复用」衬线大数字和三个操作。四张线卡写长期目标「成为 … 的 …」，附健康标签（估计）、里程碑进度和图标快捷键（访谈、重算、新建、候选）。草稿批准是一条虚线横幅。下方时间轴配「当前焦点」行，右侧抽屉常驻。风险的决定和候选关系只显示并给链接，主场分别在待确认和周复盘。 |
| [plan.html](plan.html) | 四个 KPI：本周可用、已排、未排进、估时偏差（偏差是摘要，链接到系统体检）。里程碑只留一行摘要，链接到主线。容量、「各线排程 vs 份额」、「排不下的原因」三卡同排，原因卡只能加时段，本周的推和砍去本周承诺。时段网格带分段工具、复制到工作日、精力建议。份额滑块和四个打包参数直接可见。 |
| [workbench.html](workbench.html) | 页顶是收集条。药丸页签做四问计数，旁边是主线筛选和视图切换。任务卡上有截止、首个动作、时段或计时、已备好；主按钮「开始」，其余操作是图标。「在等」改成行列表，任务库折叠。 |
| [task.html](task.html) | 面包屑后接上一项 / 下一项。页头四个数字（进度、截止、剩余、下一次）可就地编辑。左栏步骤，当前步展开首个动作、完成标准、刻度和 AI 辅助；右栏材料、教程目录、提交与完成。 |
| [approvals.html](approvals.html) | 三栏：左栏是四格计数、种类和快捷键，中栏一次答一张卡（数字键作答），右栏是助手成果、待验收、提议和最近自动生效（可撤销）。「全部按推荐」放页头，旁边先列出将处理的条数和种类。左栏另有一张「不在这里处理」：访谈问题、里程碑草稿、候选关系只给链接。 |
| [settings.html](settings.html) | 五张状态卡在上，左侧索引带计数，一次只看一个模块，页头有搜索。每个连接占一行：图标、名称、账号、状态、操作。 |
| [onboarding.html](onboarding.html) | 三栏不变。分段进度条不可点。开场折叠。问题选项做成药丸。右栏只保留开始标准，画像进度另放一卡。 |
| [portrait.html](portrait.html) | 左侧目录分「可分享 / 仅自己可见」两组，海报样式保留。操作集中到页头：分享为主，下载、形象、重画、重新生成用图标。画像确认（符合 / 大体符合 / 不符合）和外形描述的主场在本页。 |

**偏离给定规范的两处**
- 警示红 `#A3402A` 作为文字对卡片底只有约 6:1，达不到 ≥7:1。所以文字用加深的 `#8A321F`，`#A3402A` 只用于填充、描边和图形。
- Source Serif 4 与中文衬线不随草稿打包，在本机会回退到 Georgia 和宋体。实施时要像画像海报那样自托管子集字体。

## 4. 建议实施顺序

改动量按一位熟悉代码的开发者估算。「外框依赖」指今日页那一路要先交付的部分：侧栏导航、页头样式、卡片和按钮、标签、全局 tokens，以及底部输入条（`Conversation` 的停靠样式）。

| 顺序 | 页面 | 改动量 | 风险 | 依赖的外框部分 |
|---|---|---|---|---|
| 1 | 待确认 | 1.5–2 天：三栏布局；`AskCard` 选项改为整行单选并加数字键；页头计数合成一句；权限模式移到设置 | 中：键盘快捷键与中文输入法冲突（只在无焦点时生效）；e2e 选择器要更新 | 侧栏徽标（`usePendingView`）、卡片、按钮、标签 |
| 2 | 任务列表 + 详情 | 2–3 天：卡片补截止、首个动作、已备好，按钮图标化；详情双栏和页头 KPI；收集条 | 中：`TaskPanels` 被 Sheet 和 `/workbench/[id]` 共用，双栏要用容器查询，同时照顾弹窗；视觉基线重录 | 卡片、图标按钮、底部输入条 |
| 3 | 计划 | 1.5 天：KPI 行和未排进卡（读 `unplacedTaskIds`）；网格工具改分段控件，加「复制到工作日」；份额卡提出折叠 | 低：数据都已有；「复制到工作日」是新交互，要走 `impact` 预览 | 页头、KPI 样式 |
| 4 | 主线 | 2 天：线卡健康标签（读风险集合，标估计）；当前焦点行；抽屉宽屏常驻；草稿横幅 | 中：时间轴宽度变了，标签避让（`placeEdgeLabels`、`layoutAxisLabels`）要重测 | 卡片、标签；时间轴本身不依赖外框 |
| 5 | 设置 | 2 天：状态卡，一次一个模块（按锚点切换，不改路由），搜索，连接行组件 | 中：卡片多，`setup-guides.test.ts` 和 e2e 的锚点要保持 | 侧栏、页头搜索框 |
| 6 | 本周承诺 + 收工 | 各 0.5–1 天：容量条与理由，上周回顾；收工 KPI、三段按钮、明天预览 | 低：规则不变 | 页头、KPI |
| 7 | 小帮手 | 1 天：窄窗专用布局，运行中芯片 | 低：只改 `/helper` 一页；PiP 窗口尺寸要实测 | 输入条、形象组件 |
| 8 | 访谈 | 1 天：开场折叠、进度条不可点、右栏只留开始标准 | 中：访谈是新用户第一屏，要跑 `onboarding-eval` 之外的可用性走查 | 访谈不用全站外框（focus 模式），只用 tokens |
| 9 | 画像 | 0.5–1 天：页外框与目录、操作入页头；海报不动 | 低：分享导出只取前半，不受影响 | tokens、页头 |
| 10 | 登录 | 0.5 天 | 低 | 只用 tokens |
