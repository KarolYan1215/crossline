# 页面场景与功能主场（用户视角复审，2026-10-28）

本人看过草稿后的要求：

> 确认各个页面没有重复冗余的功能，每个页面都对应一个明确的场景。

本文分四部分：

- 每页一个场景，各页场景互不重叠；
- 「功能 × 页面」矩阵：每个功能只有一个主场；
- 对每条疑似重叠，核对代码后给出结论；
- 今日页实现需要改的点。

草稿和 README 已按本文修改。每份草稿页底的「逻辑修复」表新增了一列「主场在哪」，并写明该页的场景。

## 1. 每页一个场景

场景按「谁、什么时候、带着什么问题来、离开时完成了什么」写。下表里的「谁」都是本人，登录页除外。

| 页面 | 场景 |
|---|---|
| 今日 `/` | 每天开工和做事的间隙，想知道「此刻做什么、今天还剩什么、有什么必须马上定」；离开时开始了下一块，或处理了最急的几件事。 |
| 主线 `/milestones` | 想改方向或看全局时，想知道「每条线朝哪去、下一个里程碑还有多远」；离开时批准或改好了里程碑（日期、重要性、标准、草稿）或长期目标。 |
| 计划 `/plan` | 每周一次或改了作息之后，想知道「接下来几周时间够不够、各条线分到的够不够」；离开时改好了可用时段、精力或份额，或弄清了某项为什么排不下。 |
| 任务 `/workbench` | 要找某件事或看全部在办的事时，想知道「手上有哪些任务、各在什么状态」；离开时找到并打开了一个任务，或把收集里的条目变成了任务。 |
| 任务详情 `/workbench/[id]` | 开始做一件事或卡住时，想知道「这件事下一步做什么、材料在哪、做到什么程度算完」；离开时开始了计时、改了步骤或交付，或把它交给了助手。 |
| 待确认 `/approvals` | 每天一次，或收到「有事待决」时，想知道「哪些事在等本人拍板」；离开时清空了本周要定的决定（选项、助手成果、提议、验收）。 |
| 本周承诺 `/commit` | 周日晚或周一、这周排不下时，想定「这周保哪些、推哪些、不做哪些」；离开时确认了本周承诺（一次可撤销）。 |
| 收工 `/wrap` | 晚上最后一个时段结束时，想把「今天做了什么」记下来；离开时每个开始过的块都记成了完成、部分或没做。 |
| 周复盘 `/review` | 周末或周一早上，想知道「上周做成了什么、时间投到了哪、哪些长期判断要拍板」；离开时批准或否决了候选关系、调研结论和洞察提案。 |
| 设置 `/settings` | 接入新东西或某处不工作时，想知道「连了什么、哪里断了」；离开时连上或修好了一项连接，或开关了一项能力或权限。 |
| 访谈 `/onboarding` | 第一次使用（以及之后补充）时，想让系统「认识自己」；离开时说清了主线、长期目标、固定日程、可用时间和当前项目，达到开始标准。 |
| 画像 `/portrait` | 访谈写完后或想分享时，想知道「系统怎么看本人」；离开时确认了画像、改好了形象，或分享了前半部分。 |
| 小帮手 `/helper` | 不在 Crossline 页面里时（另一个窗口、托盘、快捷键），想顺手说一句或看一眼下一块；离开时记下了一句话、答了最急的一项，或完成了一次登录验证。 |
| 提醒铃铛（弹层） | 回到电脑前，想知道「系统刚才做了什么、发过哪些提醒」；离开时看过消息，并从中点进了相关页面。铃铛不做决定。 |
| 登录 `/login` | 受邀测试者或本人第一次来、或换了设备，想「进去」；离开时已登录或建好了账号。 |

**不是页面、但写在这里的两处**

`/confirm`（推送落地的单块确认）是「记录块结果」的入口，和收工用同一张表单：
- 只有任务明天或更早到期的块会单独推送（rituals.md §2）；
- 其余块晚上在收工里一起记。

计时浮窗是全站组件。主场记在任务详情，因为计时本身属于某个任务的某一步。

## 3. 疑似重叠逐条结论

核对的是工作树 `21ef61539f` 的代码。

1. **今日「N 件需要处理」与待确认**
   - 核实：今日 `dashboard-view.tsx:206` 和待确认 `approvals/page.tsx:110` 都渲染整副 `AskStack`/卡组，都能完整作答。确实重复。
   - 结论：待确认是主场。今日只列本周紧急的前 4 条，每行是主线标签、一句话、紧急旗，加上推荐的一键动作、「明天再问」「打开」三个按钮。其余项给一个链接「待确认共 N →」。
   - 全部按推荐：现在只在 `approvals/page.tsx` 和 `wrap/wrap-board.tsx`，保持不变，今日不放。今日的一键只针对单项；批量处理需要先列出条数和种类，属于待确认的场景。

2. **计划页的里程碑轴与主线时间轴**
   - 核实：计划页 `plan-view.tsx` 画了一条每线一行的里程碑轴，带状态色；主线页 `milestone-timeline.tsx` 是完整时间轴。重复。
   - 结论：里程碑轴只留在主线。计划页的状态色（按计划 / 有风险 / 待准备 / 任务库）并进主线时间轴的菱形外圈。计划页只留一行摘要：「7 个里程碑，1 个保守完成日晚于截止 →」。

3. **计划「未排进」与本周承诺**
   - 核实：计划页 `plan-view.tsx` 列出未排进的任务及原因；本周承诺 `commit-board.tsx:93` 只在预览里引用未排进的数量。今日的 `ReminderStrip` 链接到 `/plan#why`。
   - 结论：两者分工不同。计划回答「为什么排不下」，唯一的操作是加可用时段；本周承诺回答「这周保、推、砍哪些」。草稿里计划卡去掉了「推迟」，改成卡底链接「本周内排不下的去本周承诺」。

4. **本周承诺的「上周回顾」与周复盘**
   - 核实：`/review` 有「本周各线投入」（`loadWeekInvestment`）、自动验收、累不累等节；承诺草稿里的回顾只有一行。
   - 结论：周复盘是主场，承诺只保留一行摘要加链接。另外发现两处重复：
     - 计划页的「主线投入（计划 vs 实际）」与复盘的「本周各线投入」是同一份数据（`investment()`）。改为计划只看未来几周「排程 vs 份额」，回看部分交给复盘。
     - 复盘的「本月花钱」与主线线卡的领域记录重复。记录的主场在线卡，复盘只留摘要。
   - `/review` 目前只能从主线页进入（`milestones/page.tsx:63`），侧栏里没有。草稿已在「节奏与回顾」一组里加上。

5. **四处块确认：收工、今日块操作、`/confirm`、待确认「昨天没开始」**
   - 核实：
     - `wrap.ts` 调用 `confirmBlockAt` 记块结果；
     - `/confirm` 用 `confirm-form.tsx` 记单块；
     - 今日块面板 `complete-dialog.tsx` 完成的是任务，不是记块；
     - `missed_block` 是第二天的问卡。
   - 结论：按时间分界。
     - 白天在今日：开始、推迟、锁定这一块；块面板里的「完成」等同于完成任务，主场在任务详情，复用同一个完成组件。
     - 当时就要回答的（任务明天或更早到期）：`/confirm`，作为推送落地的入口。
     - 晚上：收工是主场。
     - 第二天的兜底：待确认和今日都只显示一张合卡「昨天 N 块没开始：都顺延 / 逐个处理」。「逐个处理」打开收工的「昨天」，收工需要支持日期参数。

6. **三个收件箱：铃铛、待确认、小帮手「需要本人操作」**
   - 核实：
     - `notice-bell.tsx` 是消息列表，带操作的提醒交给小帮手面板；
     - `helper-calls.tsx` 读 `lib/person-calls.ts`，内容是登录、授权、推送、站点验证；
     - 待确认是决定。
   - 结论：不合并，三者分界清楚。
     - 铃铛：已经发生的事，只看和跳转。
     - 待确认：要本人选择的事。
     - 小帮手：只有本人能在 app 外完成的动作的汇总，每项打开对应的设置卡或远程登录框；站点验证等急事在任意页面弹出。
   - 统一一点：任何一处都不复制另一处的条目。铃铛里的「有事待决」只链接到待确认，不在铃铛里作答。

7. **时段与精力**
   - 核实：
     - 计划页 `plan-controls.tsx` 是周时段与精力网格；
     - 设置→时间与提醒只有一行「在计划页设置 · 打开计划」（`settings/page.tsx`）；
     - 设置→精力 `energy-card.tsx` 是信号的同意与诊断。
   - 结论：不重复。今日的精力胶囊是「此刻」的读数与更正，计划页的网格是「每周的设定」，两者分开。

8. **访谈进度：访谈页右栏、设置·通用、待确认里的访谈问题**
   - 核实：
     - 设置·通用读 `interviewStatus`，显示状态并给「继续访谈」（`settings/page.tsx:51/70/161`）；
     - 开始标准之后，访谈问题作为 `interview_question` 进入待确认，可以直接作答（W-1xx：一张卡一次一题）。
   - 结论：访谈页是主场。设置只是摘要；待确认改为入口（左栏一行「访谈还有 N 题 → 继续访谈」），不在那里作答。这推翻了现在「待确认里逐题作答」的做法，理由是问题彼此有上下文，放在访谈里答得更准。

9. **小帮手 `/helper` 与今日输入框**
   - 核实：`helper-desk.tsx:206` 和 `dashboard-view.tsx:169` 都渲染同一个 `Conversation`，是同一段对话、同一套动作。没有两套功能。
   - 结论：
     - 小帮手是对话的主场，有当天完整记录、搜索、运行中的助手、需要本人操作的事项。
     - 各页输入框是页内入口：带当页上下文，只显示最近一次往返。
     - `/helper` 里的整块日面板缩成一条时间带。

10. **画像与访谈：画像确认、外形描述**
    - 核实：「符合 / 大体符合 / 不符合」（`PORTRAIT_UNCONFIRMED`）和外形（`gap-appearance`）都是访谈的补问（`packages/core/src/profile-gaps.ts`、`lib/asks.ts:832/877`）；画像页 `figure-picker.tsx` 只能选、上传、重画形象。
    - 结论：主场都移到画像页。
      - 画像确认：本人读完画像才能判断，所以确认放在画像里。
      - 外形描述：写在形象卡上，和重画放在一起。
      - 访谈只保留首次问一次外形，作为入口，答案写进同一个事实；对画像确认只给一行链接。

11. **交给 Agent、助手类别、助手成果**
    - 核实：
      - 任务的「交给 Agent」在 `task-actions.tsx`、`task-dialog.tsx`、`block-overview.tsx`；
      - 类别开关在 `settings/automation.tsx`；
      - 成果审阅在 `approvals/assistant-review.tsx`；
      - 产出下载在 `settings/outputs-card.tsx`；
      - 运行中的进度与停止在设置→后台任务。
    - 结论：
      - 单个任务的委派：任务详情是主场，卡片和块操作是入口；
      - 策略（类别、自动化、权限）：设置；
      - 待审阅的成果：待确认；
      - 已采纳的成果存档：设置·助手产出；
      - 运行中的进度与停止：小帮手是主场（借鉴 Manus 的运行中芯片），设置·后台任务只留按类别暂停，以及「N 项运行中」的摘要。

**另外发现的两处重叠**
- 里程碑抽屉里的「接受并提前排」与待确认的风险周报重复。主场在待确认，抽屉只显示风险说明并给链接。
- 里程碑抽屉里候选关系的批准与周复盘的「候选关系」重复。主场在周复盘，抽屉只显示关系。
