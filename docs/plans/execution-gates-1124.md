### 3. LLM 裁判的可靠性（调研，2026-11-24）

**实测过的偏差：**
- **迎合：** 让模型判断「某人说的对不对」，而不是自己作答，错误声明被接受的比例高 11.5–13.1 个百分点（arXiv 2511.10871，小模型）。用户暗示错误答案时，准确率最多降 27%；被问「你确定吗」时，GPT-4 改答案 32%（Sharma et al. 2023，arXiv 2310.13548）。
- **位置：** 交换两个答案的顺序，GPT-4 只有 65% 的判定不变（MT-Bench，arXiv 2306.05685）。
- **冗长：** 新模型基本免疫（CALM，arXiv 2410.02736，稳健率 0.88–0.98）。
- **权威与从众：** 伪造引用、声称「多数人认为」会显著改变判定（CALM，稳健率 0.56–0.70）。

**实测有效的对策：**
- 给参考答案或评分清单：GPT-4 数学题失败率 70% → 15%（MT-Bench，样本小）；清单分解提高与人的一致率（TICK、CheckEval）。
- 不同模型家族组成评审团，优于单个大模型（PoLL，arXiv 2404.18796）。
- 「不确定就转人工」：约 80% 覆盖率下保证 > 80% 与人一致（Trust or Escalate，arXiv 2407.18370）。

**没有实测证据的「民间做法」：** 「先写理由再给结论」（只改变分数，没证明更准）；「要求引用」；「给一个弃权选项」；「在提示词里提醒模型注意偏差」（CALM：检测率 46%–100% 不等，不可靠）。本设计照样用其中几条（引文逐字核对已有代码保证），但不把它们算作可靠性来源。

**对本设计的影响：**
1. **本人的自述不进判定输入。** 原则 3 要求「先看证据，再看自述」；调研显示看到自述就会被迎合。改为：判定模型只看证据，列出证据证明了什么；本人的「完成」声明由代码和判定结果比对。
2. **完成标准在任务创建时写好**（已有 `doneCriteria` / `evidenceContract`），判定逐条对照，等同参考答案。
3. **双跑：** 同一模型两次的一致不能当作正确（同一模型的错误会重复，arXiv 2609.32617 报告高置信错误上自洽检测接近随机）。不同模型家族更好。
4. **模型自报置信度偏高**（Xiong et al. 2024），不用来决定问不问本人。
5. **样本量：** 30 例全对，95% 置信下界只有 0.886。要证明精确率 ≥ 95%，单侧需 51 例 0 错，或 86 例 1 错。总一致率要同时报 κ：在「完成」占 80% 的样本上，一个永远说「完成」的裁判一致率也有 80%，κ = 0。

**J7 专项：** LLM 往 RTL 里埋的错，多数测试平台看不出来（VeriBugBench 平均可观测率约 36–40%）；RTLLM 的测试平台 72% 对变异的检出率低于 95%（GateTruth）。所以每道题必须用 iverilog 验证：原设计通过、变异能编译、变异使测试失败，并记下第一个出错的信号和周期作为答案。判分用仿真重跑，不用模型意见。

来源：见本节各处 arXiv 编号；Harkin et al. 2016（Psychological Bulletin 142(2)，进度监测 d = 0.40）。未核实项：部分论文只读了摘要或检索摘要（BugGen、VCDiag、TICK/CheckEval 的数值、跨模型分歧的几篇）。

## 四、J1–J7 详细设计

### 0. 共同的骨架

**一个判定 = 一次 Skill 运行 + 一条事件。** 复用 `runCodexSkill`（`packages/codex/src/skill-runner.ts:1330`）。每个判定的 Skill 放在 `skills/marketplace/plugins/crossline/skills/crossline-gate-<名>/SKILL.md`，提示词版本写在 Skill 的输入 `version` 字段（如 `crossline.gate.completion.v1`）。

**统一的输出外壳**（每个 J 在 `detail` 里放自己的字段）：

```
{
  verdict: <各 J 自己的枚举> | "cannot_judge",
  confidence: "high" | "medium" | "low",
  evidence: [{ kind: "event"|"file"|"mail"|"commit"|"activity"|"calendar", ref: <id 或路径>, quote: <原文片段>, at: <时间或时间段> }],
  reason: <一句话>,
  detail: {...}
}
```

- 没有证据就输出 `cannot_judge`，提示词写明不得默认通过。
- 置信度只记录，不用来决定问不问本人（调研 §二.3 第 4 条）。

**事件：** `gate.judged`（每次判定一条）：

```
payload: { gate: "J1".."J7", subject: {kind, id}, model, effort, promptVersion, inputDigest: <sha256 + 一行摘要>, output, run: 1|2, pairedWith?: <另一条 gate.judged 的 id> }
```

`gate.overridden`（本人推翻）：`{ judgedId, gate, from, to, note? }`，同时走 `learnFromUndo` 的偏好路径（`apps/web/lib/undo.ts:139`），模型下次看得到。

**防宽松（每个判定 Skill 的固定段落）：**
1. 输入里不放本人的自述（「我做完了」「我觉得这是噪声」）。本人的声明由流程在判定之后对照，不进模型。
2. 判定标准在任务创建时已写好（`doneCriteria`、`evidenceContract`），作为参考答案给模型逐条对照。
3. 提示词列出已知偏差：迎合、偏长、位置、权威与从众，要求逐条对照证据、引文出自证据原文。
4. **双跑：** P1 与对外任务的 J1、所有 J2，跑两次，第二次证据顺序倒过来。两次 `verdict` 不同 → 问本人（进待确认，选项是两个判定加「都不对」）。

**「不新增硬校验」的落实：**
- 新代码不写按业务规则判结果的代码。阈值（规划占比、成本 < 3 h 等）写成 Skill 里的「目标描述」。
- 不合格的输出靠循环处理：JSON schema 不符 → 退回重做（`runCodexSkill` 已有）；两次不一致 → 问本人。
- **已有校验的处理（第 4 轮第 2 条），待本人确认一处：** 本任务碰到的路径上（`validateDeliverableCheck` 等），按业务规则下结论的代码去掉，只留 JSON schema。唯一建议暂留的是「引文必须出自证据原文」这一条：它是 J1 防编造证据的唯一一道，去掉后一个编出来的引文就能关掉任务。建议用评测数据决定：J1 评测集分别在「有 / 无引文核对」下各跑一遍，错判完成数没有差别就去掉。仓库其他 Skill 的已有校验不在本任务里动（54 个 Skill，另开任务）。

**隐私（设备端，确定性，第 2、4 轮）：**
- 授权文件夹加「仅本地」开关（设置 `sourceFolders[].localOnly`）。标了的：文件内容不上传，只传文件名打码后的「[仅本地] + 扩展名」、修改时间、大小。
- PDK 关键词表（设置 `privacy.pdkTerms`，默认含工艺库与版图文件扩展名：`.lib .lef .def .gds .oas .spi .scs .cdl .tf .itf .tluplus`，以及本人加的工艺名）。命中的文件不读，命中的窗口标题打码。
- 已发送邮件的正文片段只进判定输入，不存账本（`gate.judged` 只存邮件 id 与主题）。

**问不问本人（§7.1）：** 每个判定的 Skill 同时输出 `ifWrong {harm, fixable}`（沿用 7.1 的字段）。`harm` 为 `external` 或 `deadline`、或双跑不一致 → 进待确认；其余只记录，周复盘可见、可推翻。

### 通用化（11-25，评审 35 条之后）

- **一张表定关口：** `GATE_SPEC`（编号、名字、结论集、哪些主体判两次、能不能问本人、哪些结论一定问）。`GATE_IDS` / `GATE_VERDICTS` / schema / `gateNeedsPerson` / web 的 `gate_check` 都从它派生，原先散在 web 和 worker 里的特例（`ASKED_GATES`、J2b 特判、单独的结论字面量）删了。
- **到期靠账本，不靠「上次跑」设置：** 每个关口给出候选，`pendingGateSubjects` 按 `gate.judged`（已判）和 `gate.attempted`（失败次数）算还剩哪些。一次调用没有回答就抛 `GateRunFailed`，不把这一轮记成已完成；同一主体当天失败 3 次就停到第二天。第二次运行没回答不算分歧。
- **共用上下文：** `gates/context.ts` 放资源上限 `GATE_LIMITS`（只管一次调用装多少、多久超时，不决定结论）、本人时区的日和周（不知道时区时用 UTC 并写明，不再默认 Chicago；深夜关口不知道时区时按深夜处理）、目标原文、待判列表。
- **批量：** 准入、挫折一次调用判一批；判两次时只把需要判两次的主体倒序再送一遍。准入不再由代码算「完成比例」，每个任务带 `progress` 由模型自己读；挫折不再由代码挑「相似尝试」，给全部记录的结果让模型找基准率。
- **撤销停放：** 本人撤销停放（里程碑重新批准）后 `reconcileParked` 写 `milestone.unparked`，不会被准入关口再次停放后又被撤销循环。
- **注意力：** 推翻也算进周复盘；没有本周审计时不再拿别的周顶上；计时块和提交各自有上限。
- **其他：** 隐私规则只有一个读取口（`privacyRules` / `privacyOf`），深夜计数 `nightCounts`、练习的事件与类型都在 core，web 与 worker 共用；`gatesPass` 不阻塞 tick；夜间报名表的判定 3 分钟超时，超时就停下等早上。
- **评测脚本：** `CLASSES` 来自 `GATE_SPEC.completion.verdicts`，导出时证据只截到判定那一刻（`completionEvidence` 的 `until`），批大小用 `GATE_LIMITS.tasksPerCall`。
