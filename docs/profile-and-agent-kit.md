# 用户画像模块与 agent 工具包（设计 2026-10-31；P1 已实现，见第十一节）

起因：机主希望访谈能单独拆出来，出一份所有 agent 都能导入的、关于本人的全量报告（人格、性格、理想、职业偏好、工作习惯、生活方式），保留形象构建；Crossline 自己的主线与精力设置往后放，具体任务和时间作为最后的可选模块；另可附近期里程碑和主线间的相互促进关系。随后又把导出扩大为整个系统的信息出口：用户在 Codex、Claude Code 等其他 agent 里也能读到自己的日程、画像和其他内容，并在规则内写回。

本文是 2026-10-31 调研（人格与精神分析、职业与生活方式、开源库与导出格式三份）和五轮问答的结论，按「分期」实现；P1 的实现与偏离设计之处记在第十一节。

## 二、调研结论：采用、改造、不采用

原则：改写题目会让常模和信度失效，许多量表的许可证也禁止修改，所以分两层。

- **A 层（卡片，可计分）**：许可证允许改写和商用的题目原样或近原样呈现。
- **B 层（编码框架，不出分）**：把构念当分类框架，模型从本人的话里找证据、引用原话，只给带证据的定性结论。

模型从访谈推断人格与量表分数的相关只有 r≈0.27–0.58（多项 2023–2025 研究），所以每条结论标来源类型，并由本人确认。

### 采用

| 工具 | 层 | 许可 | 用法 |
|---|---|---|---|
| Mini-IPIP（Donnellan 等 2006，20 题） | A | IPIP 公有领域，可改写、商用 | 人格五维，每维 4 题 |
| RIASEC Markers（Armstrong, Allison & Rounds 2008） | A | 论文称公有领域，**上线前核原文** | 每类取 2 题共 12 题，只报告相对高低，不给类型 |
| SWLS 生活满意度（Diener 1985，5 题） | A | 公有领域 | 生活方式一节 |
| Schwartz 十项价值 | B | 框架公开；PVQ-RR 原题 CC BY-NC-ND，不用 | 自写 5–6 张二选一卡片覆盖十项 + 叙事 |
| SDT 三需求（自主、胜任、联结） | B | 框架公开；BPNSFS 商用需许可，不用原题 | 按主线判断每项需求的满足与受挫 |
| McAdams 人生叙事（高峰、低谷、转折、未来剧本） | B | 访谈提纲，非量表 | 叙事身份，只写主题 |
| Savickas 生涯建构访谈 CCI（榜样、喜欢的节目、最爱的故事、座右铭、早期记忆） | B | 访谈提纲 | 生涯主题句，整个报告的锚 |
| O\*NET 六项工作价值（成就、工作条件、认可、关系、支持、独立） | B | 内容模型公开；WIP 已退役 | 编码框架 |
| Schein 职业锚的取舍式追问 | B | 只借问法 | 「被迫放弃时最不肯让出什么」 |
| 国家统计局 2018 时间利用调查大类 | — | 公开 | 生活方式的时间账本，可对比全国数据 |
| Greenhaus & Powell 2006 增益五类资源（技能与视角、心理与身体、社会资本、灵活性、物质） | B | 理论 | 跨线增益的分类依据 |
| Dell'Acqua 等的人机协作模式（Centaur / Cyborg / Self-Automator） | B | 研究 | AI 协作方式，依据 agent 使用记录而非自评 |

### 改用行为数据

时型（睡眠和活动记录，已有 `mctqLite`；rMEQ 不发题）、精力曲线、拖延（错过的块、顺延次数）、倦怠（错过与顺延的走势、睡眠债、本人的话）、运动（手机步数）。这些都比自评可靠，且已在记录。

### 不采用

- 类型学：MBTI、九型人格、DISC、16personalities 式职业匹配。
- 收费或禁止商用：Strong、Holland SDS、CliftonStrengths、HEXACO、VIA、BFI-2、MBI、PSQI、WHO-5（CC BY-NC-SA）、PERMA-Profiler（非商用）。
- 禁止修改：BAT-12（决定 3）、O\*NET 工具原样分发版（CC BY-ND）。
- 临床：OPD-2、STIPO、SWAP-200、DSQ-40 防御机制。
- 效度弱：IPAQ-SF（平均高估活动量 84%）、Ikigai 四圈图（Winn 2014 套用，非日语原意）。
- 措辞：不说「找到你的热情」，说「发展兴趣」（O'Keefe, Dweck & Walton 2018）。

## 三、卡片与文字折算

卡片是对话里的一张小卡：一道题、五个圆点（两端和中间有字）、一个输入框。本人可以点圆点，也可以写一句话，或者什么都不做跳过。

- 写下的话同时是访谈的证据句，抽取层照常引用。
- 文字由模型折算到 1–5，记 `confidence`，来源记为 `inferred`；点选记为 `self_reported`。
- 某一维度的分数注明「N 题点选、M 题由文字折算」，记 `administration: "mixed"`。
- 一个维度里折算题超过一半，或有题跳过，该维度不出分数，只出 B 层的定性结论。
- 画像页可展开看每题怎么记的，本人可改；访谈中不显示、不打断。
- 分数只用于报告本人的相对倾向，不与常模比，不出百分位。

卡片随话题出现（谈工作方式时出尽责性的题，谈和人相处时出宜人性的题），每轮至多 2 张，算在一轮的问题数里。

## 四、模块与顺序

1. **同意与范围**（约 1 分钟）：画像是什么、用在哪、导出给谁、敏感类别默认不收；单独同意（PIPL 把心理画像视为敏感个人信息）。
2. **画像模块**（约 20 分钟，可单独使用）
   - 叙事开场：CCI 五问，再到 McAdams 的高峰、低谷、转折和未来剧本。
   - 工作与学习：RIASEC 卡片、O\*NET 六项价值、取舍追问、工作方式（专注条件、心流、拖延、AI 协作）。
   - 价值与动机：二选一取舍卡、SDT 三需求。
   - 生活方式：时间怎么花、怎么充电、SWLS、外貌（形象用）。
   - Mini-IPIP 20 题穿插在以上各段。
   - 结束时写出报告草稿，本人逐节确认。
3. **Crossline 适配**：主线、份额、长期目标、精力、跨线增益（现有 orientation、lines 的内容）。
4. **可选：系统接轨**：具体项目、截止、每周时段、日历、文件（现有开始标准的其余部分）。
5. **可选附录**：近期重要里程碑与主线间的相互促进关系（来自架构师和产物计划）。

**时长（2026-10-31 机主定）**：照此执行。画像模块不可跳过，开始使用前约 50 分钟（画像约 20 分钟 + 现有约 30 分钟）。考虑过但没选的两个方案：画像可「以后再说」、由小帮手在使用中分几天问完；开始标准只要第 3 部分的最少项，第 4 部分用上之后补。访谈评测（`scripts/onboarding-eval.ts`）的时间目标相应改为：开始标准 ≤ 50 分钟。

## 五、报告结构

导出包与画像页同一结构，按此顺序：

0. **和此人协作的说明**：沟通偏好、要多少细节、做决定的方式、反感什么、什么事先问再做。每条有依据，由本人确认；这是 `AGENTS-snippet.md` 的主体。
1. **总览**：一句话画像、形象图、16 型（趣味层，注明不是标准化测验）。
2. **人格**：五维，每维写分数（若有）、在日常里表现为什么、依据。
3. **价值与取舍**：十项排序、最不肯让出的东西。原「指南针」并入此处。
4. **动机**：三需求在每条主线上的满足与受挫。
5. **生涯叙事**：主题句、榜样、座右铭、转折点。原「指南针」的叙事部分并入此处。
6. **职业兴趣**：六类相对高低和行为印证。
7. **工作方式**：时型、专注与心流条件、拖延模式、AI 协作模式（含 Self-Automator 风险标记）。原「精力」的工作部分并入此处。
8. **生活方式**：时间账本、充电方式、生活满意度、近来的状态。原「精力」的生活部分并入此处。
9. **张力与成长**（仅本人）：真问题、核心矛盾、言行落差与锚。
10. **Crossline 适配**：主线与份额、长期目标、精力模型、跨线增益。原「建议」移到这里。
11. **可选：系统接轨**、**可选：里程碑附录**。

## 六、结论条目（claim）

报告由条目组成，每条：

```
id, section, statement,
kind: self_reported | inferred | measured | observed,
confidence: 0–1,
basis: [{ sentenceId, quote } | { instrument, items, administration } | { behaviour, window }],
personStatus: unconfirmed | confirmed | corrected | rejected,
validFrom, reviewBy,
sensitivity: normal | sensitive,
shareLevel: public | agent | private,
version
```

- `measured` 只给全部点选作答的维度；有折算题的记 `inferred`。
- 被本人否定的条目保留为 `rejected`，不导出，下次不再写出同样的话。
- 行为得出的条目是 `observed`，写明窗口（如「近 28 天」）。

## 七、隐私、更新与导出

**三级**：`public`（分享卡上有的）、`agent`（默认）、`private`（第 9 节、健康与财务类、近来的状态）。本人可逐节、逐条改。法定敏感类别（健康细节、性取向、宗教、政治、精确财务、第三方个人信息、原始转写与音频、声纹、摄像头）不进报告。

**持续更新**：使用中观察到的行为以 `observed` 条目加入；会改变本人说过的结论时先问再改；每条带 `reviewBy`，到期在每周回顾里问一次。每次变化升版本号，导出包带 `CHANGELOG.md`。

**下载包**（画像页一键下载）：

- `manifest.json`：版本、生成时间、包含的节、schema 版本
- `AGENTS-snippet.md`：协作说明，可直接贴进 AGENTS.md / CLAUDE.md
- `PROFILE.md`：YAML front matter + 正文，证据以 `[c12]` 引用
- `profile.json`：全部 `agent` 级条目，配 JSON Schema 2020-12
- `digest.txt`：≤1500 字摘要，给上下文紧的 agent
- `avatar.png` + `avatar.json`：形象图，标注 AI 生成
- `CHANGELOG.md`

不含量表原题与原始得分（许可证不延伸到第三方 agent）。

**用途限制**：报告注明不得用于招聘、录取或教育评估（EU AI Act 的高风险用途），并注明「基于访谈和使用记录的推断」。

## 八、MCP 与 agent 工具包

### 服务

托管站与安装版各开一个 MCP 端点（Streamable HTTP），数据始终从 Crossline 服务端读，插件里没有业务代码。

- **授权**：沿用设备令牌，新增作用域 `agent`。每个连接有名字（如「Claude Code · 笔记本」），在 设置 → 通用 「已连接的 agent」 列出最后使用时间、本周动作数、门槛与撤销按钮。令牌由插件存在系统钥匙串里。
- **只读资源**：`profile://summary`、`profile://section/{name}`、`profile://claim/{id}`、`schedule://next7d`、`tasks://open`、`milestones://approved`、`lines://relations`、`records://recent`、`materials://recent`。
- **工具**：读取同上；写入见下。
- **提示**：`work-with-me`（协作说明 + 今日要点）。
- **防注入**：凡是第三方写的文字（邮件开头、录音摘要、文件摘要、网页）都包在 `{source, untrusted: true}` 里返回，skill 说明这些是数据不是指令。

### 写入：三档门槛

外部 agent 的每个动作都只能是动作注册表（`packages/core/src/concierge.ts` 的 `ACTIONS`）里的一个，用同一套参数 schema、执行前检查和 `withUndo`；不能直接写库。

| 档 | 动作 |
|---|---|
| 自动生效，可撤销 | 记一下（进收集箱，照常分析）、加备注、报告用时、标记由该 agent 交付的步骤完成 |
| 进待确认 | 改截止日、推迟、改估时、新建或合并任务、改里程碑、更正画像条目 |
| 禁止 | 删除、批准里程碑、任何对外动作（发送、发布、付款、上传）、改设置与授权 |

规则：

- **乐观并发**：修改带对象当前版本，版本已变则退回 `PROPOSAL_VERSION_CHANGED`；每个请求带幂等键。
- **留痕**：动作写入账本，`actor = agent:<connectionId>`；待确认卡写「来自 Claude Code（笔记本）」；撤销 24 小时内可用。
- **不算本人操作**：外部动作不更新 `lastPersonActivity`，不关闭等待项，不改变花费分级。
- **防注入**：外部写入的文字进入 Crossline 自己的模型时一律当数据。
- **限速**：每个连接每小时动作上限（默认 60），超出退回并提示。
- **信任升级**：同一连接的同一种待确认动作，连续 5 次被批准且没有被撤销后，提议改为自动；本人点头才生效；一次撤销或驳回即退回待确认。
- **交付物**：外部 agent 交来的文件附在对应任务上，当作助手产出，走同样的检查与待确认；用作里程碑证据仍过验收闸门。

### 公开仓库

独立公开仓库（暂名 `crossline-agent-kit`，MIT），同时是 Claude Code 和 Codex 的插件市场：

- `skills/crossline/SKILL.md`：何时读日程、画像，怎样写回，三档规则，不可信内容的处理
- MCP 配置（托管站与安装版两种地址）与登录说明（设备码配对，令牌进钥匙串）
- `schema/profile.schema.json` 与示例导出包（虚构人物）

## 十一、P1 实现记录（2026-10-31）

**偏离设计之处**

- 兴趣题用 18REST（CC BY 4.0，每型取 3 题中的 2 题，共 12 题），不用 RIASEC Markers：后者的商用条款查不到原文。
- 所有中文题面是我们自己的翻译，未经回译。上线前要对照台湾 IPIP-50 与 Zheng 等 2008 回译核对。
- SWLS 原为 7 点，这里用 5 点问，分数不能与已发表常模比较。
- 取舍卡是自编的施瓦茨十价值两两对比，未用 PVQ 原题（PVQ 为 CC BY-NC-ND）。
- 卡片只在中文访谈里出：题面只有中文，英文界面不出卡片。

**代码位置**

- 题库与计分：`packages/core/src/profile-instruments.ts`，共 43 题：Mini-IPIP 20、18REST 12、SWLS 5、取舍卡 6。
  - `cardsFor` 按阶段分组出卡。
  - `scaleAnswerLine` 与 `readCardAnswers` 写出、读回点选行，不经模型。2 和 4 也写明偏向哪一端（`点选：4/5（偏向「遵从」）`）：2026-10-31 的走查里只有「4/5」，模型把取舍卡读反，画像与卡片结论相反。
  - 文字折算由抽取层写入，记 `by: "mapped"`，带 `confidence` 和证据句号。
- 流程 v2：叙事 → 指南针 → 能量 → 处境 → 定向 → 主线 → 细节，只对新的主访谈生效（`coverage.flow = "v2"`）；已有一轮的会话保持原流程。卡片由 `onboarding-session.ts` 插进助手消息的 `content.cards`。
- 结论条目：`packages/core/src/profile-claims.ts`。
  - 卡片结论由 `instrumentClaims` 现算。全部点选为 `measured`，有文字折算为 `inferred`；有题未答的维度不出结论。
  - 画像撰写人写的结论在 `PortraitReport.claims`（画像 schema 6，所有账号的报告因此各重写一次）。原话必须在本人回复里逐字出现，否则丢弃（`resolveWrittenClaims`），结果存 `profile.claims`。
  - 本人判「不符合」的条目存 `profile.claimStatus`：在本人页面上保留，不导出，下次撰写时作为 `rejectedClaims` 告诉模型不再写。
- 隐私：`REPORT_PRIVACY_SETTING` 按节设三级，「张力」节默认 `private`；`exportableClaims` 只放出 `agent` 及以上且未被否定的条目。
- 画像页：`apps/web/app/portrait/profile-sections.tsx`（「04 逐条核对」），接口 `/api/profile/report`。
  - 每节可设谁能看到，每条可判符合/不符合。
  - 「卡片作答」可重答每题或跳过。

**评测**

`scripts/persona-eval.ts`：设计虚构人物的内核，写成第一人称的生活与感受（`scripts/personas/eval-2026-10-31/`），由 `crossline-eval-persona`（v2：作答卡片、对洞察说准/不准）只凭生活与感受作答。访谈、抽取、画像撰写和模拟用户都走开发者模型，各人用各自的一次性账本。内核文件不进仓库，只交给评判。服务器上是 `server.yml` 的 `persona` / `persona-report` 动作。
