# 三条发行分支（草案，2026-11-04）

本人 2026-11-04 定下三条分支，代码同仓。下面每节写明已定的部分和待定的部分。

| 分支 | 谁跑模型 | 账本在哪 | 给谁 | 详细设计 |
|---|---|---|---|---|
| **插件版**（skills） | 用户自己的宿主 agent（Claude Code / Codex），用户自己的额度 | 本机 | 用 agent 的人 | `docs/agent-host-plugins.md` |
| **本地版**（Windows 安装包） | 开发者的 token（开发者模型），按用量付费 | 本机 | 不用 agent 也想要全功能的人；可与其他 agent 协同 | 本文 §2 |
| **网页版**（托管） | 开发者的 token | 托管服务器 | 访谈出报告（付费）；本人自用；其他人付费后可全功能使用 | `docs/hosted-shrink.md` |

## 1. 已定

- 报告**只**在网页访谈里出。插件版和本地版都不带画像报告。画像 prompt、类型表、32 张模板、海报渲染只放服务端。
- 收费：私域收款 + 小红书商城 + 兑换码。
- 报告买家：可以导出带走，托管侧 90 天后删除访谈原文。
- 插件版的后台工作，由宿主的定时任务跑 skills：Claude Desktop 定时任务、Codex automations。不拿用户的订阅替我们的进程调用模型。
- 本人主账本留在托管。内存不够就搬回本机。

  说明：账本文件只占磁盘，但要用它，就得让 web、worker、Codex 运行时、求解器、浏览器这些进程常驻，它们占的是内存。所以“停掉 owner 栈”等于本人的账户停用，不是省下一块存储。

## 2. 本地版走开发者 token：必须解决的问题

1. **密钥不能进安装包。** 装进去的密钥迟早会被提取、被滥用。本地版的模型请求要走开发者的托管网关：今天 worker 内部的模型网关（`model-gateway.ts`）对外开一个入口，按用户账户计量，用户端只持有自己的设备 token。
2. **计量和额度。**
   - 每个用户一份余额，兑换码就是充值。
   - 网关按 `tokenYuan`（已有）扣费，用完即停，并按 `MODEL_SPONSOR_BUDGET` 的写法明确告诉用户。
   - 现有每月 ¥30 的上限（`CROSSLINE_SPONSOR_MONTHLY_CNY`）改成按余额。
3. **本地版需要联网登录托管账户**，否则无法计量。这和“本地优先”有冲突：没有网络时，模型相关的功能全部停，排程、提醒、日历这类不依赖模型的照常运行（`degradedService` 已有这层划分）。
4. **合规。** 开发者向用户提供模型服务，本地版也算面向公众的生成式 AI 服务：要登记、展示所用模型的备案号、给生成内容加标识。小红书商城上架 AI 类虚拟服务的规则需要查商家后台。拼多多 2026 年已经禁卖若干 AI 服务（[中国日报](https://cn.chinadaily.com.cn/a/202605/28/WS6a1820d5a310942cc49aedd0.html)），小红书的规则未查到。
5. **与其他 agent 协同。** 本地版开 `/mcp` 端点（设计见 `agent-host-plugins.md` §3.1），让用户的 Claude Code、Codex 调用看板。

## 3. 网页版对其他人开放全功能（付费）

这一条推翻了 11-04 早些时候“托管只做访谈、报告和自用”的说法，改成：报告人人可买；全功能是另一档付费。

影响：

- 托管上的访客运行时可以不要了：付费全功能用户也走开发者模型。
- 邀请码流程改成兑换码，兑换内容分两档：报告、全功能时长或额度。
- 访客能用的功能沿用今天对“托管”的限制：没有本机文件夹、屏幕、shell 助手。
- 内存随付费人数增长。模型门的多租户公平（`model-gate.ts`）继续保留。
