# 界面文案与审查标准

界面文案、模型提示词（runner 指令与 SKILL.md）都以本文为准。代码层面的领域词汇见根目录 `GLOSSARY.md`。

## 固定词汇

| 用词 | 含义 | 不用 |
|---|---|---|
| 主线 | 研究、创业、自媒体、投资等长期方向；健康是容量约束，不是主线 | 身份、线、条线 |
| 长期目标 | 一条主线的长期目标 | 目标（单用） |
| 里程碑 | 有日期、可检验的事件（考试成绩、提交、对方回复） | 目标 |
| 分数线 | 里程碑或课程要达到的分数要求 | 分数目标、目标分 |
| 任务 | 唯一可执行的单位（代码中 WorkOrder） | 作业、工作单、方案、提案、事项 |
| 步骤 | 任务内部的一步，单独排进时段，占任务进度的一部分 | 子任务 |
| 原型 | 任务的结构类型（写作产出、考试复习……） | 模板（指任务时） |
| 刻度 | 时间轴上一个里程碑之前的近端结果 | 节点、积分 |
| 飞轮关系 | 一条主线的产出被另一条主线复用 | 联系、关系（单用） |
| 收集 | 尚未分析的输入 | 待办 |
| 草稿 | 尚未批准的里程碑或步骤图 | 草案 |
| 批准 | 让计划、提案、草稿生效 | 采纳、接受、同意、点头、过目、确认（作批准义时） |
| 验收 | 依据证据判定任务是否交付 | 审阅通过 |
| 撤销 | 取消一项已生效的决定 | 退回（作撤销义时） |
| 归档 | 带原因撤下一个任务，留在账本 | 删除 |
| 待决事项 | 需要人决定才能继续的事 | 需要你一句话 |
| 待审阅 | 等人查看的助手产出 | 等你过目 |
| 当日到期 | 当天截止或当天必须处理 | 当天会误事 |

「作业」只作为课程内容本身的名称出现（文件里写的「Homework 2」），不作系统对象名。

## 风格

- 第三人称、客观。不用「你」「我」，不用对话腔（「说说」「就行」「要不要」「替你」）。
- 名词短语 + 数据：「3 项待决 · 最早 10/09」，不写「有 3 件事等你决定」。
- 标准学术与工作用语，不自造黑话。
- 标签（风险、状态、类型）用 `Tag` 组件，不写进括号与正文混排。
- 确定性数据（账本统计）用等宽数字和图表；模型生成的文字放在 `.gen` 内，以微软雅黑与系统文字（Arial + 等线）区分，不标「AI」。
- 画像海报是唯一例外（2026-10-12）：代码里写死的标题（类型码、16 个类型名、组名、施瓦茨 10 项、章节与标签栏标题）放在 `.pt-serif` 内，用自托管的 Noto Serif SC 子集；模型写的文字和本人的主线名不用它。
- 不出现开发内容：代码、错误码、路径、环境变量、内部 id、英文状态词。失败信息写成「原因 + 下一步」。

## 材料与教程版式

材料与教程一律在页面内画成 HTML，不把文件原样交给浏览器（2026-10-15）。组件在 `apps/web/app/materials/`：`MaterialViewer`（一份材料）、`TutorialView`（任务的教程）、`AssistantMaterials`（助手的产出）。

**呈现方式**

- Markdown：用 `app/ui/markdown.tsx` 画出标题、列表、表格、引用；任何 HTML 都按文字显示。
- Word、PDF：先显示抽取出的文字，并恢复结构（标题、列表、表格、按列对齐的版面）。Word 由 mammoth 转换后读成结构化区块，绝不注入 HTML。PDF 另有「原版式」一栏。每份材料都给出「下载原文件」，PDF 和图片还给出「新窗口打开」。
- CSV：画成表格。图片：直接显示。
- 代码、配置、缓存、README 不进入任何材料列表（`isTooling`）。
- 从任务卡等处直接打开文件链接时，若是 Markdown、文本、Word 或表格，文件路由会把浏览器转到材料页 `/materials/view`。

**本人上传的文件**

- 左侧内嵌预览，右侧给出解析摘要，内容包括：
  - 这份文件是什么：类型、字数、包含的章节；
  - 和哪些步骤有关：教程对它的说明按步骤列出，同一句说明只出现一次；步骤的内容单元若取自这份文件，也列出该步骤。
- 每个步骤都能链接回任务。

**教程**

- 一个步骤一节，按任务步骤的顺序排列，节号即步骤序号。
- 双向跳转：
  - 教程每节的锚点是 `tutorial-<stepId>`，任务的步骤行是 `step-<stepId>`（`tutorialAnchor` / `stepAnchor`）。
  - 每节有「回到步骤」，步骤行有「本步的教程与材料」。
- 每节依次是：
  1. 标题行：节号方块、标题、类型标签。
  2. 关键结论框：「目的」「完成标准」，黑框浅底。
  3. 「需要补充」：虚线框，从正文中提出来单独放。
  4. 正文（编号步骤）。
  5. 本步材料。
  6. 「资料解析」：折叠放在节末，属于高级内容。
- 来源脚注：
  - 全书统一编号，同一来源无论被几节引用，只编一个号。
  - 正文里写作上标数字。
  - 书末的「来源」列表注明每个来源被哪几步引用，并链接到解析。
- 阅读进度：顶部一条进度条加「第 n / N 步」，随滚动更新。独立阅读页（`/materials/<任务 id>`）在宽屏时左侧有目录。

**精简与完整**

- 同一来源只引用一次。
- 相邻或已出现过的段落合并为一处。
- 资料解析不重复正文。
- 各节之间不重叠，合起来覆盖全部步骤和必需的合同项。writer 和 designer 两个 Skill 都写明了这一要求。

**助手的产出按用途画出，不罗列文件名**

| 用途 | 画法 |
|---|---|
| 材料目录 | 树状列表（标题为枝，条目为叶） |
| 文件台账 | 表格 |
| 缺口清单、核对清单 | 勾选表，带已有项的计数条 |
| 流程、步骤 | 箭头相连的步骤示意 |
| 其他 | 文档提纲 |

分组规则沿用 `approvals/assistant-outputs.ts`。

**助手产出给人看，不给机器看**（2026-10-15，`app/materials/humanize.ts`）

- 不显示本机绝对路径、哈希（16 位以上十六进制）、字节数、扩展名，也不显示 `source_id`、`candidate_category` 这类内部列和 S01、P0 这类内部编码。
- 文件以原始文件名或标题显示：按哈希在本人上传的文件里找回名字；找不到写「来源 1」。
- 表格最多 4 列，只留人能读懂的列，英文表头换成中文；只记录文件名和能否读取的表格改成一句摘要（「两份文件均可读取：…」）。
- 缺口清单每条是短标题、状态标签（可访问 / 缺 / 待核验）和一句说明。清单和表格默认显示前 4 项，其余点「显示全部」。

**任务详情里的教程只放目录**（2026-10-15）：每步一行（节号、标题、一句目的、本步材料数），点开在页内展开这一节，当前步骤那一节默认展开；全文在阅读页 `/materials/<任务 id>`。

**公式**：Markdown 中的 `$…$` 与 `$$…$$` 用 KaTeX 排版（本地打包的样式和字体，`trust:false`、`strict`），读不出的公式按原文显示。公式内用 KaTeX 的数学字体，设计审查对 `.katex` 豁免字体与字号规则。

**排版**

- 系统文字用 Arial，模型写的文字放在 `.gen` 内；用户自己的文件不加 `.gen`。
- 正文 14px、行高 1.7、每行不超过约 46 字。次要文字 13px，任何文字不小于 12px。
- 颜色只用 ink 和 graphite，对比度 ≥7:1。
- 表格和按列对齐的版面在自己的框内横向滚动，手机上页面本身不出现横向滚动。
- 正文段落统一放在 `.long-form` 内（文案审查对它放宽段落长度）。

## 审查标准（每阶段走查）

**A. 摩擦与可用（全部通过）**
1. 常用操作 ≤2 次点击，无死按钮。
2. 每个操作有可见反馈；慢操作显示进度或排队状态。
3. 无开发痕迹：占位文字、代码、路径、env、id、英文错误码、算了却不展示的功能。
4. 背景资料、材料、引用均可点击打开或跳转。
5. 系统能自动做的不让人做（交给 Agent / 默认生效可撤销）；校验不打断主流程。

**B. 阅读负担（个别例外须记录理由）**
6. 默认视图以模块和图表为主，>3 行段落只在材料与教程正文（`.long-form`）。
7. 折叠面板只用于高级或低频内容（`details.advanced`）。
8. 数值都有可视化，悬停显示精确值。

**C. 语言**
9. 第三人称客观，术语与上表一致。
10. 生成文字与系统文字字体区分。

**D. 视觉与适配**
11. 主线配色全站一致；标签与正文层级可区分。
12. 手机可用；对比度 ≥7:1、字号 ≥12px。

自动化：`e2e/design-audit.spec.ts`（12、10 的字体部分）与 `e2e/copy-audit.spec.ts`（3 部分、6、7、9；任何发现即失败，`COPY_AUDIT_REPORT=1` 时只打印）。
