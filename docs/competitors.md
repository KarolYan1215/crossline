## 科研工具

研究者实际用的是一组工具，而不是一个平台：Zotero（7 版有本机只读 HTTP API）、Elicit、ResearchRabbit、NotebookLM、Overleaf、Quarto、DVC。ELN 多为机构强制采用，而非研究者自选。

借鉴方向是集成而不是重做：Zotero 本机 API 可作为证据和材料来源，Git、DVC、Quarto 的产物可作为「图由某次提交重新生成」的证据。**均未做。**

## 主动询问的范式（2026-10-07）

| 来源 | 机制 | 借鉴 | 可信度 |
|---|---|---|---|
| LangGraph Agent Inbox | 代理用 `interrupt()` 停下，收件箱给出接受、编辑、回复、忽略四种回应 | 询问卡：选项事先写好，带推荐项，可稍后再问 | 核实（官方文档） |
| MCP elicitation | 服务端用扁平 JSON Schema 请求结构化输入，回应分接受、拒绝、取消；敏感信息走 URL 模式 | 选项下的追问字段只用文本、长文本、日期三种扁平类型 | 核实（规范 2025-06-18 及以后） |
| Linear Inbox snooze | 稍后提醒；到点或有新动态时提前回来 | 「明天再问」「下周再问」；底层变化（fingerprint）时提前回来 | 核实（官方文档） |
| Devin | 会话状态里有「等用户输入」，在 Slack 线程里提问 | 「后台没在运行」「AI 未登录」也作为询问 | 核实（官方文档） |
| Horvitz 1999 混合主动 | 按期望效用决定：有把握就做，不确定就问，打扰成本高于收益就不出声 | 缺输入时先拆能做的再问；夜间扩展跳过之类保持静默 | 核实（原文） |
| Proactive Service Agents（arXiv 2609.03727） | 何时做、何时问、何时沉默；评估时机、渠道、打扰程度 | 紧迫度决定渠道：今天要答进今日页，两天内截止才发桌面通知 | 二手（预印本） |
| Adamczyk 与 Bailey 2004；Iqbal 与 Bailey | 在子任务边界打断成本最低 | 不在工作块中途推送，询问集中在今日页和早报 | 核实（原文） |
| Fitz 等 2019（n=237 随机实验） | 通知每天分三批：更专注、压力更低；完全关掉反而焦虑 | 早报批量呈现，紧急单发有每日上限 | 核实（期刊） |
| ClarifyMT-Bench、QuestBench（2025） | 大模型倾向于不问就答（under-clarification） | 倒推缺输入时必须写明缺什么、谁有，不许编 | 二手（预印本） |

## 证据依据（设计按这些做，不按直觉做）

| 机制 | 效果 | 来源 |
|---|---|---|
| 具体的目标 | d≈0.34；公开或有难度时更强 | Epton 等 2017 元分析 |
| 进展监测 | d≈0.40；记录下来、报告出来时更强 | Harkin 等 2016 元分析（138 项研究） |
| 实施意图（何时何地做） | d≈0.65；现场实验里写下「日期+时间」才显著，+4.2 个百分点 | Gollwitzer 与 Sheeran 2006；Milkman 等 2011（PNAS） |
| 做计划本身 | 消除未完成目标带来的侵入性思维 | Masicampo 与 Baumeister 2011 |
| 外部提醒 | 提高意图被执行的比例 | Risko 与 Gilbert 2016 |
| 受保护的专注时段 | 随机对照：专注时间 +8–11% | Microsoft Research CAP 研究 |
| 拆开再估时 | 降低规划谬误 | Kruger 与 Evans 2004 |
| 反馈真实的历史用时 | 降低低估 | Roy、Christenfeld 与 McKenzie 2005 |
| 默认选项 | d≈0.68 | Jachimowicz 等 2019 元分析 |
| 审批与预警疲劳 | 临床预警被直接关掉的比例约 90% | Felisberto 等 2024 元分析 |
| 自我追踪被放弃 | 首要原因是记录成本 | Epstein 等 2015 |
| 稀释效应 | 多目标只降低**主观感知**的有用性，不是实际效果 | Zhang、Fishbach 与 Kruglanski 2007 |
| **不作为依据的** | 自设截止日能对抗拖延：2026 年复现失败；Zeigarnik 记忆优势：2025 年元分析不成立 | Psychological Science 2026；Ghibellini 与 Meier 2025 |
