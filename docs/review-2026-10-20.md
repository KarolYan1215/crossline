## 1. Agent 代执行：对标 Meta Muse

调研（来源见文末 A）要点：

- Muse（Meta，2026-09-08，muse.ai，仅美国）在每人专属云 VM 里跑，连接器走 OAuth（Gmail、Google Calendar、Instagram、Apple Health、Plaid、OpenTable……），token 由 VM 内 `authd` 持有，agent 只拿替身 token，网络边界的 Sentinel 换入真 token；邮件**按需搜索**，不整库下载；日历变更等少数连接器推送；每夜分析当日对话推断「没说出口的目标」，档案每小时更新；敏感动作（发邮件、付款）默认先问，每次批准可选一次 / 本任务 / 本站 / 永远。
- 它被批评的恰是「主动」：接连诱导连接银行、扫描全部邮箱（Wired）；「永远允许」下在 Marketplace 自作主张约取货并泄露住址（Fortune 10-19）；内部测试员报安全失败（Reuters）。
- 用户调研（文末 D）：Ping Identity 2026 一万一千人里只有 5% 接受「经我批准后行动」、3% 接受免批准；57% 把「能撤销」列为信任首因；行业共识是邮件「先草稿后批准」。

对本系统的结论：**主动跟进要学，自动外发不学。** 现状（docs/personal-agent.md）：IMAP 只读邮箱、15 分钟一读、`crossline-mail-triage` 分拣成待办/日期/回信/知悉；助手工具模式有 `mail_search`/`mail_read`、`add_to_inbox`、`tell_person`，没有任何发送函数。差距与改动见 §1 的走查记录。

## 5. 基础架构：Codex / Claude Code 近期能力

调研（文末 B）要点：

- Codex 上游已到 0.163.0（10-15），本仓库钉在 0.155.0。0.156–0.163 的 app-server 新增：`thread/resume` 自带权限恢复；`thread/compact/start` 显式压缩并流式 `contextCompaction`；`thread/goal/*`；`tool/requestUserInput`（我们已接）；`hooks/list`（PreToolUse/PostToolUse/SubagentStart/Stop）；`thread/fork`（含 ephemeral）、`thread/revert`、`thread/inject_items`；只读工具并行；Linux bubblewrap+seccomp 沙箱文档化、命令前完整性检查。
- ChatGPT 侧：事件触发的定时任务（Gmail/Slack/GitHub 事件）、**Thread automations**（线程按计划唤醒、结果回同一线程）、Team Tasks、MCP Events。
- Claude Code 2.1.304：hooks `onFailure:"block"` 与 `defer`（结束回合、人答复后恢复）；`/loop` 会话内 cron（1 分钟粒度、抖动防撞、7 天过期、错过不补发）；auto memory（MEMORY.md 索引，每会话只加载前 200 行）。
- Goose：两级压缩（80% 先压旧工具输出，超限再 summarize）；Cline/Gemini CLI：影子 git 检查点可回退。

优先采用（按价值）：(1) 升级到 0.163，用 `thread/compact/start` 显式压缩访谈与输入框长线程，并像 Goose 一样先摘要旧工具输出；(2) 自动化借用 Thread automations 形态：线程按计划唤醒、结果回同一线程，而不是每次新开（当前 `keepThread` 十分钟即弃）；(3) 守卫加 `defer` 语义：`agent.question.requested` 的十分钟等待改为挂起回合、人答复后恢复；(4) 工具模式助手每次工具调用后给任务目录做影子 git 快照，`salvageStoppedRun` 与「退回让助手补上」可精确回退；(5) `workflowSchedulePass` 与两分钟 nudge 时钟采用抖动、过期、不补发三条规则。本次未升级 Codex（需重做 `scripts/codex-smoke.ts`、Windows 安装包与 Linux 哈希，见 docs/local-installer.md）。

## 7. 可穿戴与 AI 硬件

调研（文末 C）要点与建议：

- 录音硬件里**只有 Omi**（原 Friend，MIT 开源，吊坠 $129–179，DevKit 2 约 $70）能把原始音频不经厂商云拿到：手机 App 把 16 kHz PCM 直接 POST 到自己填的 webhook。Limitless 已被 Meta 收购停售（API 只保到 2026 年底）；Bee 被 Amazon 收购、无原始音频；Plaud 无 API、云转写配额、只能手动导出；Humane 停机、Rabbit 无 API。
- 健康数据的正确入口是 HealthKit / Health Connect，不是各厂商 API：Oura 废了 PAT 只剩 OAuth（未审核 ≤10 人）、Whoop 要送审、Garmin 2026 停收新申请、Fitbit Web API 10-30 关闭、Zepp 无公开 API。HealthKit 第三方可读睡眠分期、HRV、静息心率、`appleSleepingWristTemperature`；Shortcuts「Find Health Samples」+「Get Contents of URL」能 POST 到我们已有的 `/api/health/sleep`，限制是自动化触发时手机须解锁。Health Connect 有 `READ_SLEEP`、`READ_HEART_RATE_VARIABILITY`、`READ_RESTING_HEART_RATE`、`READ_SKIN_TEMPERATURE`。
- 证据：传感器层夜间 HRV 与 ECG 一致性 CCC≈0.99，但 readiness/recovery 综合分没有独立验证；睡眠→次日警觉有关联但效应小（R²≈0.13）；控制睡眠时长后睡眠 HRV 预测体能、不预测脑力。结论：**睡眠时长与时点是主信号，HRV/腕温边际增益小**，与现有 `dayCapacity` 只做下调先验一致。
- 推荐：第一步 ¥0、1–2 天，把 iOS Shortcuts（解锁时段触发）与 Health Connect 导出接到 `/api/health/sleep`（接口已收 `restingHr`、`wristTempDeltaC`、`steps`、`events[]`），验证 `dayCapacity<1` 的天数占比和它改变排程的次数（已有 VOI 门）；几乎不改变就到此为止。第二步 $70–130 买 Omi DevKit 2 或吊坠，PCM webhook → 本地 whisper-small（先把 `transcribe.ts` 管线跑通），验证环境录音每天产出多少本人不会手打的 capture/日期、验收率多少；低于手打就停。不做：Plaud/Bee/Limitless、厂商直连 API、ESP32 自建（XIAO ESP32S3 Sense $13.90 能做，但验证不了 DevKit 验证不了的东西）、继续精细化 HRV 模型。

## 8. 公域用户调研

要点（文末 D）：

- AI 日程助理被骂最多的是**自动重排打乱计划**（Motion 一天重排 11 次、一个会议挪动引发 4 天重排，「AI Calendar Anxiety」）、**估时不准连锁推倒数天**、忘记标完成任务反复回到空档、一上来要日历/通讯录权限、试用转年付（Motion Trustpilot 27% 一星）。中文侧：AI 排的日期差一天、作息脱离现实、语音记录会编造。
- 多重身份人群：时间不足、精力分散、优先级冲突；科研「没有死线」、每天高效脑力约 4 小时；建议按角色锁定 10–15 高杠杆小时、整天/半天分块；切换成本的可靠依据是注意力残留（Leroy），「23 分钟」说法出处混乱。
- 画像报告：分享为社交破冰与归属感；不信因巴纳姆效应、付费报告模板拼接；每条结论须引本人原话（已做），并标明「非标准化心理测验」（已做）。
- 代办信任：只读可、发送/承诺/付款永远是人；每个动作带撤销与日志；权限按需、一键删除。
- 定价：Reclaim 免费层（G2 4.8）胜 Motion（4.2，$29–49/月无免费层）；Clockwise 2026-03 关停。

对本系统：(1) 重排可控——锁定块永不动、重排前有说明（`schedule.frozen`、变化摘要已做；本次把「一键顺延」放到估时失误处，§3）；(2) 估时自学习且宽容（§3）；(3) 按身份锁定整块时段与份额（`lineShares` 已有，需在计划页更显性）；(4) 代办 = 草稿 + 可撤销（§1）；(5) 透明定价（内测后再定）。三大信任风险：画像被视为模板、AI 代表错我、权限焦虑。
