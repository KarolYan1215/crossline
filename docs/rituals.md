# 每周承诺、晚间收工、全部按推荐、风险周报（2026-10-28 定）

本人账号 2026-10-28 实测：今天可用 630 分钟，待办 1735 分钟；4 个任务逾期 5–11 天，一直只是顺延；待确认 21、待决 14、铃铛 9+、提醒 3 条、以后再定 10、调研建议 17；风险一处写「10 个里程碑风险高」，另一处写「20 个有风险」，每个里程碑一张风险卡。

对照的竞品：
- Sunsama：每周和每天各有一个固定时刻，早上约 5 分钟定今天，晚上收工，确认完成与顺延；
- Superhuman「Get Me To Zero」：一键按推荐清空可撤销的项；
- Motion：风险提前几天说一次，不是每件事一张卡。

本人定了四件事，规则都在 `packages/core/src/rituals.ts`（纯函数，测试在 `rituals.test.ts`）。

## 1. 每周承诺

页面 `/commit`（`app/commit/`，数据 `apps/web/lib/weekly-commit.ts`，路由 `POST /api/commit`）。

**这一周的数**
- 本周可用：本人可用时段扣掉日历、本人的固定日程和路上时间（`netCapacity`，与预测共用一份算法），只算本周一至周日、今天及以后。
- 本周需求：每项任务剩下的本人分钟（`remainingMinutesOf`，未完成步骤的通常估时）。只算以下几类：
  - 本周日前截止（含已逾期）；
  - 已开始；
  - 排程器本周给了时间（`schedule.upcoming`）。
- 被推到本周以后（`notBefore`）且没开始的不算。

**建议怎么分组**（`proposeWeeklyCommit`）
- 砍：逾期 7 天以上、从没开始、所服务的里程碑重要性低于 60。
- 其余按这个顺序排，可用分钟用完前都保，用完后推：
  1. 已开始的；
  2. 本周截止的，逾期的在前；
  3. 里程碑更重的；
  4. 截止更早的。
- 后面较小的任务塞得进剩余时间，仍然保。

**确认时写什么**（「确认本周」，`applyWeeklyCommit`，路由里包在 `withUndo` 中，整次确认一个撤销）
- 推：`notBefore` 设为下周一。原截止早于下周一的，截止改到下周日（`deferTarget`）。
- 砍：`archiveWorkOrder`，理由「本周承诺：不做了」，可从已归档恢复。
- 记录：`schedule.weeklyCommit` 写周、可用分钟与保留分钟；另记一条 `week.committed` 事件。
- 「预览影响」用 `previewOverrides`（`lib/impact.ts`）把推与砍一起放进预览：推按新的 `notBefore` 与截止排；砍在预览里压到远期，不排。
- 「这周不调整」：什么都不动，这周记为已承诺。

**页面**（2026-10-28 改版，草稿 `docs/plans/page-drafts-1028/commit.html`，对照表见 `impl-e.md`）
- 页头是标题、本周日期和三个按钮（预览影响、这周不调整、确认本周）。
- 容量卡：三个数字（本周可用、本周需求、保留后），下面是一条容量条，竖线标出可用线，超出部分画红色斜纹。
- 容量卡底部一行写上周的情况（`lastWeekRecap`）：上周承诺保留了多少、推了几项、砍了几项、完成几件，并链接到周复盘。详情只在周复盘。
- 下面是保、推到下周、不做了三栏。每行写明为什么建议放在这一组；本人改过组的，写「本人改到这里」并附原来的建议。每行有两个图标按钮，可改到另外两组。
- 这周没有工作时，页面说明为什么不用调整，只留「确认本周」。

**什么时候问**（`weeklyCommitDue`）
- 周日 17:00 起问下一周，周一整天问本周。只在本周还没承诺、且建议里有要推或要砍的任务时，才进待决事项（`weekly_commit`）。全部排得下就不问。
- 周二以后没承诺的周不追问，下个周日再问。今日页日程面板有「本周承诺」入口，随时可打开。
- 已承诺的周：需求比可用多出 15% 以上（`OVERLOAD_RATIO`），而承诺当时没有超，再问一次（`overloadAskedFor`），不重复。承诺时就已超载并选择全保的，不再为同一超载追问。
- 卡上三个选项：「按建议确认」（一次生效，可撤销）、「逐项看」（打开 `/commit`）、「这周不调整」。

## 2. 晚间收工

页面 `/wrap`（`app/wrap/`，数据 `apps/web/lib/wrap.ts`，路由 `POST /api/wrap`）。

- 时机：本人当天最后一个可用时段结束时（`wrapTimeOf`），推送一条 `day_wrap`（「收工」）。也可以从今日页日程面板手动进入。
- 页面列出今天真正开始过的块（`nudge.blocks:<day>` 里 `began` 的块），每块一键：
  - 「完成」= 按预估完成；
  - 「部分」= 按块的时长记一次计时，步骤记到一半（2/4），步骤仍未完成，排程会再排；
  - 「没做」= 顺延。
- 写法与完成确认相同：`confirmBlockAt` 写 `block.confirmed`，键为 `wrap:<day>:<block>`。所以第二天的「昨天没开始」、效率拟合、细拆判断和早间简报读到的是同一份数据。已经回答过的块不会重复写入。
- 同页附「全部按推荐」，可顺带处理当天待决事项里有安全默认的项。
- 「收工」写 `wrap.done:<day>`，当晚不再提醒；同时把页面右侧列出的明天前三块记为 `keep`（到明天 23:59），第二天早上它们不再随重新推导而移动。有东西落在上面时照常放开，改可用时段、份额、权重等全局重排也会清掉（`clearKept`）。2026-10-30 月度模拟里，没有这一步时这三块第二天早上只有 41%–59% 还在原位。
- 页面（2026-10-28 改版，草稿 `wrap.html`）：
  - 页头：日期、最后一个可用时段几点结束、「收工」按钮。
  - 四个数字：今天计时、记为完成的块、待确认的块、明天第一块。计时按计时区间与当天的重叠计算，暂停按比例扣除。
  - 每个块一行：时段、块内计时、主线、任务、步骤，加一个完成 / 部分 / 没做的三段按钮。「计时过的块全部按预估完成」把还没记、且块内计时过的块逐个记为完成，写法与单个点「完成」相同；没计时的块只能逐个点（2026-10-30 月度模拟：一键把没碰过的块也记成完成，任务从排程里消失）。
  - 右侧：全部按推荐；明天的前三块（`loadTimeline`）。
- 补记前几天（`/wrap?day=YYYY-MM-DD`，`wrapDayOf`）：
  - 只接受最近 7 天，其他日期一律回到今天。今日页「昨天没开始 → 逐个处理」链接到这里。
  - 那天开始过的块照样列出，写法与当天相同，键为 `wrap:<那天>:<块>`；路由 `POST /api/wrap` 带 `day`。
  - 补记页没有「收工」和「明天」，页头只有「回到今日」。
- 夜间 23:00–08:00 不推送。没收工的那天，次日早间简报的「昨晚 N 块待确认」会把当天所有未确认的块都算进去（`unconfirmedLastNight`）。

**替换了什么**
- 原先每个工作块结束后半小时内各推一次 `block_confirm`，一天最多可达 6 次。
- 现在：今天有可用时段时，只有任务明天或更早到期的块，仍在结束后单独问。这类回答会改动今晚或明天的安排，不能等。
- 其余块都并入晚间的一条「收工」消息，这条不占每日条数上限。
- 早晨与白天的其他提醒不变。

## 3. 全部按推荐

`apps/web/lib/answer-all.ts`，路由 `GET/POST /api/asks/answer-all`，按钮 `app/asks/answer-all.tsx`。按钮在待确认页四象限上方，也在收工页。

**会处理的项**（`ANSWER_ALL_KINDS`、`answerAllSteps`）
- 风险周报 `risk_digest`：接受。
- 审查风险 `milestone_risk_review`：接受。
- 昨天没开始 `missed_block`：顺延。
- 关系兑现检查 `relation_check`：这类卡的三个选项都在断言「交付了多少」，没有安全默认，所以改为下周再问。
- 助手成果：只采纳干净的，即自检通过、没改原文件、没有对外、不是半成品（`safeAssistantResult`）。
- 过期提议：截止已过，或已等 14 天、而且步骤已拆好的提议，归档（`staleProposal`）。

**不会处理的项**
- 里程碑草稿和目标；
- 任何对外动作；
- 需要本人提供事实的问题，例如成绩、文件、收集分析、步骤问题、访谈问题、等待项、考后结果；
- 两天内到期的单项风险卡（`milestone_risk`）：不看就接受，会把最后还来得及的提醒也压掉。
- 推荐项本身要填字段、要跳转页面或要本人写字的，也跳过。

**怎么执行**
- 点之前先列出将处理的条数和种类。
- 所有处理在一个 `withUndo` 里完成，一个撤销即可恢复。`withUndo` 新增参数 `extra`，用来把快照看不到的 `agent.reopen`（重新打开已采纳的助手成果）并进同一个撤销。
- `answerAsk` 和 `snoozeAsk` 新增 `{undo: false, ask}`，供批量处理调用：不单独登记撤销，也不必为每一项重新收集一遍 asks。

## 4. 风险周报，计数统一

**周报卡**
- 预测风险（`riskAsks`）和审查风险（`riskReviewMembers`）合并成一个集合（`riskSet`），每个里程碑一项。
- 两天内到期的仍各自单独成卡（`milestone_risk` / `milestone_risk_review`）。
- 其余合成一张 `risk_digest`（`risk:weekly`），一周一次。
- 周中只有某项变成高风险时（`riskDigestShows`）才再出；新出现的中风险等下周一起列。
- 「全部接受」：
  - 审查过的里程碑，记 `schedule.riskDecisions` 的 accept，排程让它的任务提前 1–2 天排完；
  - 预测风险，记 `risk.accepted`，本周不再提。
- 「这周不用管」：不改排程。
- 两种回答都会在 `schedule.riskDigest` 记下本周看过的级别。
- 旧的「每个里程碑一张卡」和折叠卡 `riskreview:batch`（含「逐个决定」）已去掉。

**计数统一**
- 今日页提醒条的风险行不再按主线页的规则估算去数「风险高」。改为 `riskOverview`，与周报卡用同一个集合。堆叠里已有风险卡时，提醒条不写这一行。
- 提醒条的里程碑草稿数改读 `countPending` 的本周草稿数。

页头仍只有一个「待确认」数（`PendingBadge`，读 `usePendingView`）。今日页堆叠与日程面板读同一份 `pending`。

## 5. 周复盘与侧栏（2026-10-28 改版）

- 侧栏新增「节奏与回顾」组：本周承诺、收工、周复盘（`RITUAL_ITEMS`），手机放在「更多」里。周复盘原来只能从主线页进入。
- 周复盘 `/review` 的场景：周末或周一早上回看上周，并拍板长期判断。
  - 页面顺序：四个数字（完成的任务、计时、自动验收、待拍板），「要拍板的」（候选关系、调研结论、信息域扩展、洞察提案），然后是「回看」。
  - 候选关系只在这里批准。主线抽屉只显示关系，并链接过来。
  - 「本月花钱」只留一行摘要，链接到主线的理财线卡和总账。记录的主场在线卡。
