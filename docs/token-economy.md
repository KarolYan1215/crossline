# Token 经济：把额度花在核心功能上（2026-10-21）

本人要求：分析系统每个调用模型的环节，尽量减少 token、提高缓存命中，把 token 优先花在核心功能上；三轮对话确认了下面的方案。教程准备的分级与流程见 `task-preparation.md`，模型闸门与调度见 `model-scheduling.md`。

## 1. 测量（托管站 10-17 至 10-22，全部账号，954 次记录在案的运行）

- 输入 30.3M，其中缓存 72%；输出 2.9M，其中推理 2.1M（72%）。
- 计价：ChatGPT 订阅额度下缓存输入按 1/10 扣（Codex 定价页），输出远贵于输入（估算按 8 倍，未证实）。**真正的花费是输出（尤其推理）和未缓存输入。**
- 按加权（未缓存 + 0.1×缓存 + 8×输出）算 ChatGPT 额度：访谈 21%、拆步骤 16%、教程撰写 13%、validation-reviewer 12%（主要是公开 skill 候选审查，缓存只有 24%）、教程检索 10%、访谈整理 7%、倒推 5%。
- **没记账的大头：Codex 记忆。** 结构化后台 Skill 在账号自己的 Codex 上开着 `memories.generate_memories/use_memories`。每个线程闲置 6 小时后，Codex 用 `gpt-5.6-luna`（low）读整份裁剪后的记录写一条摘要（stage-1），每 6 小时用 `gpt-5.6-terra`（medium）合并（phase-2），都扣同一个账号的额度，`model_usage` 不记。10-20 起 510 次 stage-1，**usage_count 全为 0**：结构化 Skill 没有 shell 读不了 MEMORY.md，输出被 JSON 限定从不引用。几个账号的记忆还混在机主运行时的同一份记忆里。
- 已有问题：
  - 前缀被打乱：Codex 路径上 SKILL.md 正文被插在每次都变的 JSON 之后；拆步骤、撰写、助手把逐任务内容拼进开发者指令，固定的 STYLE 被推到变化内容后面；JSON 把 `today` 放最前。新线程的命中常只有 15–40%。
  - repair 让模型整份重写 JSON；倒推 36 次里 12 次 repair，邮件分拣（Qwen）57 次里 16 次。
  - SiliconFlow 上 Qwen 零缓存，V4.1-Flash 缓存只收 2%。
  - 非核心后台（公开 skill 搜寻与审查、主线技能编译、调研、飞轮、画像重写、原型策展）没有总量上限；公开 skill 搜寻加审查约占 ChatGPT 额度 14%。
  - `insight-compiler` 76 次 `MINE_SKILL_BLOCKED` 循环（已由 W-114 修）。

## 2. 决定（本人，2026-10-21）

1. **关 Codex 记忆**：结构化后台 Skill 关闭生成与使用。已累积的记忆先备份，按 `model_usage.thread_id` 找回所属账号，把其中「失败与改进」「偏好信号」按规则迁入各账号的经验教训表，再删掉记忆文件。
2. **账本吸取 Codex 记忆的设计**（都不新增每线程一次的模型调用）：
   - 经验教训表（主线 × 任务类型）：由规则从已有事件抽取——助手结果的退回备注、验收「部分」的违背项、超出保守估时的步骤、重复的错误码；最多 5 条进拆步骤和助手的输入。
   - 使用计数：偏好与事实记被用次数和最近使用；结果被采纳时累加；进上下文时按使用挑选。
   - 索引加按需读取：拆步骤和收集分析只拿一行一条的事实索引，用 `read_ledger` 读全文；不能调工具的模型仍给全文。
   - 自动过期与增量编译：30 天未用的估时、重要性、推迟类偏好失效（本人确认过的不动）；主线技能编译用稳定的材料 id，只传变化的材料加上一版规则。
3. **非核心后台每周最多占额度 20%**，只在额度宽裕或夜间跑，超了暂停到下周。设置 → 后台任务只给一个「节省额度」开关（默认开），不展示数字；加权成本只在后台记账，用来判断暂停。
4. **公开 skill**：只在主线设立时（访谈完成或新增主线）为这条线搜一轮；之后每月补充一次；本人要求时可再搜。不再「覆盖全部需求」地连续多轮。
5. **前缀重排**：只改顺序不改内容——固定指令、风格、Skill 正文、画像与偏好在前，`today` 和逐次变化的数据在后。目标：新线程命中 ≥ 70%。
6. **开发者模型上的简单 Skill** 按实测加权成本挑模型：缓存价和 repair 都计入每次运行的成本。
7. **推理强度先对比再定**：在真实任务上比较拆步骤、倒推、教程撰写降一档前后的质量和 token，结果出来再逐个决定；开发者模型的规划类先把思考封顶 2048。

## 3. 实施（2026-10-22）

- 记忆：结构化 Skill 与助手线程都关掉 Codex 记忆；worker 启动时一次性把已累积的「失败与改进」「偏好信号」按 `model_usage.thread_id` 迁入各账号的经验教训，记忆文件移到 `<data>/backups/codex-memories-<日期>/`，不删除。
- 前缀：10 个 Skill 按 `stableKeys` 排序输入、逐次说明放进 `runNote`，同一 Skill 的开发者指令逐字节相同（测试数据上拆步骤的共同前缀 8% → 96%）。限制：Codex 路径上 SKILL.md 总在本次输入之后（`turn.rs`），且 `prompt_cache_key` 是线程 id，新线程不保证命中；命中率以上线后的 `skill.run` 日志为准。
- 经验教训表（迁移 20）、使用计数与过期、事实索引加 `read_ledger`、主线技能增量编译、「节省额度」（迁移 21 的 `model_usage.purpose`）、公开 skill 设立一轮加每月补充加 Skill 库「再检索一轮」、开发者模型简单 Skill 按 `skillYuanPerRun` 选：见 CLAUDE.md「Token economy」。
- 托管账本副本实测：拆步骤事实 15.6k → 12.0k 字，收集分析上下文 87.1k → 74.1k 字，研究线主线技能重编 12k → 1.2k 字。
- 未做：推理强度对比（第 7 条，待在真实任务上跑）；Codex 路径的技能目录（`skills.include_instructions`）仍开着，它随并发开关的 skill 变化，关掉会改提示内容，留待决定。
