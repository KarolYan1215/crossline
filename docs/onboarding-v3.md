# 登录与访谈 v3（设计，2026-10-14）

机主在本机装好安装版后，以新用户身份看了登录页和访谈页，结论是「登录页很丑、没有可视化；访谈和设计不一样；全是文字」。本文是随后六轮问答确定的方案，按阶段实现，每阶段走查后再进下一阶段。

## 审查发现（2026-10-14，安装版 0.1.0）

登录页
1. 只有一个「C」、标题、一句话和一个普通按钮，看不出产品做什么。
2. 按钮写「用 ChatGPT 登录」，没有标识。OpenAI 的 Sign in with ChatGPT 文档要求写「Continue with ChatGPT」，用官方标识，与其他登录方式同等醒目。
3. 点按钮后在新标签页打开 OpenAI，原页面只显示一行灰字；没有「登录 → 回来 → 开始」的步骤，第一次启动 Codex 的半分钟没有进度，也没说数据只在本机、模型用本人额度。

访谈页
4. 顺序与 2026-10-12 的「先加材料」不一致：第一屏是「先设定主线」，材料在第二屏。（2026-10-08 的设计写的是先设主线，两份设计本身矛盾。）
5. 第一屏先讲六层概念（主线、长期目标、里程碑、任务、步骤、日程），设完主线后又讲一次。
6. 设主线要先理解「参与主次 / 硬约束 / 底座 / 平行」四个概念和四条长规则，只有一个空输入框。
7. 页头说「右侧为实时画像」，第一屏没有右栏，1440 宽时右侧约 40% 空白。
8. 小助手旁浮着只写「10 月 14 日 周三。」的气泡；顶部导航的今日、主线、计划、任务点了都回到访谈。
9. 每轮等 1–4 分钟只有一行灰字；右侧画像几乎都是文字块，「能量地图」是四格文字，阶段条是一排字，「开始使用前还差 N 项」是文字列表；看不到总时长。
10. 12–13px 灰字、细边框，主线颜色在访谈里没有用到，整体像线框稿。

## 决定

### 登录页
- 左右分屏。左边：Crossline、一句「几条人生主线，排进同一张日历」、一段示意动画（几条主线依次接入、一周日历块依次落位；`prefers-reduced-motion` 时为静态）。右边：「Continue with ChatGPT」主按钮（官方标识）、三步说明（在新标签页登录 ChatGPT → 回到这里自动进入 → 回答几轮问题，约 N 分钟拿到第一版一周安排）、「数据只存在这台电脑 · 模型用你自己的 ChatGPT 额度」。
- 等待状态是三步里的当前一步在动，第一次启动 Codex 显示真实进度。
- 风格沿用画像的「编辑杂志」风：米白纸底、衬线标题、墨线分隔，主线色用于图形。

### 访谈页：三栏
- **左栏**：材料与日历（拖入文件、录音、授权文件夹、接入日历；每个来源显示读取状态和读出了什么）、长期目标选取（属性候选拼成「成为 … 的 …」并采用）、已确认的事实与日期（可当场纠正或确认）。
- **中栏**：对话流，输入框始终在底部。
- **右栏**：按阶段切换的实时构建图，可以点回看之前阶段的图；「开始使用」五项标准做成分段进度环放在右栏顶部，并显示预计剩余时间。
  - 开场：主线网络
  - 现状：一周日历骨架（接入的日历、课表、可用时段）
  - 指南针：价值雷达，工作观与人生观对照
  - 能量：「擅长 × 热爱」点阵与心流时刻
  - 细节：里程碑时间轴草图
  - 结束：画像海报，以及用本人内容画出的六层结构图（「你的计划是这样搭起来的」）
- 顶部阶段条带名称，旁边写预计时间。导航在开始使用前不显示四个工作视图。

### 引导性开场
参考机主给的「人生设计师」写法，只取设计引导对话的方式，不照搬内容：
- 第一条消息用大白话说清前提（人生像一件可以反复改的作品，起点是承认现在真实的位置）、接下来的流程、大概时间和能拿到什么。
- 紧接着一道带选项的问题定语气：直接犀利 / 温和支持 / 中性客观，**默认中性**，之后在设置里可改。
- 对话用第二人称「你」（只限访谈对话；按钮和其他页面的文案仍按 `docs/copy-style.md`）。
- 仍不做「三个五年版本」和「原型行动清单」（维持 2026-10-08 的决定）。

### 提问节奏：混合
- **事实类**（身份、主次排序、哪条主线有固定日程即硬约束、每周可用时间、项目与截止日）：选项卡片，一批答完。主次和硬约束放进首轮事实卡；开始时可选接入日历，接入后由日历推断，首轮问得更准。
- **深度类**（最焦虑的问题、工作观、人生观、心流、执念）：一次一个，答完给一句简短而切中要害的反馈再追问，追问结束回到主线。用现在允许的最高档模型（`gpt-5.6-sol` medium），不用快速模型。

### 等待
- 实时进度：正在读哪个文件、已整理出几条事实和日期，右栏的图边读边长（需要把运行中的事件传到页面）。
- 等待时可以做别的事：确认已读出的日期、调整主线顺序、采用长期目标。
- 可以离开；下一轮好了时发桌面通知、标签页标题加「● 新问题」、托盘图标提示。

### 日历接入
- 保留 ChatGPT 的日历连接器（Google / Outlook，`calendar-apps.ts`）。
- 在 app 里自建、不依赖用户的 ChatGPT 账号：
  1. 先做订阅地址：粘贴日历的私密 iCal 地址（苹果、Google、Outlook 都能导出），只读，无需授权，配各家图文步骤。
  2. 再逐个加官方授权直连（Google 需机主注册 Google Cloud 项目，内测期最多 100 个手动添加的测试用户；微软需改 Entra 设置；苹果用 CalDAV 加用户自己生成的应用专用密码）。

### 文件夹授权
- 授权一个文件夹路径，递归读取所有子文件夹中能读的文件（PDF、Word、文本、Markdown、幻灯片），默认跳过 `.git`、`node_modules`、缓存；单个文件上限 50 MB，超过的只记文件名。读前显示文件数和总量。
- 持续跟踪：新增或修改的文件在后台重读，用于以后的任务规划和材料准备；设置里可随时取消授权。
- 模型按文件夹名和内容自动归属主线，一个文件夹可属于多条主线；左栏可修改。

## 阶段
1. 合并 `claude/elegant-pascal-ksk86u`（17 个更新提交）。
2. 登录页。
3. 访谈三栏骨架、引导性开场、语气选择、混合节奏、右栏按阶段的图、进度环与时间。
4. 等待体验：运行事件传到页面、等待时可操作、三种通知。
5. 日历订阅地址。
6. 文件夹授权与跟踪。
7. 日历官方直连（逐个）。

每阶段：实现 → 测试 → 以用户视角走查（摩擦、阅读量、语言、视觉）→ 给机主看 → 下一阶段。

- 阶段 1（2026-10-14）：已合并（`2bf7b30`），全量 1704 项测试通过。
- 阶段 2（2026-10-14）：登录页完成。`app/login/page.tsx`（本机版分支）、`login-preview.tsx`（四条示例主线依次接入、一周日历块依次落位，减少动态效果时静止）、`local-login.tsx`（三步、当前一步转圈、Codex 启动时显示已等待秒数）、`login.css`。标题用画像的衬线体（`.pt-serif`），界面用到的固定标题在 `app/ui/serif-strings.ts`，字体子集随之重建。手机宽度下隐藏示意图（标签会缩到 12px 以下；安装版只在桌面上用）。
  - 走查时发现：安装版和常驻版都在 127.0.0.1 上，cookie 不按端口区分，同一浏览器里登录一边会挤掉另一边的会话。安装版的 cookie 改用 `crossline-local` 前缀（`packages/auth/src/index.ts`）。

- 阶段 3（2026-10-14）：访谈三栏完成。
  - 中栏：`onboarding-workspace.tsx`。开场卡（`opening-card.tsx`）先说前提、三段和约 30 分钟，再问语气（直接犀利 / 温和支持 / 中性客观，默认中性，`onboarding.tone`，`POST /api/onboarding/tone`）、身份、未来 12–24 个月的底座和哪几条有固定日程；答案写入主线（排名、硬约束），再作为首轮回答发给访谈。事实类一批答完；深度阶段（现状、指南针、能量）一次一个大号问题，其余事实题挪到左栏「待补充的事实」，随下一次回答一起发。对话固定在中栏内滚动，新一轮把问题滚到视野顶部；设计里程碑和网上查证在达到开始标准后才出现。
  - 左栏：`left-column.tsx`。材料与日历、待补充的事实、长期目标（已采用的收成一行加「修改」）、已记下的事实（槽位名一律中文，未知的显示「备注」）。

- 阶段 4（2026-10-14）：等待体验完成。
  - 运行时把答案边写边推（`item/agentMessage/delta`），runner 新增 `onProgress`（`SkillProgress`：thinking / writing / checking，带修正与重发次数，写作阶段每半秒一次）。答案按 schema 顺序出，`reply` 在最前，所以 `readPartialTurn`（`packages/core/src/onboarding-progress.ts`）能在一轮结束前读出回复的前半段，并数出已写的问题、事实和日期。这些都不入账、不信任，验收后的答案一到就替换。
  - worker 在一轮运行时把进度写进账本 `onboarding.progress:<会话>`（写作阶段每秒最多一次，另有 15 秒心跳，读文件时也不会被当成停止），结束即删；网页 `GET /api/onboarding/progress` 读取，超过 45 秒没更新视为没有在跑。
  - 中栏的等待气泡（`turn-progress.tsx`）：正在读哪几个文件 → 正在写（回复逐段出现）→ 正在核对引文和日期；已整理几条事实、几个日期、几个问题；已用时间。刷新页面后若后台仍在跑，会接上并在结束时自动载入，期间不能再发一轮。
  - 等待时可做别的事：左栏（长期目标、待补充的事实、事实修改、上传）和日期确认在一轮进行中仍可操作；确认日期不会打断这一轮的等待状态。
  - 提醒：页面不在前台时标签页标题加「● 新问题」；允许后由页面自己发桌面通知（「好了用桌面通知提醒我」）；安装版另有托盘气泡——网页在用户离开 90 秒后往 stdout 写一行 `@crossline:notify {…}`，启动器检查（只许本应用的页面路径）后转给托盘，点气泡打开访谈；手机推送照旧。
  - 预览：`scripts/install-preview-progress.ts [秒]` 在预览账本里模拟一轮进行中的进度。
- 阶段 5（2026-10-14）：日历订阅地址完成。
  - 粘贴日历的私密 iCal 链接（`webcal://` 或 `https://`），只读、不用登录、不依赖 ChatGPT 账号；卡片（`app/connectors/calendar-subscriptions.tsx`）在访谈左栏和设置 → 日历与连接，附苹果 / Google / Outlook 三家取链接的步骤（点「链接在哪里？」展开）。
  - 链接本身是钥匙：只存在 worker 的 DPAPI 密钥库（`ical-<id>`），账本只记名称、域名和最近一次读取的结果（`calendar.subscriptions`），不进导出和备份，换电脑要重新粘贴。
  - 添加前先读一次（`addSubscription`）：打不开、不是日历文件、不是 https 都当场拒绝，不存下来每轮失败。读取走 `safeGet`（公开域名、每次跳转都查 DNS、5 MB 上限、只收日历类内容类型）。
  - 解析用 Mozilla 的 ical.js 2.2.1（无依赖，MPL-2.0）：`readIcal`（`packages/connectors/src/ical.ts`）展开重复日程，应用改期与跳过（`RECURRENCE-ID`、`EXDATE`），文件自带的时区、Outlook 的 Windows 时区名、文件没定义的 IANA 时区和 UTC 都按各自的方式换算（含夏令时切换）；全天、标为空闲和已取消的不算占用。
  - 每个订阅是现有同步里的又一个 `CalendarSource`（键 `ical:<id>`）：没有增量游标，每次读都是全量，所以只对自己的日程有权威；读失败时保留上次的日程并在卡片上说明原因；移除时立刻从计划里拿掉它的日程。没有配置 Graph 的机器（安装版）也照常同步。
  - 访谈：日历里未来七天的日程（`calendarWeek`）首轮必带、之后只在变化时带给访谈，Skill 先从中读出固定日程和已占用的时间，再请本人确认，而不是从零问起；右栏「一周」把日历日程画成灰块，接上日历后从第一阶段起就能看。
- 阶段 6（2026-10-14）：文件夹授权完成。
  - 卡片（`app/connectors/source-folders.tsx`）在访谈左栏和设置 → 日历与连接：填文件夹完整路径 → 「查看」先说要读几个文件、共多大、几个只记文件名、跳过几个依赖/缓存/隐藏文件夹，并列出前几个文件名 → 「授权并读取」后在后台读，读完显示「已读 N 个文件」；「取消授权」后不再读取，已读的内容保留。
  - 规则（`packages/core/src/source-folders.ts`）：递归，不跟随链接；跳过隐藏、`node_modules`、构建输出、缓存、回收站等目录；跳过隐藏文件、Office 锁文件和 `isSecretPath` 认作密钥的文件（`.env`、私钥、密码库……）；读 PDF、Word、文本/Markdown/CSV，单个超过 50 MB 只记文件名；幻灯片、表格、旧版 Word 暂只记文件名；图片和录音不读（私人内容，请主动上传）。拒绝整个磁盘、整个用户文件夹、系统文件夹、应用数据文件夹和 Crossline 自己的数据。每个文件夹最多读 1000 个文件、走 20000 项。
  - 读取（`apps/worker/src/source-folders.ts`）：每个文件按内容哈希复制进应用自己的 `sources/` 再读（与上传同一条提取路径 `extractDocument`），所以原文件移走也不影响；每轮 worker 重扫，按大小与修改时间只读新增或改动的，每个文件夹每轮最多 40 个，其余下轮继续。
  - 主线归属：新 Skill `crossline-folder-classifier`（低档，intake 类后台任务）按文件夹名、文件名和几个文件的开头提议它属于哪几条主线（可多条，可为空，附理由），每个文件夹只问一次；本人在卡片上点主线即改为自己的选择（`linesBy: "person"`），之后模型不再覆盖。步骤规划在任务自己的文件少于 3 个时，会补上归在该任务主线下的文件夹里的材料。
  - 访谈：每轮只读能放进预算的新文件（最多 12 个、约 6 万字），其余留到下一轮并告诉访谈还有几个在等（`sourcesWaiting`），不再出现「标记已读但正文被截掉」；左栏的上传列表不再逐个列出文件夹里的文件。
  - 预览：`scripts/install-preview-server.ts` 的替身后台直接调用同一组 worker 函数，文件夹授权可在预览里真实走通。
