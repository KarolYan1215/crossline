# 使用手册

第一次接触这个仓库、想知道"从零开始该按什么顺序做"，先看
[docs/getting-started.md](./getting-started.md)——那份文档是完整的首次走查，
会在需要的地方链回本文这里。本文覆盖的是账号、离线、Tailscale、备份这类基础设施细节，
不是产品功能的操作顺序（第 11–14 节讲采访、转写、屏幕活动、用量）。

这份手册按真实场景组织，每一节除了操作步骤，还说明这一步背后动的是哪个真实机制——
session、`AccessContext`、workspace 过滤、Codex capability token、离线 outbox、审计事件——
不是空泛的点哪里点哪里。涉及的代码位置见各节标题旁的引用。

## 1. 首次注册（邮箱密码）

1. 打开 `/signup`，填邮箱、密码（至少 8 位）、名字，提交。
2. Better Auth（`packages/auth`）写入 `auth.db` 的 `user` 表，`emailVerified: false`，并通过配置好的
   SMTP（见下方「SMTP 是什么」）真实发出一封验证邮件。
3. 点击邮件里的链接，`emailVerified` 变成 `true`。**没验证之前不能登录**——`requireEmailVerification: true`
   是硬编码的，不是可选项，登录会直接报 `EMAIL_NOT_VERIFIED`。
4. 用刚才的邮箱密码在 `/login` 登录，跳回首页。

**这一步背后发生了什么（`packages/auth/src/index.ts` 的 `requireAccessContext`）**：首页第一次真正加载时，
`requireAccessContext` 从 session 里拿到 Better Auth 的 `user.id`，查 `crossline.db` 的 `principals` 表——
第一次查不到，就在**一个事务里**同时建好 `principals`/`workspaces`/`workspace_members` 三行，
角色是 `owner`。这是全新的空 workspace，**不会**自动继承磁盘上旧的 `personal-crossline` 账本数据——
旧数据还在，只是新账号看不到（这是阶段二定下的决策，不是遗漏）。往后每次请求都会重新查一遍
`workspace_members`，不是从登录时的 session 里读一份缓存的角色——这也是为什么下面「撤销设备」和
「撤销 session」一旦生效，是**立即**生效，不用等 cookie 过期。

**SMTP 是什么、为什么邮箱注册可能是关掉的**：`packages/auth`
在 `CROSSLINE_SMTP_HOST`/`PORT`/`USER`/`PASSWORD`/`FROM` 五个环境变量**全部**配好之前，
邮箱注册这个功能整个不存在——不是"注册了但收不到验证邮件"，是 Better Auth 的
`emailAndPassword` 插件根本没有被启用。这是有意设计的（"SMTP 未配置时禁用邮箱注册，不允许退化为
未验证账号"），宁可整个功能消失，也不允许一个永远收不到验证邮件的账号存在。生产选型是
[Resend](https://resend.com)（免费层 3000 封/月）：`smtp.resend.com:465`，`user` 固定填
`resend`，`password` 是 Resend 后台生成的 API key，`from` 用 Resend 提供的
`onboarding@resend.dev` 即可（不用自己验证域名）。**这里有一个只有真实跑过才会踩到的坑**：
沙盒模式下 `onboarding@resend.dev` 只能发给 Resend 账号自己的注册邮箱，
不是"发给任何人都行"——真实收件邮箱必须和注册 Resend 账号时用的邮箱一致，不然验证邮件根本发不出去
（会收到 `550 You can only send testing emails to your own email address`）。

## 2. Google 登录

前提：`CROSSLINE_GOOGLE_CLIENT_ID`/`CROSSLINE_GOOGLE_CLIENT_SECRET` 已配置（`apps/web/.env`）。

1. `/login` 页面点"用 Google 账号登录"。
2. 跳到 Google 账号选择/授权页，同意后跳回 `/api/auth/callback/google`，Better Auth 建 session，
   跳转到首页。

**从零开通 Google OAuth 客户端**（Google 云端操作，跟本机无关，只有回调 URI 要指到本机/Tailscale
能到的地址）：
1. [console.cloud.google.com](https://console.cloud.google.com) 新建或复用一个项目。
2. "OAuth 同意屏幕"：User Type 选"外部"；只勾 `openid`/`email`/`profile` 三个基础 scope
   （Better Auth 默认只要这三个）。
3. **不要停在"测试"状态**：测试状态下签发的 refresh token 7 天就过期，长期用会每周被强制重新登录。
   基础 scope 发布到"生产中"**不需要 Google 人工审核**，填好应用名称、支持邮箱、开发者联系邮箱后
   直接点"发布应用"，几秒钟生效、免费、长期有效。
4. "凭据" → "创建凭据" → "OAuth 客户端 ID" → 类型选"Web 应用"。
5. **已获授权的重定向 URI** 可以同时挂两条（同一个客户端不用为每个环境建新的）：
   - `http://127.0.0.1:3210/api/auth/callback/google`（本机直连）
   - `https://<你的 tailscale 主机名>.ts.net/api/auth/callback/google`（阶段六接入 Tailscale 后再加）
6. 复制 Client ID / Client Secret 到 `apps/web/.env`（**不是**仓库根目录的 `.env`——Next.js
   只认自己项目目录下的 env 文件，根目录放一份会被静默忽略）。

**这一步背后发生了什么**：`packages/auth` 配了
`account: { accountLinking: { disableImplicitLinking: true } }`——如果这个邮箱**已经**注册过密码账号，
再用同邮箱的 Google 登录**不会**静默合并成同一个账号，而是报错。已登录状态下可以用
`authClient.linkSocial()` 显式关联，但那是账号本人的主动选择，不是系统替你做的决定。
`requireAccessContext` 里 `identity.provider` 的判定逻辑（查 `account` 表，社交登录优先）
是审计用的——`audit_events`（如果调用方传了）会记这次到底是密码登录还是 Google 登录，跟真正的
授权判断（`workspace_members` 查询）是两回事，一个记录"是谁"，一个判断"能不能"。

## 3. 邮箱找回（重置密码）

1. `/login` 页面点"忘记密码"，进 `/reset-password`。
2. 没带 token 时显示"发送重置链接"表单，填邮箱提交。
3. **不管这个邮箱是否真的注册过，页面显示的文案都一样**："如果这个邮箱已注册，重置链接已经发出，
   请查收邮件。"——故意如此，避免这个表单被用来试探"这个邮箱到底有没有注册过"。
4. 邮件里的链接会带一个 token 参数回到 `/reset-password?token=...`，这时页面自动切换成"设置新密码"表单。
5. 提交新密码，成功后跳回 `/login` 用新密码登录。

同样依赖第 1 节的 SMTP 配置——没配 SMTP，这条链路一样是"整个功能不存在"，不是"发不出邮件"。

## 4. Tailscale 绑定（私网跨设备访问）

**先决条件**（一次性，Tailscale 账号侧操作，详见 `docs/private-network-deployment.md`）：
tailnet 已创建、这台机器已 `tailscale up`、tailnet 管理后台已启用 Serve 功能、本机已跑
`tailscale serve --bg 3210`。做完这些，`https://<hostname>.ts.net` 就能从 tailnet 内任何设备访问到
这台机器上跑着的 Crossline，`CROSSLINE_DEPLOYMENT_MODE=private` 打开了 HSTS/CSP 等安全响应头。

1. 从 tailnet 内的另一台设备（手机、另一台电脑，只要都登录了同一个 Tailscale 账号）打开
   `https://<hostname>.ts.net`，正常走第 1/2 节的登录流程。
2. 登录后打开设置页（`/settings`）的「日历与连接」，「私有网络身份」卡片会显示这次连接实际携带的身份
   （`Tailscale-User-Login` 请求头，只有真的经过 `tailscale serve` 反代才会有）。
3. 点「记录为可信身份」，写进 `tailscale_bindings` 表。

**这一步背后发生了什么，以及为什么不是自动登录**：Tailscale Serve 转发给后端的身份头只有三个——
`Tailscale-User-Login`/`-Name`/`-Profile-Pic`——**没有任何节点标识**，而且 Tailscale
会剥离请求里任何伪造的同名头，所以这三个头本身是可信的。但"可信"不等于"可以当登录用"：
这里设计成**必须先用正常的 Better Auth 账号登录**，再在已登录状态下主动点一次"信任"，
写下的只是一条审计记录（谁在什么时候确认过哪个 Tailscale 登录是自己）。任何页面的真正访问控制
依然只看 session 是否有效，Tailscale 头从来不参与鉴权判断——`apps/web/app/api/connectors/tailscale/route.ts`
的 doc comment 专门写明了这一点。撤销一条绑定（列表里点"撤销"）只是删掉这条审计记录，
不会让对应的登录 session 失效。

## 5. 离线工作

1. 网络断开时，Workbench 页面的"开始执行"/"暂停"/"恢复"/"完成"按钮照常可点——命令被写进浏览器本地的
   Dexie（IndexedDB）数据库，不是丢弃或报错。
2. 网络恢复、页面重新加载时，`OfflineReplay` 自动把队列里的命令依次回放到服务器。
3. 首页会显示"N 条等待同步"，同步失败的（服务器永久拒绝，比如证据格式不对）进"无法同步"列表，
   跟另一台设备冲突的进"冲突"列表（见第 6 节），都能在 `/offline` 页面看到并且手动丢弃。

**这一步背后发生了什么**：Dexie 数据库名是 `crossline-offline-${workspaceId}`，不是固定名字——
换账号登录时不会把上一个账号缓存的离线命令带进新账号的队列，这是账号切换时的数据隔离，不用额外操作。
队列里的负载（payload）用 `crypto.subtle.generateKey` 生成的**不可导出** `CryptoKey`（AES-GCM 256）
加密后再写入 Dexie，密钥本身也存在 IndexedDB 里（浏览器原生支持存储 `CryptoKey` 对象），
但因为标记为不可导出，就算有人能读到这台设备的 IndexedDB 文件，也拿不到明文密钥本身去解密。
命令要真正被服务器接受，还要求这台设备持有一个未过期、未撤销的**设备租约**（`device_leases` 表，
24 小时有效期，`POST /api/auth/device-lease` 在联网成功同步时自动续期）——这是为了让"这台设备离线时
产生的命令，是不是真的被这个 workspace 的 owner 授权过"这件事有据可查，而不是任何猜中
`deviceId` 格式的请求都能冒充。

## 6. 冲突处理

跟第 5 节是同一个机制的另一面：如果 A 设备在线时已经把某个作业从 `ready_for_human` 推进到别的状态
（比如已经开始执行、已经完成），B 设备却是在离线时基于"还没开始"的旧状态点了"开始执行"，
B 联网后这条命令回放到服务器会被服务器**拒绝**（`EXECUTION_NOT_STARTABLE`，HTTP 409）——但拒绝的方式
不是静默丢弃，也不是覆盖 A 设备已经做的事，而是被 `classifyReplay` 归类成 `"conflict"`，
进 Dexie 的 `conflicts` 表。

在 `/offline` 页面（或首页的离线横幅）能看到冲突列表，每条显示原始命令的内容、失败原因、失败时间，
可以"复制原文"（把这条命令想做的事复制出来，方便手动确认要不要重新做一次）或者"丢弃"
（确认不需要了，从本地队列清掉——这不影响服务器上的真实状态，那早就是 A 设备写定的了）。

## 7. Codex 执行（后台作业与令牌）

材料准备（手册设计、检索、撰写三个 Skill）和里程碑闸门判定（`crossline-milestone-gate`）
由 worker 在后台 tick 里自动跑，也可以在 Workbench/Review 页面点"重新准备材料"/"现在判定"手动触发一次。

**这一步背后发生了什么**：web 和 worker 是两个独立进程，worker 单独监听 3211 端口跑 Codex supervisor。
点按钮触发的请求，从 web 发到 worker 之前，会用当前这次请求真实的 session 派生出的
`AccessContext`（`principalId`/`workspaceId`/`role`）现签一个**30 秒有效期**的 HMAC capability
token（`CROSSLINE_SUPERVISOR_CAPABILITY_SECRET` 签名，跟 `BETTER_AUTH_SECRET`
是两个独立的密钥，一个泄漏不会连累另一个），worker 那边逐路由校验这个 token——过期、
重放（同一个 `jti` 用过第二次）、`operation` 和实际请求的路径不匹配、worker
重启后旧的 `supervisorBootId` 不再有效，四种情况都会被拒绝。也就是说，**不是任何能连到本机
3211 端口的进程都能让 worker 去跑 Codex**——这个洞（阶段四之前任何本机程序都能直接打
3211 端口）已经堵上了。

## 8. Graph 连接（工作日历只读同步）

设置页「日历与连接」的「读取的日历」卡片列出已登录账号下的所有日历，勾选想作为固定日程进入计划的那些
（新登录的账号默认只勾其默认日历，不会一次性把"中国节假日""生日"这类日历也拖进计划）。
worker 按 15 分钟一个 tick 增量拉取，同一模块的「日历」卡片显示今日导入数、最近一次变化，以及 Crossline 日历的写入账户是否已设置；
「计划」页的「立即同步日历」可手动触发一次（真的等结果再刷新页面）。

这条链路当前是**只读**——`GraphReadSource` 这个类结构上就没有任何写方法，跟负责写入的
`MicrosoftGraphConnector`（写回锁死在一个名字精确匹配 `"Crossline"` 的日历/列表上，目前这条写回路径
本身还是关闭的）完全分开。

## 9. 撤销设备

设置页「日历与连接」的「离线设备」卡片列出这个 workspace 曾经签发过离线租约的每一台设备（本机标「本机」，
其他设备按顺序标「设备 N」），点「撤销」。

**这一步背后发生了什么，以及它不做什么**：撤销只影响第 5 节说的那件事——这台设备离线时产生的命令，
下次联网后还能不能被服务器接受（`revokeDeviceLease` 把这条租约标记为已撤销，`isDeviceLeaseValid`
判断时直接拒绝）。它**不会**让这台设备当前登录的 session 立即失效（那是账号本身的安全设置，
如果设备丢失、需要连登录状态一起切断，应该去改密码或者用账号安全设置撤销 session，
不是这个"离线设备"列表能做到的），也**不会**清空这台设备本地已经缓存的 IndexedDB 数据——
真正把本地缓存清空的操作是"退出登录"（每个页面右上角"退出登录"按钮），
那个会把 `crossline-offline-${workspaceId}` 这个 Dexie 数据库整个删掉。

## 10. 备份与恢复

```powershell
powershell -ExecutionPolicy Bypass -File scripts\backup-crossline.ps1
```

导出账本为 JSON、连同（如果存在）`auth.db` 一起打包、用当前 Windows 用户的 DPAPI 加密、算好
SHA-256 校验值，最后把过程中的明文临时文件删掉。`auth.db` 只有在真的有人登录过一次之后才会存在——
全新安装、还没人注册登录时备份，不带 `auth.db` 是正常结果，不是备份出错。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\restore-crossline-backup.ps1 -BackupPath <加密文件路径>
```

解密、解压、用 `pnpm restore` 把账本重建成一个**新的** SQLite 文件（不会碰 `data\crossline.db`
这个真正在用的文件），然后**真的**把每张表读回来验证——如果备份里带了 `auth.db`，
也会同样重建并读回 `user`/`session`/`account`/`verification` 四张表的行数。
替换掉正在用的 `data\crossline.db`/`data\auth.db` 是一步刻意保留的人工操作，脚本不会替你做这一步。

## 11. 采访、画像与文件

**先设主线**：新账户的第一屏是主线设定：写下身份名词（研究者、创业者……，避免「学习者」这类太宽的身份），拖动排出未来 12–24 个月的主次（不排的为平行），最多两条标为硬约束。硬约束主线的固定日程是日历骨架、截止优先、决定可用时段，访谈也先问它。之后可在「主线」页增删、改名、换色、调整主次；新增的主线会单独做一轮该主线的访谈（`/onboarding?line=<id>`）。

**分阶段访谈**：定向 → 现状 → 指南针 → 能量 → 主线 → 细节，顶部显示所在阶段。每一轮是一批互不依赖的问题，逐条作答（单选、多选或自由填写）。访谈过程中右侧实时显示画像；到「主线」阶段，每条主线会有一段个性化描述和多个「成为 ___ 的<身份>」长期目标候选，可勾选、修改或自己添加。你口述的固定安排（「每周二四上午组会」）和同步日历里的日程会作为固定日程；访谈结束时建议一套可用时段，在「计划」页确认。

**访谈如何算完成**：系统在后台按一张清单判断访谈是否完成（画像写满、有据、经本人确认；每条主线的描述与长期目标；硬约束主线的固定日程；可用时段；每个项目的目标、截止与交付证据，课程另有成绩构成和上课时间；日期确认；文件归属），清单本身不展示，访谈没做完时不会宣布完成。每一轮除了访谈自己的问题，还会加入和这一轮相关的澄清题：正在聊的课程还没说上课时间、这一轮刚上传的文件属于哪个项目、画像写好后是否符合你。

**先开始使用**：访谈页底部「先开始使用」可以随时离开；一天没有回复也视为暂离。暂离后，访谈的问题逐条列在待决事项里，可以在那里回答，本轮答完后一起交给访谈；回到访谈页回复即继续。

**过去的日期**：文件里已经过去的日期（以及「某某记录于 7/28」这类记录日期）不会作为日程让你确认，也不会排程，只作为了解进度与习惯的历史。

**Codex 与 Claude Code 使用记录**：设置 → 隐私里可以开启。开启后系统只读这两个工具会话记录里的时间和所在文件夹名，不读对话内容；统计近 30 天每个文件夹的小时数和一天中常工作的时段，交给访谈和画像报告了解习惯与进度，不用于排程。关闭即删除统计。

**主线飞轮**：每条主线是一个节点，访谈提出的每一种「这条线如何帮到那条线」是一条带箭头的边（促成、复用、提供输入、约束、反馈回路）。未确认的边是虚线，点「不成立」即删除，「成立」变实线；剩下的边形成的回路就是你的飞轮。

**画像报告**：前半部分可分享——Crossline 人格类型（深耕/跨界、实证/直觉、造物/传播、规划/应变四个维度，16 种类型、4 个类型组，每个维度附依据）、代表这一类型的卡通形象（统一风格，按你的画像定服装、道具、姿势）、几项分类标签（飞轮形态、充电方式、价值核心、工作时段、建议底座）、一段概括和图表（价值雷达、能量地图、主线飞轮与精力分配、言行对照）。后半部分是真问题、指南针与能量的文字、言行落差与锚、建议和下一步，只给自己看。前半结束处和报告末尾各有一个「分享画像」，都只分享前半部分（隐去人名、机构、课程编号）：一张 1080×1350 的类型卡片和一张前半部分长图。

**固定日程建议创建**：画像报告生成（或访谈清单完成）后，你确认过的固定安排——文件里的每周课程、带具体时间的考试，以及你在输入框里加的日程——如果你自己的日历里 60 天内没有对应事件（时间相差 15 分钟以内且名称相近即算已有），待决事项会问「日历中没有「X」，要创建吗？」，并写明它是周期性还是一次性。选「创建」后写入名为 Crossline 的日历：周期性的写成**一个每周重复的系列**，一次性的写成单个事件，都提前 10 分钟提醒；选「已在别的日历里」或「不需要」则不再问。没有时间的截止日不是事件，不会问。

**画像报告**：访谈完成后自动生成，在 `/portrait` 查看，可「重新生成」。前半部分（画像、真问题、指南针与能量、主线飞轮、言行落差）可导出分享版，人名、机构、课程号、项目名等会被隐去；后半部分（现况洞察与建议、Crossline 下一步）只在完整版里。「下载 PDF」走浏览器打印（每节一页 A4），「下载图片」导出整份长图。

采访（`/onboarding`）是账本里的一场对话（`apps/worker/src/onboarding-session.ts`），不是页面状态：消息、事实、项目、上传的文件都在 SQLite 里，所以刷新、换设备都能接着聊。

**每个事实为什么能信**：模型返回的 `confirmed` 事实必须引用本次会话里真实存在的 `reply-N`（你的第 N 条回复）或 `src-N`（第 N 份文件），并附一段**逐字**出现在那里的引文；对不上就整轮拒收并要求模型改。模型自己推断的只能标 `inferred`、引文留空，而且存储层不允许推断覆盖你已经确认的事实。

**文件**：PDF、docx、图片、文本在 worker 里抽取文字（`apps/worker/src/extract.ts`），原文件和文字都留在本机的数据目录；抽出的文字就是上面引文校验的对照物，所以抽取留在我们这一侧而不是交给模型自己读——模型读到了什么，必须能被逐字核对。

**文件里的日期**：同一轮采访里由模型读出（不另起一次调用），每个日期要带含这个日子的逐字引文，对不上的丢弃并报告。重复事件（每周一三五）由代码展开，不由模型展开；只有今天及以后的才进日历。整批确认后变成只读的日历块，日历同步永远不会改写它们。

**重新读一遍**：如果这批日期不对，在批次卡片上点「重新读」会让模型重读文件，旧批次在新批次出现后作废（只作废还没人答复的）。

## 12. 录音转写

录音（mp3 / wav / m4a / ogg / flac，上限 3 小时）在本机用 Whisper small 转写（`apps/worker/src/transcribe.ts`），音频和文字都不出本机。模型首次使用前要你点一次下载按钮——按钮写明来源（Hugging Face 的 `onnx-community/whisper-small`）和大小（约 255 MB），下载完才会开始排队转写。下载之后识别本身完全离线。

转写结果带时间戳，进入采访的来源列表，之后可以被引用。**语言自动识别**：识别前先听录音（在开头、40% 和 70% 处各取半分钟，把模型对各语言的打分加起来，避免一段静音或音乐的开头决定一切），在中文、粤语、英语、日语、韩语、德语、法语、西班牙语、俄语、意大利语、葡萄牙语里选最像的，再按这个语言识别。转写稿第一行写明「[语言：中文，自动识别]」，识别错了一眼能看出来。用 Windows 自带的中、英文语音实测：中文分数 30.2 对英文 23.7，英文 30.8 对 21.2。想固定语言，给 worker 设环境变量 `CROSSLINE_TRANSCRIBE_LANGUAGE=zh`（Whisper 语言代码）。**已知局限**：Whisper 输出中文时常是繁体字（实测「下週一的七中考試」），也会听错同音词；转成简体需要再加一个转换库，等你同意再装。

## 13. 屏幕活动与隐私

屏幕活动默认关闭，在设置页「隐私与屏幕活动」选择记录级别（关闭 / 只记分钟 / 应用与窗口）。机制与承诺：

| | 只记分钟数（v1） | 应用 + 窗口标题（v2） |
|---|---|---|
| 存什么 | 每天的活跃 / 空闲分钟数、窗口切换次数 | 另外存一段一段的「哪个应用、什么标题、什么分类、多久」 |
| 标题在哪 | 不读 | 只存在本机的 `activity_segments`；不进导出、不进备份、不发给任何模型 |
| 保留 | 长期（聚合） | 标题 14 天后抹掉，应用与分类再留到 90 天 |

**哪些窗口完全不记录**：密码管理器、银行与支付、无痕 / InPrivate 窗口、含验证码或密码字样的窗口，以及你自己在设置里加的词。这类窗口不仅不存标题，连「它开过」都不存（那一分钟只算作活跃）。规则偏宽是有意的：漏记几分钟只少一点图，误记则收不回来。

**暂停与清除**：设置页「隐私与屏幕活动」可以暂停 1 小时 / 4 小时 / 到明天（到点自动恢复），可以查看系统此刻存着的最近记录，可以一键清除所有标题。选「关闭」会同时关闭详细档。选「应用与窗口」后，同一模块画出今日每小时的活跃分钟和按类别的时长。

**用来做什么**：今日的「此刻状态」和日历里的「实际」块。「此刻状态」由规则算出（最近 15 分钟的应用分类、切换次数、有没有会议），每个读数带原因和把握度，数据不足就说数据不足。能离开本机的只有「编程 20 分钟」这样的分类时长，从来没有应用名或标题。`apps/web/lib/activity-privacy.test.ts` 在源码层面保证：除了设置页那一个路由，没有代码能读到标题，所有构造模型上下文的代码也碰不到这些记录。

**可用时段的建议**：开了详细档、观察满一周以上之后，「计划」页「时间与容量 → 可用时段」的刷涂网格旁会出现「采用活动建议」：按最近两周实际在电脑前的时间（按本地时区，每个星期几至少出现两次才算习惯）填进网格。它只填进网格，**不会自动保存**，要先「预览影响」再「应用」；它只知道人在不在，不知道精力好坏，精力档请自己刷。

**目标先由系统提，你一键改**：课程这类有评分占比的项目，系统会根据你的长期目标先提一个目标（比如总评 A−，附理由），分数线都从它倒推。在「主线」页时间轴上，课程分数线是链条末端的星形节点，点开后：合适就点「批准」；不合适从列表里选别的（A / A− / B+ / B / B− / 只要通过）或自己写，点「修改并重算草稿」，这条主线还没动过的草稿里程碑会按新目标重算。已批准的里程碑不会被自动改，它们的分数线在各自节点的右侧抽屉里直接改数值，旁边显示“最低够线”，余量不足 3% 时会提醒。暂定目标没看之前会算在「待确认」里。只有一种情况系统会直接问你：某条主线手里只有系统的猜测、没有你确认过的事实时，它会让你说说实际在做什么，或者这条线先不规划。文件里写着“待定（TBD）”的项目日期不会被当成没有这件事：它仍有一个里程碑，截止日期先按“期末前”暂定并标明待确认，你知道确切日期后再改。

**数字从结果倒推，并且留余量**：里程碑里的分数线、估时和日期不是凭感觉定的。每个里程碑先写明「你要的结果」（`plan.outcome`，如「ECE 555 总评 A」），再把倒推过程写成算式（`plan.derivation`）：总评目标 → 大纲里的占比 → 其他部分合理预计 → 这一项至少要拿多少（`bareLine`，刚好够的最低线）；真正设的线（`value`）一定在 `bareLine` 的安全一侧，至少多留 3%。没给倒推、没有余量、线正好卡在翻转点上，都会被退回重写；算式和余量显示在里程碑详情里。任务估时同理：从「验收证据要有什么」倒着拆步骤，各步之和是 p50（不加水分），余量只放在 p85（必须是 p50 的 1.2–3 倍，由最可能超时的那一步决定）；排程按 p85 留位置，计划页的预测要求按 p85 完成时比截止至少早 2 天，否则标出「没有留出余量」。

## 14. 模型用量与额度

设置页「用量与体检」的「模型用量」按功能画出近 7 天的 token 用量和每日趋势，悬停可看调用次数、平均与最长耗时、失败与重试次数；不显示模型名称。数据来自 Codex 自己上报的用量（每次调用记一行 `model_usage`）。模型按任务分三档，额度紧张时自动降档：用量到 85% 时部分功能改用更小的模型，到 100% 只跑你逐项批准的核心任务。里程碑闸门和任务分析不降档——它们弱一档的判断是错答案，不是便宜的答案。读不到额度时系统拒绝执行，而不是当成 0%。

## 15. 主线、计划与设置（2026-10 版界面）

**主线**：页面顶部是主线卡片：拖动调整主次，可设硬约束、写长期目标、换颜色、新增或归档主线。「新建里程碑」打开对话框（主线、达成的状态、截止日、目标说明），保存为草稿；也可以在任何页面的输入框里写「研究者里程碑：12 月前投出第一篇论文」。横轴是日期。里程碑是截止日上的菱形（草稿为虚线），课程分数线是链尾的星形，没有日期的放在「未定日期」区；里程碑之前的圆点是刻度（步骤的阶段结果）：实心为已达成，空心为计划中，错过的显示为空心「已顺延」并在原日期留淡点。顶部统计条显示本周达成刻度、跨主线复用和最近截止。点任一节点打开右侧抽屉：截止日与重要性就地修改，验收标准是四段圆环，分数线是子弹图（余量不足 3% 时提醒），下面是任务与步骤树、跨主线关系（说明与证伪条件，可批准或撤销）和推导；全部标准达成后出现回顾卡，填写的回顾进入个人偏好。草稿在时间轴上方按主线列出，可整条批准或撤销；抽屉里还能改标题、补验收标准、归档，已归档的在页面下方恢复为草稿。链内依赖是带箭头的弧线，跨主线关系按来源主线着色并标出类型，悬停里程碑会高亮它的全部关联。

**日历归类**：同步进来的日历事件和文件里确认的日程，不需要手动分类：每次同步后系统会读标题和时间，把它们归到对应的主线（例如课程、组会归到研究者），日历上按主线着色；个人事务、节假日或看不出归属的保持无色。同一个标题（每周重复的课）只判断一次；主线改名或新增后会整体重新归类。

**计划**：日历下方依次是每周容量图（所述投入 / 可用时段 / 本周已排 / 待完成）、未来 8 周图（每周可排时长与各里程碑的通常、保守完成日和截止刻度）、「排程依据」表（优先档、重要性滑块、截止日、首个时段与未排入原因；改重要性或截止日先预览影响；任务库单列，写明各任务哪天排入）以及「时间与容量」三项设置：周 × 半小时的可用时段刷涂、四个排程参数（任务间隔、每日最高占用、单段专注上限、截止前缓冲）、每个已批准里程碑的 0–100 重要性滑块（系统预设由主线主次与硬约束、跨主线关系、后果规模与本人历史调整算出，悬停可见各项分值）。所有改动都先「预览影响」，再「应用」。

**设置**：左侧分类为通用、时间与提醒、自动化与助手、个性化、日历与连接、隐私与屏幕活动、用量与体检，全部为点即生效的分段控件。助手的每类工作是「关闭 / 逐次审阅 / 自动」三档：自动表示自检全部通过的产出直接算完成，被退回或自检失败一次即回到逐次审阅；对外发送、付款交易、代为承诺始终由本人完成。助手待审阅的产出、新类别请求与运行中的许可请求都在「待确认」页。

## 16. 个人偏好与任务原型

向小助手纠正分类、步骤顺序或估时，填写里程碑回顾，手动修改估时或重要性，手动确认标准，驳回跨主线关系——这些都会记为「个人偏好」，之后的分析、步骤拆分与里程碑设计都会参考。设置页「个性化」按来源列出全部偏好，可逐条删除，删除后不再使用。

任务原型扩充：系统按周期（默认每两周，可改为每月或关闭）或积累满 20 条新偏好时，根据已拆分的任务与偏好联网归纳新原型，每个都必须基于至少两个本人任务和一个能打开的公开来源。新原型与内置的 18 个一起供步骤拆分选用，可在「个性化」中删除。

## 17. 输入框、撤销与任务库

**一个输入框**：今日页的输入框就是小助手，右下角的「小助手」是同一段对话的展开视图（当天的对话在电脑和手机上相同，换一天开一段新的）。写什么都行：新任务、改截止或时长、推迟、「第一步做完了」、回答待决事项、「撤销刚刚的不等了」、日程、长期目标、里程碑、新主线、精力、关于自己的话，或者直接提问。系统会查你的任务、待决、计划和文件，然后：提问直接回答；要改动的列成一张**理解卡**——每一项写明动作和对象，点「执行」（多项时「全部执行」）才生效，每一项都可在卡上或顶栏撤销，「不用了」则一项也不做；意思不明确时在框下**追问一句**并给出选项，点选项即执行对应的动作。没有任何一句会被默认当成新任务。只想记一笔不是任务的事（「记一下：……」），它只留在对话里，在小助手面板顶部的搜索框可以找到。模型暂时不可用时，原话照样保存在对话里，卡片会提供「作为新任务收集」。拖入或粘贴文件（PDF、Word、文本、图片）时，系统先读出文件内容，再说明它是什么并提议怎么处理：课程大纲或进度表交给访谈读出日期（到「待确认 · 文件中的日期」确认）；作业题目挂到对应任务（任务的步骤会按题目重新安排），没有对应任务时提议新建；讲义、论文挂到用到它的任务或归入项目；你自己完成的成果作为证据提交（尚未开始的任务会先开始）；扫描件和图片读不出文字时会问你它是什么。也可以让它写一个脚本或表格并「保存为任务材料」，或按你的描述新增里程碑模板。断网时输入仍按原方式收集为任务。任务弹窗里的输入框是同一段对话，但只显示在这个任务里说的话，「这一步做完了」「用了 40 分钟，卡在第三题」都指这个任务的当前步骤。卡片上的日期、任务、时长、主线等可以点「修改」直接改；也可以接着说「不对，是周五」，上一张卡会被撤下。这两种更正都会记进「设置 → 个性化」，以后照此理解，可删除。系统没把握或一句话改动多处时，会先给出卡片并用更强的模型再核对一遍（卡片上会写明），核对完才能执行。访谈页的回答只进访谈。

**主动提醒**：当天第一次打开时，对话以当日要点开头（固定安排、排给工作的时段、三天内截止的任务、最紧急的待决事项，可以直接点选回答）。此后系统只在这些时候主动开口：关系到一周内截止的时段开始前 15 分钟；这样的时段结束后还没开始（会顺延，也可以推到明天或去补记）；某个两周内截止的任务按保守估时余量已不足一天，或已经来不及；计时超出这一步通常时长的一半；助手做完了待审阅的成果、准备步骤已备好、新提案已分析好。计时中、开会时、刚回答过不到 20 分钟时只说紧急的；每天的条数跟随「设置 → 通知」档位（时段开始提醒不计）。每条都有「少问这类」，点了这一类一周内不再出现；连续三条都没理会，也会安静三天。页面开着时提醒出现在对话里和右下角气泡上；十分钟没打开页面时，改为发到电脑和手机。

**用输入框安排日程**：写「周三下午 3 点和导师开会」「每周二四 7:00–7:45 健身到年底」或「明天找个 45 分钟和师兄对数据」。系统区分周期性和一次性：写了「每周」的成为每周重复的系列（必须写明时间，未写结束日期默认 12 周）；没写时间的一次性日程由系统在你的可用时段里找第一个够长的空档，优先不占已排任务的时间。加入后只做**局部重排**：与新日程冲突的任务块重新排，其余任务块一周内原地不动；结果写明重排了几个。日程同时写入 Crossline 日历，可在顶栏撤销。

**撤销**：所有改变状态的操作 24 小时内可撤销：操作后的提示条、顶栏「撤销」菜单（列出最近的操作）、Ctrl+Z，或在输入框里用一句话说要撤销什么。撤销一次后该操作离开列表，不能重复撤销。

**任务库**：每个已批准的里程碑都会被倒推出任务（每 15 分钟最多三个里程碑，按截止日由近及远）。所属里程碑三周以后才截止的任务先放进任务库，不排程也不出现在「下一步」；进入三周窗口的那天自动排入。「任务」页的「任务库」折叠区和「计划」页的排程依据都写明每个任务哪天排入。如果入库太晚会来不及，计划页的预测会标出截止风险。
