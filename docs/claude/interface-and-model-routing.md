**Model routing is more than a table** (`packages/codex/src/model-policy.ts`, `usage.ts`, `skill-runner.ts`). A Skill's route can be overridden per Skill (`SKILL_OVERRIDES`, empty since the one-model table: the input box's old `medium` override would now raise it above its tier's `low`; `CROSSLINE_ROUTE_<SKILL>="model[:effort]"` pins one) and carry its own `maxRepairs`. When the quota is tight (`budgetPolicy` says `economy`, read through `setSpendModeProvider`, cached for a minute, an unreadable quota counts as normal) a Skill **steps down one tier** instead of being refused, except the gate and the capture analysis (`NEVER_DOWNGRADED`): a weaker reading of either is a wrong answer, not a cheaper one. Runs are paced by the model gate, not by a line per tier (2026-10-19, docs/model-scheduling.md; the per-tier lanes made one account's backplans and step plans strictly serial): only the assistant keeps a line of its own per runtime (`agentLanes`) and two turns on one thread never overlap (`threadLanes`); switching a Skill on and off is held in one short line (`underConfigLock`) because that rewrites the runtime's one config file, and is ref-counted (`holdSkill`/`releaseSkill`), so two runs of one Skill may overlap and the last to finish switches it back off. Every run reports `thread/tokenUsage/updated` totals to `setUsageSink`; the worker writes them to `model_usage` (per workspace, attributed through `enterUsageWorkspace` — the supervisor sets it from the verified capability, the tick loops set it per workspace) and Settings shows the last seven days per Skill. The old `ModelTier`/`model-tiers.ts` (never wired to anything) is gone.

**Manualbooks (phase 3, `apps/worker/src/manualbook.ts`, `packages/core/src/manualbook-schema.ts`, `safe-fetch.ts`).** A work order in `preparing` gets a per-task book in `CROSSLINE_DATA_DIR/materials/<workOrderId>/` (`manifest.json` with checksums, `flow.json`, `manual.md`, `nodes/<id>/{task,analysis,tutorial,sources}`) instead of one file. Three Skills in sequence: `crossline-manualbook-designer` (top tier) lays out the steps as a **DAG** that must cover every required `materialContract` item (`validateManualDesign`, `topologicalOrder`); `crossline-material-researcher` (mid, web) finds sources for each step that needs them; `crossline-material-writer` (mid) writes the step from those sources only. The worker, not the model, decides what is real: every source must be a public https URL that **actually opens** (`safeGet`: DNS public-host check on every hop, size/type caps; a title the model claimed must match the page), and the full text is downloaded only when the host passes `openAccessVerdict` *and* the model did not say no — everything else is `summary_only`. A write-up may cite only the source ids it was given and may not contain a URL of its own. `requiredApproval("download_open_access")` is `automatic`, `download_other` is `never`. A failure writes `materials.blocked` with a typed code; it never leaves half a book that looks finished. The task detail shows the book as a contents list (`TutorialView layout="toc"`: a row per person's step, opened in place, the current step open) and `/materials/<id>` reads it whole; both are served by `/api/work-orders/[id]/manualbook` and `/materials` (`manualbook-view.tsx` is gone). The assistant's outputs are cleaned before they are shown (`app/materials/humanize.ts`: no local paths, hashes, sizes, extensions or internal codes; hashed sources are named from `source_documents`; tables keep at most four readable columns), and Markdown renders `$…$`/`$$…$$` with KaTeX (`trust:false`, strict; a failure shows the source). Evidence: `scripts/manualbook-check.ts` (real Codex, throwaway DB; 2026-10-02: 6 steps, 6 verified sources, 9 minutes, checksums match). **Only marked steps are researched** (2026-10-21, replacing 「every step is researched」 of 2026-10-09): the designer marks `needsResearch` (now optional) and at most `MAX_RESEARCHED_STEPS` (3) are researched; a step with the same title reuses research already done — the interrupted draft (`<id>/.research-draft.json`), the task's previous book, or the project's other books within 30 days, links and summaries only. A book's steps are written in one writer conversation (Codex's `prompt_cache_key` is the thread id, so a new thread is a cold cache): the first turn carries the shared material, each later turn only the next step, without repeating `$skill`; a lost thread is reopened, the thread is released at the end, and source ids carry the step (`n<k>-s<m>`). Measured over the hosted ledger's first 19 hours: 43 tutorial runs, 1.69M input of which 0.58M uncached, 5 builds for 3 books; estimated after: about 0.7M input, 0.16M uncached. A page that answers 401/403/429 exists but refuses automated readers: it is kept as `kept: "unverified"` — link and the researcher's summary, labelled 「未能自动核实」 — instead of being dropped; anything else that does not open is still dropped. A real ECE 548 tutorial had one researched step out of seven and both of its sources dropped (a faculty page 403, a rating site 429).

**Screen activity (phase 5; `packages/core/src/activity-state.ts`, `apps/worker/src/activity-{source,recorder}.ts`, table `activity_segments`).** `ActivitySource` is the interface (`start(onReading)`/`stop()`), so a wearable or phone is another implementation later; the Windows one is a single long-lived PowerShell reading, every `CROSSLINE_ACTIVITY_INTERVAL_SECONDS` (60), the foreground app, its window title and the idle time — nothing else. `createActivityTracker` offers each reading to **every workspace** (the recorder used to be bound to `personal-crossline`) and each decides from its own settings, re-read per reading: `localActivity.consent` = daily aggregates only (the original promise: no app, no title), `localActivity.consentV2` = segments with app and title, `localActivity.pausedUntil`, `activity.blacklist` (the person's own words), `activity.rules`. A window matching `isPrivateWindow` (banking, password managers, InPrivate/incognito, …) is **not recorded at all** — not title, not app, not that it was open; its minute still counts as active in the aggregate. Titles stay on the machine: `ActivitySegment` (what core and the web read through `listActivitySegments`) has **no title field**, `exportSnapshot` blanks them, they are blanked after 14 days (minutes/app/category stay, rows go after 90), and `recentActivityEntries` is read by exactly one route — the settings card that shows the person what is kept, with 清除所有窗口标题. `apps/web/lib/activity-privacy.test.ts` is the discovery test: it fails if any other file reads titles or if anything that builds a Codex context touches the segments. `inferWorkState` is rules, not a model (focused / switching / in_meeting / away / leisure / mixed / unknown, each with reasons and a confidence; under five tracked minutes is `unknown`); the Today chip and the day timeline's 「实际」 blocks exist only with the V2 consent. `categoryMinutesOnly` is the only shape that may ever go to a model. The work-category segments (minutes and category only) also feed measured capacity and the inferred outcome of a block (`apps/web/lib/measured-capacity.ts`), which the privacy test allows: it is not a model context.

**The Crossline calendar (Phase 3 of the assistant; `packages/connectors/src/crossline-calendar.ts`, `apps/worker/src/calendar-publish.ts`, `apps/web/lib/calendar-publish.ts`).** The user's hard constraint: never alter a calendar they set by hand. `CrosslineCalendarWriter.#assertWritable` is the single gate for every non-GET: it allows creating a calendar named exactly `Crossline`, creating events in that calendar, and PATCH/DELETE only for ids just read back carrying the extended property `crosslineBlockId`. An owned event whose content no longer matches the hash in the ledger (`calendar.published` setting) was edited by the person and is left alone; deletes are future-only; events are `showAs: free`. **Two boundary changes the person chose on 2026-10-06:** (1) `requiredApproval("write_focus_block")` is `automatic` — `apps/web/instrumentation.ts` runs `autoPublishPass` (`apps/web/lib/auto-publish.ts`) every ten minutes as a `system-job` context and publishes when the blocks' hash changed (off with `CROSSLINE_AUTO_PUBLISH=off`, in vitest and in e2e); the button stays. (2) Reminders: work blocks remind 10 minutes ahead, and two marker kinds are written beside them — `followup:<waitingId>` on a waiting item's follow-up day and `deadline:<milestoneId>` two days before an approved milestone's deadline, each reminding at its start. The ledger records the reminder written; a reminder the person changed by hand is theirs (the content still follows the plan). What may be written did **not** move: only the calendar named Crossline, only events this app made and the person has not changed, deletes only in the future, `proposed:`/`optional:` blocks never. There is no approval gate any more (2026-10-12): the plan takes effect by default, so a new meeting no longer freezes the calendar on an old schedule. The writer's account is a separate device-code login (`scripts/graph-write-login.ts`, scopes User.Read + Calendars.ReadWrite) stored in `calendar.write.account`; the read-only sync keeps its read scopes. `calendar-sources.ts` drops any calendar named Crossline from the catalogue and the selection so the plan never reads its own blocks back as constraints. Google Calendar is not read; see `docs/calendar-write-setup.md`.

**Calibration is one residual model** (`packages/core/src/calibration.ts`, `workspaceCalibration` in `crossline.ts`). It learns `ln(actual / analysis p50)` with hierarchical shrinkage (overall toward 0, line × kind toward overall, k=5), 60-day half-life, half weight for another analysis version, an empirical-85th-percentile p85 once there are 20 residuals, and is applied only after a rolling backtest **against the frozen raw estimate** beats it by 10% in log error without worse p85 coverage; otherwise the screen says it is still learning. It replaced `effectiveEstimate` (a per-kind average that discarded the task's own estimate) and `calibrateEstimate` (an unshrunk global ratio). Analysis v2 no longer receives `historicalStats` or `rhythm.planActualRatio` — handing the model a correction and correcting its output again counted the bias twice; it gets `referenceClass` (raw past estimates and actuals) instead. Migration 10 adds the analysis estimate, source (`timer`/`one_tap`/`activity`), context version and `censored` to `duration_observations`, backfilled from work orders; an observation sums every session of the order and is one row per order. Completion offers one-tap durations (≈估时/一半/多一半/两倍/自填, plus the screen record's suggestion with the detail consent). The real ledger had zero observations on 2026-10-06, so nothing is calibrated yet.
- **Byproducts** (analysis `byproducts[]`, `#materializeByproducts`). At most one per other line, a concrete artifact, capture steps done during the main task (in its p50) and a short landing. Approving the main order creates `landing-<order>-<line>` on the other line: own milestone, own evidence (the gate judges each separately), default-effective, scheduled after the main order is handed in with a two-day window and the lowest tier.
