- Gate 4 (Codex material prep): done (real run on the live ledger, 2026-09-16). `apps/worker/src/manualbook.ts` builds a manualbook (see Phase 3 below) for work orders sitting in `preparing` — the old single-shot `crossline-material-preparer` is gone; `apps/worker/src/milestone-gate-runner.ts` invokes `crossline-milestone-gate` for work orders in `evidence_review`. **Both now run on the worker tick and both have a run-it-now supervisor route** (`/v1/work-orders/:id/prepare-materials`, `/v1/work-orders/:id/milestone-gate`, each answering 202 and finishing in the background) behind the 重新准备材料 and 现在判定 buttons — until 2026-09-16 the gate existed only inside `scripts/gate-loop-check.ts`, so on the real ledger nothing ever judged a submission. Neither job is retried on a timer: `pendingMaterialWorkOrders` and `pendingMilestoneGates` both apply last-word-wins over a `…blocked`/`…retry_requested` pair, and the gate additionally treats a revoked acceptance as closed, or the next tick would re-judge the same evidence and undo the revocation.

  **What `pass` means.** The gate answers one question: did this work order deliver what its own `evidenceContract` promised? It used to require every required measured criterion of the whole *milestone* to be met by one submission, which on a real ledger is almost never true — correct work came back 「证据不足」 and blocked. The milestone's criteria are still judged, all of them, and every judgement appends `milestone_gate.judged`; that is the milestone's progress record (best reading per criterion wins) and is what the Milestones and Review pages show. `applyMilestoneGate` throws `GATE_ALREADY_APPLIED` on a spent idempotency key rather than writing an acceptance audit for a transition that did not happen.

  Three things that check keeps honest, each of which it got wrong once: `validateMilestoneGateResult` takes the work order's **own** `evidenceContract` and requires every requirement back verbatim with a non-null `satisfiedBy` — `contractCoverage.every(...)` alone is satisfied by an empty array, so the gate could be passed by reporting nothing. A verbatim quote is demanded only for `met`/`partial`; `unmet` and `unverifiable` carry an empty `evidenceQuote`, because there is no text to quote for something the evidence does not contain and an unmet milestone criterion is now the normal case. And the two run-it-now routes detach through `runDetached`, not `void p.finally(...)` — the latter still propagates the rejection, and since Node 15 an unhandled rejection terminates the process, so one click on an order the store then refused would have taken the worker down.

**Calendar via apps (probe 2026-10-12, `scripts/apps-probe.ts`).** The local Codex runtime reads calendars through ChatGPT's connectors, called deterministically with `mcpServer/tool/call` (server `codex_apps`) on a thread — no model turn. On the owner's runtime: Google Calendar, Outlook Calendar (the connected Outlook is the UW `wisc.edu` account, which also holds the current `Crossline` calendar), Gmail, Outlook Email, Drive and Notion are installed and callable; one read takes 0.75–3.3 s. **Connecting is a real path without the directory** (`packages/core/src/calendar-apps.ts`, supervisor `GET /v1/apps/calendar` → `/api/apps/calendar` → `app/connectors/calendar-apps.tsx` in 设置 → 日历与连接). `app/list` (the connector directory, `chatgpt.com/backend-api/connectors/directory/list`) is answered with a Cloudflare challenge (403) on every attempt from this runtime; why is not established (the runtime's `originator` is our `clientInfo.name`, and the official Codex desktop app's own directory cache shows that client fetching it on 2026-09-18), and renaming the client to an official one would be impersonation to get past bot detection — not done. Nothing needs the directory: Google Calendar's and Outlook Calendar's connector ids are ChatGPT's own and the same for every account (`CALENDAR_APPS`), `app/installed` says whether each is connected (`enabled`) and usable (`callable`), and `app/read` by id — which is not challenged — returns the official `installUrl` (`https://chatgpt.com/apps/<slug>/<id>`, the same address the directory carries). The card shows each as 已连接 or as a link to that page, opened in the person's own browser; 「已连接，刷新」 reads again. Only an https `chatgpt.com` address is ever passed to the page (`safeInstallUrl`). Verified 2026-10-12 against the real runtime through a throwaway supervisor; a guest runtime still needs its own run (task 0.7). Event shapes (redacted fixtures in `apps/worker/src/testing/fixtures/apps-*.json`): Google gives `my_response_status`, `organizer.is_self`, `transparency`, `event_type`, `recurring_event_id`, `original_start_time` and **no iCalUID**; Outlook gives `response_status.response`, attendees, `organizer`, `type` (singleInstance/occurrence), `series_master_id`, `original_start`, `i_cal_u_id`, `show_as`, `is_cancelled` and UTC `dateTime` strings. **Calendars by subscription link** (docs/onboarding-v3.md 「日历接入」, 2026-10-14; `packages/connectors/src/ical.ts`, `apps/worker/src/calendar-subscriptions.ts`, `packages/core/src/calendar-subscriptions.ts`, card `app/connectors/calendar-subscriptions.tsx`). The private iCal link Apple, Google and Outlook export, read-only and with no sign-in, so the installed copy (no Graph) reads calendars too. The link is a credential: it lives only in the worker's DPAPI secret store (`ical-<id>`); the ledger keeps label, host and the last read (`calendar.subscriptions`). A link is read once before it is kept (`safeGet` with calendar content types, 5 MB). `readIcal` (ical.js 2.2.1) expands recurrences with `RECURRENCE-ID`/`EXDATE`, reads file-defined, Windows-named, undefined-IANA and UTC zones, and leaves out all-day, free and cancelled events; each occurrence gets its own `iCalUid` (`uid@occurrence`) because the sync collapses items sharing one. Each subscription is one more `CalendarSource` (`ical:<id>`) in the same `createGraphSync` — no cursor, so every read is authoritative for its own blocks; ids stay `graph_calendar:ical:…` so everything that treats `graph_calendar:` as "a synced calendar event" keeps working. One syncer per workspace over Graph sources plus subscriptions (`syncCalendarFor` in the worker; subscriptions alone when Graph is absent or the login is another account's); removing one takes its blocks off the plan at once. The interview gets the coming week (`calendarWeek`) on the first turn and whenever it changed.

**Authorized folders** (docs/onboarding-v3.md 「文件夹授权」, 2026-10-14; rules in `packages/core/src/source-folders.ts`, reading in `apps/worker/src/source-folders.ts`, Skill `crossline-folder-classifier` via `folder-classifier.ts`, card `app/connectors/source-folders.tsx`, routes `/api/sources/folders` → supervisor `/v1/sources/folders*`). The person gives a path; the worker refuses a drive, the user folder, system and AppData folders and its own data, previews what it would read, then walks it without following links (skipping hidden/dependency/build/cache directories and `isSecretPath` files), copies each readable file (PDF, Word, text; ≤50 MB) into `sources/` by content hash after reading it with `extractText` (a file whose opening text holds an SSN, a Chinese ID or a Luhn-valid card number is not kept); larger files and slides/spreadsheets are kept by name only. Recordings are left alone unless 录音自动转写 is on (see 「Recordings are transcribed on this machine」): then they are queued, not read, and their index entries survive the consent being turned off. **Idle and active minutes per clock hour** (`ACTIVITY_HOURLY`, 28 days, under the daily-aggregate consent, deleted with it; `atComputerByHour`/`atComputerLines`) are what the interview's and the portrait's `workHistory` and Settings' 「电脑前的一天」 read; the daily aggregate now resumes from its stored row after a worker restart instead of restarting from zero. The tick re-walks every folder and reads only new or changed files (index `sources.folder.index:<id>`: size and mtime per relative path), forty per folder per tick. The classifier proposes lines once per folder (`linesBy: "model"`, with `linesWhy`); the person's choice (`linesBy: "person"`) is never replaced. **What is left out (2026-10-15, before the owner authorized Downloads and Desktop):** credentials are never read and cannot be ticked back, enforced in the worker (`credentialName`: api key / access key / secret / token / credential / password / 私钥 in the name's words, `.pem/.key/.p12/.pfx/.env`; `credentialText`: `sk-`, `AKIA`, `ghp_`, `xox[bp]-`, `-----BEGIN`, or a long base64/hex string beside key/secret in the first 2 KB); files that look like private papers by the words of their name and folders (`nameWords` splits camelCase, letter–digit seams and punctuation, so `YanKai9262026TaxDocs` is ` yan kai 9262026 tax docs `; `sensitiveName`: IDs, immigration and visa, SSN, bank statements, tax, proof of funds, payments and receipts, insurance and medical, offers and pay, vehicle and application forms, leases and contracts, and 个人档案 — a Chinese name beside a student number, or the account's name / a profile name fact with a long non-date number) or by the IDs in their first 2 KB (`sensitiveText`) are not read unless the person ticks them back (`include`); the person's exclusions (`exclude`: a relative path covers a subfolder, `*`/`**` globs) are kept with the folder and obeyed on every scan; copies of one content are read once; past 1000 readable files the most recently changed are read and the rest counted (`over`). The preview groups by top-level subfolder with per-group and per-file ticks and lists the suspected-sensitive apart; the card's 排除列表 edits the rules afterwards (`/v1/sources/folders/:id/exclusions`), and what becomes excluded leaves `sources` (only documents the folder itself created — `created` in the index — never an upload with the same content; the stored copy goes when no row reads it; event `sources.folder_content_removed`). Revoking stops reading and keeps what was read, unless the person picks 「取消授权并删除已读内容」 (`/purge`; event `sources.folder_revoked` with `purged`). The interview reads at most twelve new files (the 60k budget) per turn and says how many wait (`sourcesWaiting`) instead of marking clipped files as read; the step planner adds the line's folder material when a task has fewer than three files of its own.

Two rules learned the hard way: structured output runs in strict mode, so every schema object needs `additionalProperties: false` *and* every property listed in `required` (express a union with `anyOf`, not optional fields); and this runtime's `web_search` takes `disabled | cached | live` — the wrong variant fails the whole `thread/start`, which is why the flywheel could never run before 2026-09-16.
