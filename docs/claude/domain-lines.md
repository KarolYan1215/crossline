# Domain lines and records (the lite edition, 2026-10-19)

> Moved verbatim from `CLAUDE.md` on 2026-11-04. Add new notes for this area here, not to `CLAUDE.md`.

Design, decisions, research and what is reserved: `docs/domain-lines.md`. There is **no edition flag**: a line may carry `domain: "wellness" | "wealth"` (`LineSpec.domain`, `DOMAIN_PACKS` in `packages/identity-packs`), and the lite edition is only the opening card pre-filling 健康管理者 + 理财者 (+ an optional named fixed-schedule line, `hard` and the base). At most one live line per domain: `addLine`/`setupLines`/`updateLine` refuse a second with `LINE_DOMAIN_TAKEN` and the holder's `lineId` (409 from `/api/lines`), so the page and the input box (`line.add` with `domain`) offer to tag the existing one (投资者 → 财富) instead. New domain lines take the fixed ids `line-wellness` / `line-wealth` while free (`domainLineId`): never `health`, which stays the capacity pack feeding only the energy model.

- **What a domain brings.** `identityPacksFor` merges the pack: templates, `diligenceTopic` (`evidence_summary` for wellness, new; `tracking_framework` for wealth) and `noTradeCalls`. A built-in line tagged with a domain keeps its own templates and topic. `topicFor` now reads the workspace's pack (every custom line used to get `opportunities`), and the no-trade-call guard in `validateDiligence` is `noTradeCalls || id === "investment"`, never the id alone. Undated file dates fall back to the workspace's first line, not `research`.
- **Interview.** Both layers get `lines[].domain` and `domainGuides[]` (`domainGuides()`); each Skill has a 「Domain lines」 section: ask the `ask` list in order, record under the fixed `health_*` / `wealth_*` slots, never account numbers, exact balances, passwords or holdings, never a diagnosis or a dose. The five parts are unchanged.
- **Milestones.** `domainMilestoneTemplates(lineId, domain)` (six each) are seeded INSERT-OR-IGNORE the first time the architect builds a context for that line.
- **Records** (migration 18, `domain_records`; core `records.ts`, db `records.ts`, web `lib/records.ts`). One row per real event (`UNIQUE(workspace_id, dedupe_key)`), soft-deleted (`deleted_at`) so 撤销 works (`Inverse` `records.deleted`). Every source goes through `recordAndJudge`: `recordProblem` range checks, then the domain line's approved milestones are read (`recordReadings`: only a threshold in kg, % on a wealth line, or 元/a currency with `lte`; a multi-week cadence is never judged from records) and a `milestone_gate.judged` with `source: "records"` is written only when the readings changed (key carries their hash). Sources: the input box's `record.add` (card confirmed); mail triage's new `transaction` kind, kept only when `amountsInText` finds the same amount in the mail's own subject or opening (else `info`; `MailAccount.bookkeeping === false` turns it off); `POST /api/records` with the new `records` device-token scope (Wallet transactions as `records[]`, Android payment notifications as `notifications[]` parsed by code only, `recordFromNotification`); weight / kcal / workouts / Health Auto Export beside the night on `/api/health/sleep` (`healthRecordsFromPhone`); a confirmed exercise block on the health line (`recordWorkout` in `lib/confirm.ts`); a screenshot dropped into the box, which now reaches the model as an image (`images` on `runCodexSkill`/`continueSkillTurn`, sent with the first prompt only; uploads are stored as `.img`, so the worker hands the runtime a copy named by its magic bytes, `asTypedImage`). CSV, wearables and bank aggregation are reserved source names, not built.
- **Bookkeeping is one ledger of real transactions** (2026-10-28, the owner: 「最后能记一个总账，并且做好可视化，汇报花钱的情况」; docs/mail-bookkeeping.md). An expired PayPal request had been booked as 61 USD spent.
  - **Which mails are booked.** Mail triage reads `money {event, amount, amountLabel, currency, merchant, category, occurredOn, refs, last4, instrument}` for every mail about money (`MAIL_TRIAGE_SCHEMA`). Only `charge`/`receipt`/`refund`/`income` are booked (`BOOKABLE_EVENTS`); `authorization`, `own_transfer`, `statement`, `request`, `alert` and `upcoming` never are, and `failed` voids the record it matches (`voidByEvidence`).
  - **Code checks every field** (`moneyEventFromMail` in core `money-events.ts`). A veto word in the subject or on the amount's line (request, expired, pending, hold, statement, balance, 过期, 预授权, 余额 …) keeps a mail out whatever the model said; the amount must stand in the first 8000 characters of the body (`MailHeader.body`, never stored or sent to a model) beside a total's label, never a subtotal, tax or balance; order numbers and card digits must appear verbatim; the stated day is used only within the mail's window.
  - **One transaction, many pieces of evidence** (migration 22). The record is one row of `domain_records`; each mail, notification or entry is a row of `record_evidence`, unique per source item. Layer 0: `mailMessageKey` (Message-ID, else sender, subject, minute and opening), so the same mail in two mailboxes is sorted and booked once. Layer 1: `matchScore`. A shared order number scores 70; then merchant key, the same amount, the same card and day closeness add points. Hard blocks: another currency, kind or card; differing order numbers; a different amount with no shared order number; the same sender sending the same event again (two coffees); more than 10 days apart. ≥70 attaches (`recordMoneyEvidence`); 40–69 is a new record with `status: "pending_review"`, not summed, listed on the `ledger_duplicate` ask and the ledger page and counted as two after a week (`settleStaleDuplicates`). The person's own entry is `trusted`, never put aside.
  - **Refunds and other sources.** A refund is kind `refund`, linked to its expense (`refundOf`), and lowers spending in that category, never income. Phone notifications, Wallet and the input box go through the same matcher (`addDomainRecord` in `lib/records.ts`).
  - **Categories and rules.** Categories are fixed (`SPEND_CATEGORIES`, `INCOME_CATEGORIES`). The person's change can become a merchant rule (`ledger.merchantRules`, undoable); `categoryBy: "person"` is never overwritten.
  - **The ledger page `/ledger`** (`lib/ledger.ts`, `/api/ledger`, `app/ledger/`) draws:
    - this month's spent, income, net and savings rate, and the pace against the same day of last month — income, net and savings rate only while income is tracked (2026-11-11, docs/ledger-wealth.md §3.4: not under 「只记开销」 `ledger.spendingOnly`, nor with fewer than two income entries this month; then the page says income is not recorded);
    - the cumulative line against last month, the 3-month average, the limit and the month-end projection (only once spending is booked on 7 days);
    - the monthly budget (`ledger.budget` with its own `currency`, `monthlyCap`) as a meter: spent, left or over, and the pace against the budget's share of the days gone (`budgetPace`);
    - categories with last month's tick, 12 months of income and spending, and a daily heat calendar;
    - top merchants, accounts (money in and out only; balances live in 资产与负债 above), recurring charges (`recurringCharges`: weekly, monthly or yearly, at least three times, price rises flagged) and anomalies;
    - the filterable list with category change, split, merge and delete, all undoable (`records.fields` / `records.evidence` inverses).
  - **Reports.** `moneyReportPass` (worker) sends the weekly report on Monday from 08:00 and the monthly one on the 1st (`money_weekly`/`money_monthly`). They are template text from the ledger, with no model call, once per period, and nothing for an empty week. The monthly spending limit is the person's own cap (`ledger.budget`) when set, else a wealth milestone's `lte` currency threshold (`monthlyLimitFrom`); totals are in the base currency.
  - **Assets, liabilities, base currency, budgets** (2026-11-10, docs/ledger-wealth.md; migration 24). `wealth_accounts` / `wealth_snapshots` / `wealth_holdings` plus the global, derived `market_prices` cache (not exported). Balances are the person's own dated snapshots (no bank aggregation); brokerage holdings (`AAPL.US`) are valued daily from Longbridge's read-only `quote` tool through the person's ChatGPT connector, each price checked by code against the tool result (`verifiedQuotes`; any other tool voids the run); common coins from one keyless CoinGecko call a day; FX from Frankfurter v1 (ECB only), cached per day, so it works offline. Every income/expense total is converted to the base currency (`ledger.baseCurrency`, default from the zone) at its own day's rate; a currency with no rate stays out of the totals. Budgets: monthly cap + per-category caps (`ledger.budget`), no envelopes. On the 1st the `wealth_balances` ask lists accounts with no snapshot this month. The 小帮手's `wealth.update` card records a balance or a holding, confirmed and undoable (`wealth.rows` inverse). Never advice, targets or orders.
  - **Questions in the input box.** The 小帮手 answers money questions with `ledger_query` (`queryLedger`).
  - **Old records.** `repair.mail-records.v1` voided the old mail records a veto subject marks, turned refunds booked as income into refunds and merged twins, with one undo.
- **Shown** on the line card (`app/milestones/domain-records.tsx`): this month's income, spending, savings rate and top three categories, or the last 7 days' workouts and the latest weight, then the trend (`recordTrends`, 2026-10-20: six months of income and spending as paired bars, or eight Monday-first weeks of workout minutes as bars with each week's last weight as a `Sparkline`; drawn in HTML and plain SVG with the value on hover, and only once two periods hold anything), and the last 30 records with their source and 删除. The mailbox card's 「自动记账」 switch (`setMailBookkeeping`, `POST /api/mail/accounts/[id]` with `{bookkeeping}`) is what turns a bank or shop mail's amount into a record; it is on by default and only while sorting is on.
