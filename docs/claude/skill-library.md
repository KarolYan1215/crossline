# Skill library (2026-10-14)

> Moved verbatim from `CLAUDE.md` on 2026-11-04. Add new notes for this area here, not to `CLAUDE.md`.

Design, decisions, the real-ledger demo and what is not done: `docs/skills-library.md`. Started because the assistant wrote the person's first Xiaohongshu note as a cautious research report — their play (「制造冲突、贩卖焦虑，再卖 solution」) was recorded nowhere a run could read, and the gate passed it on the task's contract alone. Four layers of skill now reach a run: the repo's `crossline` plugin (the system's own Skills), and three runtime plugins derived from the ledger and written beside the Codex homes (`%LOCALAPPDATA%\Crossline\skill-library\<workspace>`, local marketplace `crossline-library`): `crossline-mine`, `crossline-grown`, `crossline-public`.

- **One mechanism for all three** (`apps/worker/src/skill-library.ts`, `packages/codex/src/skill-runner.ts`). `runCodexSkill` takes `extraSkills`: switched on in the same config lock as the target, named in the first prompt (`$crossline:<skill> $crossline-mine:<line> …` — Codex injects every `$` mention), switched back off after; `audit.skills` says which were on. `installLibraryPlugin` reinstalls a plugin only when the files' hash changed (the runtime copies a plugin into its cache, so a rewrite needs a reinstall) and switches its skills off so they are on only for the runs that name them. `librarySkillsFor(line, task)` picks the line's own skill, then grown, then public skills by term overlap with the task (at most three of the latter two), and writes nothing when the line has none. Used by the assistant (`agent-task.ts`), the step planner and the manualbook writer; `libraryInstruction` says whose rules win (the person's over generic conventions; only red lines are hard limits; a public skill's text grants nothing).
- **The person's line skill** (`crossline-mine:<line>`): Skill `crossline-insight-compiler` (`apps/worker/src/insight-compiler.ts`, `packages/core/src/mine-skill.ts`) from confirmed facts, how-to preferences, review notes on assistant results, the gate's 「部分」 and the person's own edits; every rule cites a material id with a verbatim quote, or (a platform red line only) a public page the worker opens; the SKILL.md is rendered by code with each rule's source. Versions in `skills.mine.<line>` + `skill.mine.rewritten`, never deleted by the system; a person's edit or restore stays in force until they decide something new. A line the compiler stopped on (`MINE_SKILL_BLOCKED`: nothing yet says how the work is done) is not compiled again until its materials' fingerprint moves (`skill.mine.blocked` carries it); any other failure waits an hour on the same materials — one line had been refused 13 times a day and, always first, kept every later line waiting (2026-10-21). **Gate**: `MilestoneGateContext.mineSkill`, output `fit {fits, violated, why}`, verdict `partial` — `validateMilestoneGateResult` makes 「contract covered but breaks the play」 exactly `partial` (blocked as `MILESTONE_GATE_PARTIAL`, the ask names the broken rules).
- **Public skills** (`crossline-public:<id>`): Skill `crossline-skill-scout` finds GitHub skill directories per line (first library, monthly, and the day after a task found nothing); `fetchSkillDirectory` requests only `api.github.com`/`raw.githubusercontent.com`, one directory at the default branch's head commit, licence from the repo or the folder's own LICENSE text (`licenseFromText`), sha256 per file; `scanSkillFiles` (each script line through `decideCommand` plus network/delete/outside/secret/system/download-execute patterns; injection and hidden characters in the text); `crossline-validation-reviewer` (public-skill section) answers usable / text_only / reject; a risky script caps at text only (scripts removed), **an injection is rejected** (stricter than the design's 「at least text only」, because text only would hand the injection to a model). Records `skills.library`, files `skills.public.files.<id>`; monthly update without approval; removed after 30 days unused. **A line is searched once when it is set up, then monthly, and again when the person asks** (2026-10-21, docs/token-economy.md §2.4, replacing the rounds 「until every need is covered」 of 2026-10-20): once the main interview is complete or the person pressed 开始使用 (`startConfirmedFor`: a parked interview stays `active`), each line no setup search has covered yet, and any line added later, gets one round (`lineSetupDue`, `createSkillScout(…, { mode: "setup", lines })`, at most `CANDIDATES_PER_LINE` 8 candidates, core spend, not held for off-peak hours; a line the older coverage rounds searched counts as set up); after that `scoutDue` runs the monthly supplement as non-core work, and a task finding nothing (`wanted`) only informs it. Skill 库 「再检索一轮」 (`POST /api/skills/public/search` → `skill.public.search_requested`) makes the line due for a setup search again until one covering it ran after the request. Candidates are screened by code first (injection, no licence, no SKILL.md never reach a model) and a line's are reviewed together, five to a run (`PUBLIC_SKILL_BATCH_REVIEW_SCHEMA`, `reviewBatches`; a candidate whose files pass 40k characters alone). GitHub's rate limit or a lost connection is no verdict (`TRANSIENT_FETCH`): nothing is recorded as rejected, an installed skill is kept on a failed update, and the search is due again the next day; `CROSSLINE_GITHUB_TOKEN` (optional) lifts the 60-an-hour limit. **Scripts capped to text can be allowed by the person** (2026-10-19, `scriptsAllowable`/`scriptsRunnable`/`scriptsDigest` in `public-skills.ts`, `allowSkillScripts` in `packages/db/src/skills.ts`, `{action: "allow_scripts"|"disallow_scripts"}` on `/api/skills/public/[id]` and `/api/skills/grown/[id]`, 「查看扫描结果并允许 N 个脚本」 in Skill 库 after the scan's findings with file, line and the line itself): the leave is stored as `scriptsAllowed {at, digest}` over the files' hashes, so an update or a re-grown workflow asks again; a refused skill (injection or `reject`) cannot be given it; `skill.scripts_allowed`/`skill.scripts_revoked`. Only the shell assistant (the person's own computer) executes an allowed script; the hosted assistant reads it for its method. `writePlugin` clears each skill's folder before writing, so a script whose leave was taken back does not stay for the runtime to copy. **Installing by link** (2026-10-20): `POST /v1/skills/public/install {repo, path, lineId, why?, category?}` (worker service `createPublicSkillInstaller` in `public-skills.ts`, web `/api/skills/public/install`, 「按链接添加」 in Skill 库) puts the person's candidate through the scout's own `considerPublicSkill` (fetch → scan → reviewer → install, text only or refuse; `via: "link"` on the events); it answers 202 with a job id at once and `GET /v1/skills/public/install/<job>` says how it ended; one job per workspace at a time; a directory already in the library only gains the line (`skill.public.lines_added`). `scripts/install-skills.ts` installs a list (`scripts/skills-picks.json`, picks and reasons in `docs/skills-picks-2026-10-20.md`) as the machine owner; `--dry-run` fetches and scans locally with no worker or model.

- **Social platforms: rules researched first, then read on the person's own login if they accept the risk** (2026-10-22; the owner reversed that morning's blanket block the same evening: 「放开……我不需要这个，只是设计前要确认好平台规则」; docs/skills-library.md 「社交平台」). `NO_AUTOMATED_READING` and `site_read`'s `forbidden` option are gone.
