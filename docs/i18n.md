# 中英双语界面

全站可一键在中文与英文之间切换（2026-10-16 定）。本文是规则、术语表和工作方法；守卫是 `packages/i18n/src/catalog.test.ts`。

## 决定

- 范围：私有应用和公开速测 `apps/assess` 都做。覆盖界面、系统拼出的句子、通知、邮件、海报。
- 默认中文。选择存在浏览器 cookie `crossline-locale`，登录后也存到账号（账本设置 `ui.locale`）。新设备没有 cookie 时，采用账号上的选择。
- 切换按钮的位置：
  - 每页页头（手机也在页头；2026-10-28 前在「更多」里）。切换不整页重载：写 cookie 和账号设置后 `router.refresh()` 原地重渲染，服务端组件和根布局的 `LocaleProvider` 一起换语言；组件自己取来的文字在下次读取时跟上；
  - 登录、注册页；
  - 设置 → 通用；
  - 速测页右上角。速测做到一半切换，不丢已答的题。
- 模型写的内容：
  - 已经写好的保持原语言，不翻译；
  - 切到英文之后，新内容用英文写；
  - 切回中文，已有的英文内容保持原样。
- 访谈：以开始时的语言进行到结束，画像报告也用这个语言。访谈中途界面仍可切换，页面会说明访谈继续用原语言。
- 本人写的内容一律不翻译，包括主线名、任务标题、回复。
- 海报、双人卡、邮件按读者的语言：
  - 海报和双人卡：谁看用谁的语言，按语言分别缓存；
  - 速测结果邮件：用提交时页面的语言；
  - 应用的通知、推送、验证邮件：用账号的语言。

## 机制

- **i18next，中文原文就是 key。** 写法是 `t("待确认")` 或 `t("已完成 {{n}} 项", { n })`，英文放在 `packages/i18n/locales/en/*.json`，以中文为键。
  - 中文不需要词表：找不到 key 时直接显示 key 本身，值照常填入。
  - 中文句子一改就是新 key，守卫会要求补上英文，旧译文不会默默挂在新句子上。
- **一个进程一个实例。** 各入口登记自己的词表：
  - 网页：`apps/web/lib/i18n.ts`，服务端和客户端都会引入；
  - worker：入口引入 `@crossline/i18n/catalog/worker`；
  - 速测：引入 `@crossline/i18n/catalog/assess`。
- **语言从哪来**：
  - 有请求的地方：`AccessContext.locale`，`requireAccessContext` 依次取 cookie、账号设置，最后默认中文；
  - 后台任务：`readLocale(store, workspaceId)`；
  - 没有登录上下文的页面：`getLocale()` 读 cookie。
- **英文复数**：词表里写 `_one` / `_other` 两条，例如 `"{{count}} 项_one": "{{count}} item"`。调用时必须传 `count`。
- **一个中文词对应两种英文**：用 context 区分。`t("开启", { context: "state" })` 读的是 `"开启_state": "On"`，而 `"开启": "Turn on"` 是另一条。中文侧仍显示「开启」。

## 模型写的内容

- 每次 Skill 运行都会在开发者指令末尾加一段写作风格，用的是工作区的语言（`packages/codex/src/style.ts`：`styleInstructions`、`setLocaleProvider`）。
  - worker 按每次运行读取账本的 `ui.locale`，所以切换语言后，下一次运行就生效。
  - 英文那一段明确覆盖各 Skill 里「写中文」的要求；全部 SKILL.md 的 Language 段开头也都说明了这一点。
  - 助手的 shell 线程另外加一行语言要求。
- 访谈：每个会话在第一轮锁定语言，记在 `onboarding.locale:<session>`；主访谈的语言另存为 `onboarding.locale`，画像报告也用它（`lockInterviewLocale` / `interviewLocale`）。界面切换不影响正在进行的访谈，访谈页会说明这一点。
- 长度：
  - 输出 schema 的字符串上限都是按中文定的。英文运行时，`schemaForLocale` 把每个 `maxLength` 放宽到 2.5 倍。
  - 代码里的长度检查用 `textWidth` / `clipWidth`（`packages/core/src/text-width.ts`）：含中文的文字照旧按字数算；纯英文按 2.5 个字母折一个字。所以中文的行为一点不变，英文任务名可以长到 60 个字母。
- 未登录时选的语言：登录后如果账号还没选过语言，就写进账号（`requireAccessContext`），后台通知和模型调用才会跟着变。

## 字体

画像页的衬线标题（`.pt-serif`）：
- 中文用 Noto Serif SC 子集；
- 英文用自托管的 Source Serif 4 拉丁子集（700 与 400 字重，SIL OFL，许可证见 `apps/web/public/fonts/poster-serif-latin.OFL.txt`）。它就是中文字体自带拉丁字母的来源设计，两种文字放在一起像同一套字体。
- 只在 `:lang(en)` 下启用，中文页面一个字形都不变。

速测海报的英文只用 ASCII，由现有的海报字体子集覆盖。

## 写法

| 位置 | 写法 |
|---|---|
| 客户端组件 | `const t = useT();` 然后 `t("保存")`（`app/locale-context.tsx`） |
| 有 ctx 的服务端组件、路由、lib 函数 | `const t = tOf(ctx);`（`lib/locale.ts`） |
| 没有 ctx 的服务端页面（登录、注册、离线） | `const t = tFor(await getLocale());` |
| 只读、不该变成客户端的共用框架 | `<Say text="更多" />` |
| `packages/core` 中拼句子的函数 | 加 `locale?: Locale` 参数（有选项对象就放进去，没有就加在最后），函数内 `const t = tFor(locale)`。默认中文，旧调用和测试行为不变 |
| worker | `tFor(readLocale(store, workspaceId))` |
| 速测 | `apps/assess/lib/i18n.ts`（速测自己的 cookie 读法与 `useT`） |

规则：

1. **一句话一个 key。** 不用翻译过的片段拼句子，英文语序不同：
   - 错：`t("已完成") + n + t("项")`
   - 对：`t("已完成 {{n}} 项", { n })`
2. **标签表保留中文值，在显示处翻译。** 例如 `RELATION_KIND_LABEL[kind]` 仍是「促成」，显示时写 `t(RELATION_KIND_LABEL[kind])`。
   - 守卫只能查出每个中文字面量都有英文，查不出显示处漏了 `t()`；漏掉的要靠英文截图走查发现。
   - 所以标签宁可在构造处就翻译：拿得到 locale 的地方，直接返回译好的文字。
3. **JSX 文字和 JSX 属性一律包 `t()`**，包括 `title`、`aria-label`、`placeholder`、`alt`。
4. **日期与时间**：
   - 日期用 `monthDay(locale, day)`，得到「10月17日」或 "Oct 17"；
   - 星期用 `weekdayShort(locale, n)`；
   - 并列用 `joinList(locale, items)`；
   - `Intl` 一律用 `intlLocale(locale)`；
   - 两种语言都用 24 小时制。
5. **不是界面的中文不翻译，要标出来**：
   - 哪些算：与模型或本人文字比对的正则、与账本存量数据比对的值、给模型的指令、日志、测试夹具；
   - 怎么标：该行或上一行写 `// i18n-ignore`；大段用 `/* i18n-ignore-start */ … /* i18n-ignore-end */` 包住；整个文件都不是界面时，在开头 40 行内写 `// i18n-exempt: <原因>`。
6. **读中文的启发式规则要补英文。** 例如 `stepLeavesMachine`、`PERSONS_CALL`、`questionKind`、课程代码正则。英文界面下，本人和模型都会写英文，所以要：
   - 在同一规则里加上英文写法；
   - 中文行为保持不变；
   - 中英各补一条测试。
7. **账本里存的字符串**：
   - 已经写进事件或设置的文字，按原语言显示。
   - 新写入、且只用于显示的文字，按写入时的语言生成。
   - 拿来做比对的值不能翻译（例如 `「与「X」合并」` 这类存量标记）。

## 英文风格

- 按英文产品惯例写：
  - 按钮用祈使句，句首大写其余小写，例如 "Approve all"、"Start timer"；
  - 状态写成名词短语，例如 "3 decisions · earliest Oct 9"；
  - 可以用 "you"，但少用。
- 美式拼写；标点用英文，不留全角符号；范围用 en dash，例如 "14:00–15:30"。
- 时长写作 "45 min"、"1 h 30 min"；数量带单位并区分单复数，例如 "1 task"、"3 tasks"。
- 中文原句如果过于依赖语境，英文按意思写，不逐字翻译。
- 英文通常比中文长 30%–60%，要做到：
  - 不写死宽度；
  - 按钮可以换行；
  - 窄卡片在手机宽度下检查一遍。

## 守卫

`pnpm vitest run packages/i18n` 检查以下各项。

源码（测试和夹具除外）：

- 没有中文 JSX 文字，也没有中文 JSX 属性；
- 没有带 `${…}` 的中文模板字符串；
- 每个中文字面量都在 `locales/en/*.json` 里有英文。

词表：

- 是合法的 JSON；
- 英文值不为空，也不含中文；
- 两边的 `{{占位}}` 一致；
- 同一个 key 在各文件里的英文一致；
- 所有翻译完成后，没有过期的 key。

翻译某一区域时，用 `I18N_SCOPE=apps/web/app/settings pnpm vitest run packages/i18n/src/catalog.test.ts` 只看该区域；路径按整段匹配，`apps/web/app/connect` 不会匹配到 `connectors`。`PENDING` 已清空（2026-10-16），守卫现在对全部源码生效，也检查过期的 key。

英文界面另有端到端检查 `e2e/english.spec.ts`：
- 逐页在桌面和手机宽度下检查 `lang`、页框是英文、没有横向滚动、文字互不重叠；
- 每页截一张全页图，存到 `ENGLISH_SHOTS_DIR`。

`apps/web/lib/english-pages.test.tsx` 在单元测试层渲染英文账户的六个主页面，去掉账本里本人的内容之后，不许再剩任何中文。

英文词表按区域分文件，各区域只改自己的文件。下列文件归属如下：

- `common.json`：页头、导航等全站共用的文字，由总负责人维护；
- `core-a.json` / `core-b.json`：`packages/core`；
- `assess.json`：速测；
- `web-*.json`：网页各区域；
- `worker.json`：worker 和其余各包。
