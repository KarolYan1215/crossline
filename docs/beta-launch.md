## 1. 和 MBTI 拉开差距：海报设计

**依据。** 网易云「人格主导色」把简化版 MBTI 换成颜色，结果文案大量夸奖，又把 16 种人格分成「吸引 / 远离」来制造讨论，结果成了社交开场白，很多人吐槽不准照样转发。SBTI（2026 年 4 月）用自嘲标签对抗 MBTI 的「精英标签」，一度崩服，高仿版本很快稀释了热度。分享的动机主要有三种：显得与众不同、塑造理想形象、表明属于某个群体。

**定位。** 和 MBTI 是互补关系，不是替代：MBTI 回答「你是谁」，这张海报回答「你怎么同时活好几条线」。

**海报正面（3:4，1080×1440，适配小红书多图）。**
1. 漫画形象：类型的基础角色 + 本人外貌；底色是组别颜色。
2. 类型名 + 四字母代码 + **狠一点的副标题**。
3. 四条轴的百分比。距离中线 ±10 以内的字母用浅色，表示「两可」。
4. **推荐主线和飞轮图**：这个类型最适合同时推进的 3 条主线，以及它们之间如何互相供养（例如「研究 → 课程 → 内容 → 研究问题」）。图下面一行写「在 Crossline 里把这几条线真的跑起来」。
5. 最佳搭子类型、最容易吵架的类型。
6. 估算排位：只印最突出的一条轴，「你的跨界倾向约超过 X% 的人（理论估算）」（超过 95% 的显示方式见 §2.4）。
7. 页脚：二维码就是**本人的邀请链接**：朋友扫码做题，做完自动生成你们的双人卡（§1.1）。小字注明「基于自评的趣味测评，非心理诊断」；品牌只放在最下方。

### 1.1 双人对比卡：只靠邮箱 + 转发链接，不需要账号

**依据。** 爆款默契测试都是「发起人做题 → 链接或海报转发 → 好友答完 → 合成结果卡」：网易哒哒的「来拆穿我的瞎话吧」最高每小时 400 万访问。有篇实测文章指出一个常见卡点：结果要等对方回传，对方不回，发起人就看不到合卡。Clearer Thinking 的人格测试也是可选分享结果、和朋友自动并排对比；PrinciplesYou 则要求双方都有账号，摩擦大得多。

**流程。**
1. A 做完题、填邮箱，服务器保存结果，同时生成两个随机令牌（各 128 位）：结果令牌（看自己的结果）和邀请令牌（给别人用）。
2. 结果页和海报二维码都指向 `/t/<邀请令牌>`。可选填一个署名，默认「你的朋友」。
3. B 打开链接，先看到「署名 邀请你测测你们是什么关系」和 A 海报的公开部分（类型、形象、四轴），然后做同一套 32 题，再填自己的邮箱。
4. 服务器按规则算出两人的关系（§2.3），生成双人卡：两个形象并排、关系名、两条相处建议、两人推荐主线的交集。B 当场看到。
5. A 收到邮件「TA 完成了，来看你们的双人卡」（A 的勾选框默认勾选）；A 从邮件里的结果链接回来，能看到所有和他做过对比的人（最多 20 个）。B 也拿到自己的邀请链接，可以继续往下传。

**解决「等对方回传」的卡点。** 合卡在 B 做完的那一刻生成，B 当场就能看到，A 由邮件通知，没有人需要等对方再操作一次。

**隐私与安全**（参考 W3C 的能力 URL 实践）：
- 链接用不可猜测的随机令牌，全程 HTTPS；
- 这些页面不加载任何第三方脚本，设 `Referrer-Policy: no-referrer` 和 `noindex`；
- 邀请页只露署名和公开海报，**永远不显示邮箱**；
- 令牌随结果保存 90 天，本人删除结果时一起失效；
- 同一个邮箱对同一个邀请只算一次，按 IP 和邮箱限频，计分在服务器上重算。

**海报上的简要版。** 正面只写「最佳搭子：XX 型」「一起做事容易吵：XX 型」，各配一句建议；详细的留给双人卡。

**双人对比卡。** 对方用邀请链接做题后自动生成：两个形象并排，标出两人的关系名和两条相处建议，再加上两人推荐主线的交集。

### 1.2 海报渲染（W3，2026-10-14）

**为什么在服务器上出 PNG。** 微信内置浏览器里，`<a download>` 和脚本触发的下载基本没有反应，长按保存只对页面上真正的 `<img>` 有效；前端 canvas 导出还会遇到跨域图片、安卓上 base64 / Blob 图片长按存不下来等问题。所以海报、长图、双人卡都由服务器画成 PNG，页面用 `<img src="/api/poster/…">` 展示（依据：阿里云开发者社区 developer.aliyun.com/article/906395、jb51.net/article/250735.htm、掘金 juejin.cn/post/6885952653075939335，均为经验文章，上线前要在安卓和 iOS 微信里实测）。

**做法。**
- satori 0.33.5 把元素树排版成 SVG，文字转成路径；@resvg/resvg-js 按 `fitTo: { mode: "width", value: 1080 }` 栅格化，不加载系统字体。satori 只支持 flex 布局和它列出的 CSS 子集（`display` 只有 flex / block / none，`position` 支持 absolute，支持 `borderRadius`、`opacity`、`textWrap: balance`），字体只认 TTF / OTF / WOFF，**不认 WOFF2**；没有给到的字形会被直接丢掉（只回调 `loadAdditionalAsset`），不会换成别的字体（satori 自带 README）。图片用 data URI 嵌入并写明宽高，免去渲染时的 I/O；形象文件按开头字节判断 PNG / JPEG，WebP 等 satori 解不了的格式退回类型模板，再不行就在圆里写四字母代码。
- 字体：Noto Sans SC、Noto Serif SC（SIL OFL 1.1，来自 github.com/notofonts/noto-cjk），用 `scripts/assess-poster-fonts.ts`（subset-font / HarfBuzz）裁成子集放在 `apps/assess/fonts/`，许可在 `OFL.txt`。黑体两个字重收全部固定文字 + GB2312 一级 3,755 字 + ASCII（每个约 1 MB），宋体两个字重只收固定文字（每个约 235 KB）。昵称里子集没有的字符印成「·」，不会悄悄消失。改了类型名、副标题、主线、关系或海报文字后要重跑脚本，测试会提醒。
- 样式沿用画像海报的「编辑杂志」：纸色 #F6F2EA、墨色 #1E1B16、灰 #4F4A42，节与节之间用墨线分隔；1080 宽时没有小于 24 px 的字。测试遍历 16 种类型的海报和长图、256 种双人组合的卡片，检查文字不重叠、不出画布、不小于 24 px。
- 缓存：PNG 存在 `dataDir()/posters`，文件名是版式版本、类型视图、昵称、邀请链接和形象文件字节的哈希，换了形象就是新文件；海报上有昵称，所以文件写入一周后删除，之后再请求就重画。路由返回 `Cache-Control: private, max-age=300`、`Referrer-Policy: no-referrer`、`X-Robots-Tag: noindex`，未知或过期的令牌给 404。字体加载后，单张海报在本机约 0.2–0.5 秒。
- 部署（交给 W2 的 `next.config.mjs`）：`@resvg/resvg-js` 是原生模块，要列进 `serverExternalPackages`；`fonts/**` 要用 `outputFileTracingIncludes` 带进 standalone 产物（或设 `ASSESS_FONTS_DIR`）。

### 2.3 关系（按两人在四条轴上的异同，由规则推出，覆盖全部 16×16 组合）
| 关系 | 条件 | 相处建议（草稿） |
|---|---|---|
| 复刻搭子 | 同一类型；只差一条轴时作为第二种关系 | 默契高、盲区也一样；重要决定找一个类型不同的人看一眼。分工别重叠，不然两人抢同一件事 |
| 进度条之争 | 规划 / 应变不同 | 约定里程碑，不约定每天的计划。规划的人给出底线日期，应变的人决定怎么到达 |
| 挖井的和修路的 | 深耕 / 跨界不同 | 跨界的人定方向，深耕的人定标准。别让跨界的人一周换三次题目 |
| 做的人和讲的人 | 造物 / 传播不同 | 最佳产品搭档：一个做、一个推。提前分好功劳，署名写清楚 |
| 数据党 vs 直觉党 | 实证 / 直觉不同 | 争论前先说好：什么证据能让你改主意。直觉提出假设，数据负责验证 |
| 开坑联盟 | 都是直觉 + 应变 | 一起开新坑很快乐；指定一人负责收尾，每开一个新坑先关一个旧坑 |
| 双保险 | 都是实证 + 规划 | 稳，但容易错过机会；每月留一点「冒险预算」，允许一件事没有数据就开始 |
| 镜像对手 | 四条轴都不同 | 不是最好就是最差；先合作一个两周的小项目试试，再决定要不要绑在一起 |

只差一条轴时，那条轴的差异是主关系、「复刻搭子」是副关系（否则「数据党 vs 直觉党」永远当不了主关系）。其余情况按「镜像对手 → 开坑联盟 / 双保险 → 进度条之争 → 挖井的和修路的 → 做的人和讲的人 → 数据党 vs 直觉党」取第一条为主关系、第二条为副关系。海报上的「最佳搭子 / 最容易吵架」按每种组合的预设分数取最高和最低。

### 2.4 估算排位
- 每条轴的得分按理论分布 N(50, 15) 换算成百分位，卡上写「约超过 X%（理论估算）」。
- 测评人数满 200 后，改用自有数据的经验分布，同时去掉「理论估算」字样。
- 封顶（2026-10-15 本人定）：算出来超过 95% 时，显示 91–96 之间的一个数，由结果 id 和轴的哈希决定（`shownRank`）。同一份结果每次打开都一样，在页面、海报、长图、双人卡上一致；强偏好的人不会都晒出同一个 99。真实分布启用后同样封顶。
- 类型占比在满 200 人前不显示。

## 3. 测评流程
1. 落地页：一句话说明「你怎么同时活好几条线」，约 4–5 分钟。
2. 32 题：每条轴 8 题，其中 4 题反向计分，Likert 1–5。题库在现有 16 题基础上扩充，计分沿用 `quizScores`。
3. 外貌：3–4 个选择（发型、眼镜、肤色、风格）+ 1 个可选填空，只用于生成形象。
4. **填邮箱**，下面写明用途：「邮箱只用来：找回你的结果，以及朋友做完双人卡时通知你。不发营销邮件」「加入 Crossline 内测后，用同一个邮箱登录，这次结果会自动带进 App」「结果保存 90 天后自动删除；结果页和每封邮件里都有「删除我的结果」」；勾选框「把结果链接发到我的邮箱」**默认勾选**；可选填昵称。带进 App 的接口见 [assess-deploy.md](assess-deploy.md)「与 App 的结果连接」。
5. 结果页：先出类型和基础形象，个性化形象生成好后替换。导出 3:4 海报和长图，海报二维码就是本人的邀请链接。
6. 「邀请 TA 测」→ 朋友做完当场生成双人对比卡，本人收到邮件通知（§1.1）。从邀请链接进来的人走同样的 1–5 步，只是落地页换成「署名 邀请你测测你们是什么关系」。

### 3.1 页面做法的依据（W4，2026-10-14 检索）

- **一屏一题、自动前进、可以后退。** 一项随机对照实验（计算机问卷的「下一题」按钮与后退按钮）发现：自动前进和按「下一题」相比，缺失数据和量表信度没有差别，按钮版多花约一半时间，作者建议自动前进并保留返回上一题。另一项分支问卷研究也发现逐题自动前进最快、自动滚动让人迷失方向。Qualtrics 与 SurveyMonkey 都把一屏一题作为默认做法。所以：选完停 0.26 秒让人看到所选，再进下一题；「上一题」始终在；键盘 1–5 作答、Enter 下一题。
- **进度条按整套 32 题计，不按小节归零。** 关于进度条和完成率没找到对照研究，厂商意见不一（长问卷里进度条可能劝退）；共识只有一条：显示全程进度，小节之间不要重置。外貌和邮箱两步另写「最后两步 · 1 / 2」。
- **单选组用原生 `<input type="radio">`。** WAI-ARIA APG 的单选组模式规定方向键在组内移动并选中；原生单选框由浏览器提供这些行为和读屏语义，无需自写 roving tabindex。由此有一条细节：方向键只改选择、不自动前进（否则按方向键浏览选项会一路跳题），点击、轻触、空格和数字键才前进。
- **微信里保存图片。** 微信内置浏览器不允许 H5 页面用脚本或下载链接保存文件，但对 `https` 地址的普通 `<img>` 长按可以「保存图片」；base64 / blob 图片有长按保存失败的报告。所以海报和双人卡都是服务器渲染的 PNG 地址，直接放 `<img>`，手机上写「长按图片保存」，有鼠标的设备才显示「下载海报 / 下载长图」（`download` 属性）。两者用 CSS 的 `(hover:none) and (pointer:coarse)` 切换，服务端渲染和浏览器不会对不上。
- **分享。** 先检测 `navigator.share`，有就显示「分享邀请」；用户关掉分享面板（`AbortError`）不算失败；其余失败退回复制。「复制链接」始终显示（藏起来用户会以为没有这个功能），在点击处理里直接调用 `navigator.clipboard.writeText`，失败就选中链接文字并提示手动复制；结果写进 `aria-live` 区域。
- **360 px 手机优先。** 单列、两侧 16 px；输入框字号 16 px（iOS 小于 16 px 会放大页面且不复原）；可点区域至少 44 px；正文不小于 12 px，灰字 #4F4A42 在纸色上约 7.9:1。

来源：[Next/back 按钮实验（eScholarship）](https://escholarship.org/uc/item/3557w1mn)、[分支问卷研究（UMD）](https://drum.lib.umd.edu/items/89eb861e-8e4e-4b44-a221-fa73a901ee3e/full)、[SurveyMonkey 一屏一题](https://help.surveymonkey.com/en/create/one-question-at-a-time/)、[GuidedTrack 进度条](https://docs.guidedtrack.com/research-guide/building-user-friendly-surveys/progress-bar/)、[W3C APG 单选组模式](https://w3.org/WAI/ARIA/apg/patterns/radio)、[微信 H5 无法下载图片（阿里云开发者社区）](https://developer.aliyun.com/article/906395)、[微信开放社区：base64 图片长按保存失败](https://developers.weixin.qq.com/community/develop/doc/0000a8c4cbce10fd356391fa566400)、[W3C Web Share API](https://www.w3.org/TR/2022/WD-web-share-20220607)。

## 4. 形象生成
- **基础角色**：16 个，每种类型生成 3 个候选，由本人挑选，作为该类型的参考图，存进代码库。画风自己设计，不模仿 16Personalities。
- **用户形象**：在类型模板（参考图）上按外貌描述做图生图小改动，作为免费福利，费用由本人承担。按第三方报价约 0.008–0.06 美元一张（官方人民币价未核实），每个邮箱限 3 次。
- **防爆量**：设每日预算上限；超限或排队太久时，直接给该类型的基础形象。服务器要能扛住突发访问，避免网易云那种 503。
- **访谈后**：按访谈内容重画个性化形象，作为注册的奖励。

### 4.1 形象流程的实现依据（W5，2026-10-14 查证）

**硅基流动接口**（官方文档：[创建图片生成请求](https://docs.siliconflow.com/cn/api-reference/images/images-generations.md)、[生图模型](https://docs.siliconflow.com/cn/userguide/capabilities/images.md)、[速率限制](https://docs.siliconflow.com/en/userguide/rate-limits/rate-limit-and-upgradation.md)、[错误处理](https://docs.siliconflow.com/en/faqs/error-code.md)；`docs.siliconflow.cn` 上的同名页面目前返回 404，内容以 `docs.siliconflow.com` 为准）：
- 接口：`POST {base}/images/generations`，`Authorization: Bearer <key>`，JSON 请求体。国内地址 `https://api.siliconflow.cn/v1`（文档示例用的就是它），国际站 `https://api.siliconflow.com/v1`。
- 图生图模型 id：`black-forest-labs/FLUX.1-Kontext-dev`。它的请求体必填 `model`、`prompt`、`image`，可选 `seed`（0–9999999999）和 `prompt_enhancement`（默认 false）；**没有** `image_size`，输出尺寸跟随参考图。参考图字段是 `image`，格式是 `data:image/png;base64,…` 字符串。注意 Kontext pro/max 的字段名是 `input_image`，换模型时要一起改。
- Kontext [dev] 必须带参考图，所以出模板候选（纯文生图）改用 `black-forest-labs/FLUX.1-dev`（`image_size: "1024x1024"`，`num_inference_steps` 1–30）。
- 返回：`{ images: [{ url }], timings: { inference }, seed }`。**图片链接只有一小时有效**，必须立即下载保存。
- 错误：429 是限流（消息里写明是 RPM/TPM/IPM/IPD 哪一项）；503/504 是负载过高，稍后重试；400 是参数错，401 是 key 没设对，403 多半是模型要求实名认证。
- 限流：图片模型按 IPM（每分钟张数）和 IPD（每天张数）计，最低一档是 **IPM 2、IPD 400**，按账号（不是按 key）、按模型分别计算，消费越多档位越高。
- 价格：模型页标价 **0.015 美元/张**（[模型页](https://www.siliconflow.com/models/black-forest-labs-flux-1-kontext-dev)，国际站美元价；人民币价未核实）。每天 300 张，最坏约 4.5 美元/天。

**保持角色不变的提示词写法**（Black Forest Labs 官方：[FLUX.1 Kontext 图像编辑](https://docs.bfl.ml/kontext/kontext_image_editing.md)、[单参考图编辑](https://docs.bfl.ml/guides/prompting_editing_single_reference.md)）：Kontext 擅长多次编辑后保持角色一致；指令里先写清楚改什么，再**逐项列出不变的东西**（不能只写「其余不变」）；颜色用十六进制色值；要保留的细节直接点名，例如「keep her pose」「Preserve its identity」。所以提示词是固定英文：只改性别呈现、发型、眼镜、肤色（附色值）和衣服版型，然后逐项写明不变的部分：画风、线条粗细、平涂颜色、姿势、比例、表情、构图、服装颜色、道具、背景和圆形底。`prompt_enhancement` 关掉，避免平台改写这段固定指令。

**用户自填文字的安全处理**（[OWASP LLM 提示注入防护速查表](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)）：这份速查表要求多层防护，也明确说**只靠分隔符或标签分不开指令和数据**；它把不可见字符夹带列为一种攻击方式。所以填空不是原样拼进提示词，而是：
1. NFKC 规范化，去掉所有控制字符和不可见字符，截到 40 字，去掉网址和邮箱；
2. 读起来像指令（「忽略以上」「你现在是」「system」等）或涉及不安全内容（裸露、血腥、武器、仇恨符号、像某个真人），就**整条丢弃**；
3. 剩下的文字只提取固定词表里的外貌词（发色、帽子、围巾、耳环、雀斑、胡子、刘海、马尾……），翻译成固定的英文短语，最多 4 个，用引号标明是描述，不是指令。

这样，词表以外的任何字都进不了提示词。邮箱、署名和答案从来不进提示词。

**排队与重试**（[AWS 架构博客：指数退避与抖动](https://aws.amazon.com/blogs/architecture/exponential-backoff-and-jitter/)；`Retry-After` 见 RFC 9110）：进程内队列，并发 2（对应最低档 IPM 2），最多 40 个排队，再多就直接给模板。每次调用 60 秒超时。只对 429 和 5xx（含超时）重试**一次**：有 `Retry-After` 就按它等，加不到 1 秒的随机抖动；没有的话，429 等 20–40 秒，5xx 等 2–5 秒。400、401、403 不重试。

**费用护栏**：每日上限 `ASSESS_IMAGE_DAILY_LIMIT`（默认 300，低于最低档 IPD 400），按北京时间自然日计，存在 `dataDir()/avatar-budget.json`（原子写入，重启不清零）。**每次调用模型都占一个名额，重试也算**，所以计数只会多算、不会少算。另有每个邮箱最多 3 张（`AVATARS_PER_EMAIL`）。没有 key、超出上限、队列满或调用失败，都立即给该类型的模板，结果页永远不会因为画图而卡住或报错。

**下载生成的图片**：只接受 https，每一跳重定向都检查，地址里不能带账号密码；最大 12 MB，内容必须是 PNG/JPEG/WebP；下载时不带 API key。

**实现位置**：`apps/assess/server/avatar/`（`provider.ts` 接口、`prompt.ts` 提示词和填空处理、`queue.ts`、`budget.ts`、`templates.ts`、`placeholder.ts`）、`apps/assess/app/api/avatar/[file]/route.ts`、`scripts/assess-templates.ts`；模板与审定流程见 `apps/assess/templates/README.md`。

### 4.2 16 个基础角色怎么设计（2026-10-14）

本人要求：抽出每种类型的核心特征，体现在外貌上，参考 MBTI 和 SBTI。两者都只取做法，不照搬形象：

- **16Personalities 的做法**：每种类型一身「角色服装 + 招牌道具」，同组共用一套颜色。角色由 Zeda Labs 绘制，作品集按 Sentinels、Analysts 等分组整理，说明颜色体系以组为单位（[Zeda Labs 作品集](https://dribbble.com/zedalabs/projects/240402-16-Personalities)）。虚拟角色研究发现，服装（颜色、款式、类型）比动作更能细致地改变观者对角色性格的判断（[MDPI 2024，服装对虚拟角色性格感知的影响](https://payment.mdpi.com/2813-2084/3/1/2)）。所以性格主要靠服装和道具表达。
- **SBTI 的做法**：B 站 UP 主做的恶搞版人格测试，27 种类型全是自嘲式网络梗标签，结果配可分享的形象卡片，靠「被说中缺点」传播（[ai-bot.cn 介绍](https://ai-bot.cn/sbti-test/)、[星岛报道](https://www.stheadline.com/zh-hans/lifetips/3560918/MBTI已经过时内地搞笑版人格测试SBTI爆红-27种自嘲式人格-背后藏暖心理由)、[香港01 报道](https://global.hk01.com/数码生活/60340864/sbti人格测试爆红-恶搞版mbti测出荒诞标签-网-imsb是在骂我)）。所以每个角色要把副标题里的缺点**演出来**。

于是每个角色由五部分组成（`scripts/assess-templates.ts` 的 `LOOKS`）：
1. **核心特征**：一句话，取自类型名和简介；
2. **服装 + 招牌道具**：表现长处（钟表匠的放大镜和镊子、改装师的胶带与扳手）；
3. **一个自嘲笑点**：把副标题的缺点画出来（试验家口袋里拖到画外的实验记录、旗手腋下一片空白的日程本、探险家每个口袋都插着地图和票）；
4. **姿态**：四个字母各对应一种身体语言——S 收拢专注、G 敞开且挂满东西；E 在测量和记录、I 抬头、有灵光；M 手里有工具、R 张嘴比划；P 扣好扣子、左右对称、A 松散、在动；
5. **表情**：随类型变化，不再统一「冷静自信」。

几条不变的规矩：
- 同组共用组别色和底色；
- 半身构图，满底色，内容都在中心圆里，因为海报会把图裁成圆；
- 发型简单中性，不戴眼镜，个人外貌之后再按描述改；
- 图里没有任何文字，纸和屏幕上只有空白或抽象线条；
- 画风是平涂加墨线，不用 16Personalities 的低多边形和切面上色。

每种类型出 3 张候选：一张按描述画，一张换更有动感的姿势和角度，一张把笑点再夸张一点。

**第二轮（同日，本人看过第一轮 48 张后改）**：本人更喜欢 MBTI 测评那种人物的脸、身材和画风，要全身像，每种类型男女各一版，并给个性化留足余地。于是：
- **画风**：改为 MBTI 测评头像那种全身、低多边形切面、每个面平涂柔和阴影、修长约六头身、小头、极简五官（小黑点眼、细眉、小嘴）、脚下一圈柔和投影，提示词里直接写「in the style of popular MBTI personality-test avatars」。只借画风；服装、道具和笑点仍是自己的，提示词也写明「不是任何已有角色的复制」。第一轮的平涂墨线风格作废（图存在本机 `candidates/v1-waist-up/`）。

  - 四组的颜色改成莫兰迪色（`TYPE_GROUPS`，私有 app 的画像也跟着变）：工匠组灰绿、求索组豆沙玫瑰、架构组雾霾蓝、开拓组陶土。每组三个值：`tone` 是人物服装的主色（中等明度、低饱和），`tint` 是底色，`colour` 是同色相的深色，用于文字，在海报纸色上不低于 7:1（`packages/core/src/portrait-type.test.ts` 检查）。避开了 MBTI 那套紫、绿、蓝、黄。
  - 每个角色另加体型（紧凑、修长、敦实、轻快……）和男女各一种发型，姿势都改成「动作进行中」：单膝跪着雕刻、踮脚转圈、一脚踩工具箱、被螺旋桨带离地面、边走边回头挥手等，让 16 个人一眼看出是 16 个不同的人。

**这次为 Linux 做的改动**
- `CROSSLINE_STATE_DIR` 是 POSIX 路径时按 POSIX 拼接（`codexProcessEnvironment`）。
- Codex 用上游同一标签 rust-v0.155.0 的 Linux 发布版，按 `CODEX_LINUX_RELEASE_BINARY_SHA256` 固定哈希；fork 唯一的改动是 Windows 迁移修复。
- 密钥存储在 Linux 上改用 AES-256-GCM，主密钥放在 `CROSSLINE_SECRET_KEY`（`createKeyFileSecretStore`）。
- 机主专用的功能（屏幕活动、键鼠节律、作息、桌面通知、读文件夹、Codex 使用记录、带 shell 的助手）在 `CROSSLINE_PUBLIC_BETA=1` 时对**所有账号**关闭，机主也不例外（2026-10-16 走查发现）：之前机主的账号在服务器上仍算「电脑主人」，助手的 shell 和文件夹授权会落在装着所有人账本的服务器上，守卫只是绊线不是沙箱。`assistantAvailable` 与 worker 的 `machineOwner` 在这个开关下都返回否。
- 多人同时用时不崩（2026-10-16，本人决定不升级 2 GB）：整台服务器同一时刻最多跑 2 轮模型（`CROSSLINE_MODEL_CONCURRENCY` 可改），其余排队，访谈和输入框优先、后台任务让路，访谈页显示「排队中，前面还有 N 个」；worker 内存超过上限的 75% 时不再启动新的模型调用和新的 Codex 进程，先回收空闲进程；其他账号的 Codex 进程同时最多 2 个、空闲 10 分钟回收，正在跑的不回收，第三个人等其中一个空出来（不再报「连接已满」），排队中的任务若其进程被让出，轮到时自动重启；worker 预编译后用 node 直接跑，web/worker 设了 Node 堆上限，排程只用贪心（不开 HiGHS 求解线程）。代价：几个人同时做访谈时每轮要多等前面几轮，不会挂。
- 网页按队列渲染（2026-10-16）：10 个登录用户同时开页面时 280m 的 web 容器两次因内存被杀、两成页面 502；现在 web 通过 `apps/web/queue-server.mjs` 运行，页面渲染同时最多 2 个（`CROSSLINE_WEB_CONCURRENCY`）、其余排队，容器内存超过 80% 时先等手头的完成，静态文件和写操作不排队；容器上限改为 assess 300m、web 400m、worker 550m（合计 1.25 GB）。压测脚本 `scripts/load-assess.ts`、`scripts/load-app.ts`。
- 主机升到 3.5 GB / 2 核（2026-10-17，本人升级）：`run.sh` 按主机 `MemTotal` 选档，3.2 GB 以上为 worker 1500m（同时 4 轮模型、4 个访客 Codex 进程，后台最多 3 个）、web 700m（同时渲染 3 个页面）、assess 450m（海报同时 3 张），合计 2.65 GB，给系统留约 850 MB；低于 3.2 GB 仍是原来的 1.25 GB 档。防崩溃机制不变：容器硬上限、不用 swap、worker 内存 75% 高水位、超出时排队而不拒绝。CPU 没有增加，页面渲染受 2 核限制，比内存更早成为瓶颈。`app.env` 里手工设了并发值的以手工值为准。
- 给交互预留一个模型位（2026-10-17）：托管版后台任务（里程碑设计、画像重写、拆步骤……）最多占 `上限 − 1` 个位置（`CROSSLINE_MODEL_INTERACTIVE_RESERVE`，默认 1），访谈和输入框总有一个位置可用，不会排在占满两个位置的后台任务后面。代价：后台任务一次只跑一个。
- 出图只按账号限（2026-10-17 本人决定）：测评每个邮箱 3 张（`AVATARS_PER_EMAIL`），不再设每天总数（`ASSESS_IMAGE_DAILY_LIMIT` 不填即不限，部署时从 `assess.env` 删掉旧的 300）；App 里用服务器方舟 key 画的画像形象每个账号 3 张（`CROSSLINE_IMAGE_PER_ACCOUNT`，计数在 `portrait.imageDraws`，删除不退回；用本人 Codex 画的不计）。成本上限因此随人数线性增长：100 人做测评最多 300 张。
- 备份（2026-10-17）：`deploy/server/backup.sh` 每天 19:17 UTC 用 SQLite 在线备份 `crossline.db`、`auth.db`、`assess.db`（逐个 `integrity_check`），连同账本旁的文件打包，保留 14 天（文件包保留 3 份），由部署时 `backup.sh --install` 装进 `/etc/cron.d`。异地：`server.yml` 每天和 `[backup]` 时把最新一份连同两个 env 文件经 openssl（AES-256，PBKDF2）加密成工作流制品，保留 30 天；需要仓库密钥 `BACKUP_PASSPHRASE`，没设就不上传。
- 删除账号与隐私说明（2026-10-17）：设置 → 通用 → 删除账号（输入账号邮箱确认，机主账号与本机安装版不提供）删除工作区的所有账本行（按表结构找出所有带 `workspace_id` 的表，`purgeWorkspace`）、只属于它的上传文件、材料、画像形象、模型 key 文件、服务器上的 Codex 登录和 Better Auth 账号；测评结果不在其中，用结果邮件的删除链接。`/privacy` 是公开的隐私说明，登录页有链接；`CROSSLINE_CONTACT_EMAIL` 设了才显示联系邮箱。
- 部署只从 `main`（2026-10-17）：`images.yml` 只在推送 `main` 时构建并覆盖 `:beta`，`server.yml` 的提交信息动作（`[deploy]`、`[server]`……）也只认 `main`。
- 测评站多人同时做（2026-10-16）：海报同时最多渲染 2 张（`ASSESS_RENDER_CONCURRENCY`），其余排队；形象同时画 3 张（`ASSESS_IMAGE_CONCURRENCY`），方舟出图通常 25–40 秒、下载 1–2 秒，但偶尔一次调用卡住（实测 293 秒、超过 300 秒，重试 24 秒就好），所以每次调用 100 秒没回就放弃重试，一轮最多 3 次（日志 `answeredSeconds`/`downloadSeconds` 记录出图与下载各自耗时），排队超过 60 个才改用模板，页面提示人多时要排队；结果邮件走 2 条连接的连接池排队发送，邮件服务暂时拒收（4xx）会在 30 秒、2 分钟、10 分钟后重试；同一出口 IP（教室、宿舍、运营商 NAT）每小时可提交 120 次、写「想做的事」120 次；assess 容器 300m（25 人同时测时峰值 168 MB）。
- 三个容器都有内存上限且不许再用交换分区（assess 300m、web 400m、worker 550m，合计 1.25 GB；服务器实际只有 1.6 GB，第一版上限合计 1.7 GB，部署拉镜像时整机又卡死了一次；主机要配 2 GB 交换文件给系统兜底，worker 的 Codex 运行时是它的子进程，算在它头上）。2026-10-16 走查时里程碑设计、画像重写和生图同时跑，没有上限，整机换页到 Caddy 和 SSH 都不应答，两个站一起挂；超限时改为 Docker 杀掉并重启那一个容器。重启后的 worker 若拿到和上次相同的 pid，不再把自己留下的锁当成「已在运行」。
