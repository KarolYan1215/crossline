# 设备模式：托管站是唯一主账本，本机只做本机的事

2026-10-22，本人决定。

## 问题

本人的账号此前有两份：托管内测（app.crossline.lol）上的一份和这台 Windows 电脑上常驻版（127.0.0.1:3210）的一份，靠 `scripts/ledger-sync.ts` 每小时把「本人最后操作的那一边」整本复制到另一边。两边的 worker 各自跑同一套倒推、步骤规划、助手任务，用的是同一个 ChatGPT 额度；一边的结果随后被另一边覆盖。额度花了两遍，结果只留一遍。

## 决定

- **托管站是唯一的主账本。** 计划、任务、访谈、邮箱、日历、助手、所有模型工作只在托管站做。
- **本机降为这个账号的一台「设备」。** 只做必须在这台电脑上做的事，结果立即发给托管站；不再整本复制账本。
- 定时的整本同步停止：「Crossline Ledger Sync」计划任务已于 2026-10-22 停用。`scripts/ledger-sync.ts`、`pack-for-server.ts`、`migrate-workspace.ts` 保留，只用于一次性搬迁。

## 连接

1. 托管站 设置 → 通用 →「这台电脑」：点「生成设备令牌」。令牌只显示一次，托管账本只存它的 sha256（`device.token.sha256`，与健康、收集、记账、录音令牌同一种做法，`issueDeviceToken(ctx, "device")`）。再生成一次，旧令牌立即失效；「撤销」删除它，设备的下一次发送就被拒绝。
2. 本机打开 `http://127.0.0.1:3210/device`（设备模式下唯一留在本机的页面），填托管站地址和令牌，点「连接」。本机先用令牌请求一次 `GET /api/device/hello`，通过才保存：
   - 地址存在 `data/device/link.json`（不是机密，网页据此判断设备模式）；
   - 令牌用 DPAPI 加密存在 `data/secrets/machine/device-token.bin`（`createDpapiSecretStore`，只有这个 Windows 用户能解开，不进账本、不进备份）。
   选择文件而不是环境变量：本人在页面上就能连上和断开，不用改启动脚本；令牌也不会出现在进程环境里。
3. 保存后 worker 自行退出，常驻的守护循环（`keep-running.ps1`）几秒后以设备模式重新启动它。断开（同一页面「断开」）同样重启回完整模式。

## 设备模式下本机做什么

只有这些，且都不调用模型：

| 本机的事 | 怎么做 | 发给托管站 |
| --- | --- | --- |
| 屏幕活动、作息（长时间空闲）、键鼠节律 | 原有的活动读取器写进本机暂存账本，规则不变 | `POST /api/device/activity`：每天合计、按小时合计、长空闲段、键鼠刻钟合计、按类别的时段，和各项同意的状态 |
| 授权文件夹 | 原有的文件夹读取，规则（排除、私密文件、凭据）不变 | `POST /api/device/sources`：每个文件的文字、文件名、原文件 sha256、所属文件夹；排除后发删除 |
| 本机录音 | 本机 Whisper 转写 | `POST /api/device/recordings`：转写文字和录音的 sha256、时长 |
| Codex/Claude Code 使用记录 | 原有的时间汇总 | 随活动一起发（只有汇总） |

暂存账本就是本机原来的 `data/crossline.db`、原来那个工作区：同意开关、文件夹授权和排除规则都留在本机（文件夹路径只在这台电脑上有意义），在 `/device` 页面设置；发出去的只是结果。

### 录音：本机转写，只发文字

两条路比过：上传音频到托管站的收件箱，或本机转写后只发文字。选后者：

- 一小时录音的音频几十 MB，文字几十 KB；
- 托管站的转写容器只在夜里跑、750 MB 内存，本机的 CPU 闲着也是闲着，转写不花任何额度；
- 音频不离开这台电脑，比上传更少暴露。

托管站收到后照常写 `recording.transcribed` 事件（以录音 sha256 为键），所以同一段录音若又从手机上传，托管站认得出来，不会再转一次；之后的摘要（模型工作）由托管站做。

### 隐私

- 窗口标题、应用名永不离开本机。按类别的时段里，应用只以「本机随机盐 + 应用名」的哈希前 8 位表示，只用来数「切换了几次」，托管站不知道是什么应用；本机暂存账本里的标题照旧 14 天后清空。
- 文件夹里被排除的、疑似私密的、含凭据的文件本机根本不读，也就不会发。
- 某项同意关掉时，托管站删掉这一项已收到的数据（与本机「关掉即删除」一致）。

## 不做的事

设备模式下本机 worker 不启动 Codex，不跑：收集分析、倒推、步骤规划、教程、验收关卡、访谈、邮箱、日历同步与写入、助手、自动化、夜间飞轮、通知推送。网页的后台循环（自动发布日历、待决快照、主动提醒）在设备模式下也停。

## 已知的损失

- **能在电脑上执行命令的助手**（`crossline-agent`，danger-full-access）只能在本机跑；设备模式下没有它，托管站用的是工具模式的助手。现在不做代理。
- **Crossline 日历写入（Microsoft Graph）**原来由本机的写入账号完成；设备模式下本机不再发布。需要时在托管站另行设置，或改用订阅日历。
- **桌面通知**：本机不再弹 Windows 通知；提醒走托管站的网页推送（手机、浏览器）。
- **文件夹自动归线**是模型工作，本机不做；文件到托管站后按文件名归项目（规则，不用模型）。本人在 `/device` 页面给文件夹选的线会随文件夹信息一起发过去。
- 小红书收藏读取等「读本人登录」的工作流以后再接到设备上，这次不做。

## 发送：本地发件箱

- 每件要发的东西先写成 `data/device/outbox/` 下的一个文件，再发送；发送成功才删。断网、托管站重启都不丢。
- 每件带一个幂等键（请求头 `Idempotency-Key`）：活动是内容哈希，文件是原文件 sha256，录音是音频 sha256。托管站记住最近收到过的键，重复的直接回 `duplicate: true`，内容层面也按 sha256 去重，重试不会产生第二份。
- 同类的新快照替换还没发出去的旧快照（活动只需要最新的）。
- 失败按 30 秒、1 分、2 分……最多 1 小时退避；401/403（令牌被撤销）停止发送并在 `/device` 页面说明；400/413 之类的永久错误移到 `outbox/dead/`，不再重试。
- 活动每 2 分钟看一次有没有变化；文件夹和录音在本机读完、转写完立即发。

## 接口

托管站（全部先过 `isCrossSiteWrite`，CSRF 发现式测试覆盖）：

- `GET/POST/DELETE /api/device/token`：会话登录，查看、生成、撤销设备令牌。
- `GET /api/device/hello`：设备令牌，确认连接。
- `POST /api/device/activity`、`/api/device/sources`、`/api/device/recordings`：设备令牌，只接受上面说的形状，未知字段一律忽略；每小时最多 600 次。

本机：

- `GET/POST/DELETE /api/device/link`：会话登录，转给 worker 的 `/v1/device/link`（完整模式和设备模式都有）。
- 设备模式下除 `/device`、登录页和静态资源外，本机每个页面都重定向到托管站（`apps/web/proxy.ts`）。

## 给本人的步骤

1. 托管站 设置 → 通用 →「这台电脑」→「生成设备令牌」，复制令牌。
2. 本机浏览器打开 `http://127.0.0.1:3210/device`，地址填 `https://app.crossline.lol`，粘贴令牌，点「连接」。
3. 等几秒，页面显示「已连接，设备模式」。worker 已自行重启；不需要手动重启网页。若没有守护循环（手动 `pnpm worker` 启动的），重新运行 `scripts/start-crossline.ps1`。
4. 在 `/device` 页面确认屏幕活动、作息、键鼠节律、录音转写、文件夹的开关与以前一致（它们本来就存在本机，连接不会改）。
5. 托管站「这台电脑」卡片会显示最后一次收到设备数据的时间。
