# Crossline

跨人生主线执行看板。每条主线是一个身份（默认 研究者 / 创业者 / 创作者 / 投资者，可增删改名），所有主线共享**同一份任务与证据账本**；健康是容量约束，不是又一条竞争主线。全部运行在本机，数据落在本地 SQLite（WAL）。

层级固定为：**主线**（身份名词）→ **长期目标**（「成为 ___ 的<身份>」，每条线可多个）→ **里程碑**（陈述达成的状态）→ **任务**（动词开头的短标题）→ **步骤**（可排进日程的一段）。最多两条主线可设为**硬约束**：它们的固定日程是日历骨架、截止优先、决定可用时段；其余按 12–24 个月主次排序或平行。

设计立场只有一句：**数学只作用于可测量的量，判断只交给 LLM，永远不对 LLM 的输出做数学。** 所以这里没有综合评分、没有贡献度、没有 DAG 求解器——排序依据一律是可数事实（停滞天数、是否复用已有产物、反例条数、实测分钟数）。

第二条立场是**模型说的话必须能被检验**：每个事实、日期、来源都要带逐字引文或真实打开过的网址，通不过确定性校验的输出一律拒收。能让 Codex 自己做的事（读材料、检索、写作、判断）交给 Codex；代码只负责校验、持久化和审批。

文档索引见 [docs/README.md](docs/README.md)；给开发者和 Claude Code 的约定在 [CLAUDE.md](CLAUDE.md)。

## 快速开始

完整走查（含注册、配置、第一次采访）见 [docs/getting-started.md](docs/getting-started.md)。最短版本：

```powershell
pnpm install
pnpm build
pnpm dev        # http://127.0.0.1:3210
pnpm worker     # 后台作业：分析、手册、闸门、日历同步、尽调、转写、屏幕活动
```

常驻运行用 `scripts\start-crossline.ps1`（可反复执行，健康的不动、死掉的拉起）；`scripts\install-startup.ps1` 注册"登录 + 每 15 分钟"的看门狗任务。

## 闭环：先了解你，再规划

```
首次登录 → 设定主线（身份、主次、硬约束）
  → 分阶段访谈（每批几道互不依赖的题逐条作答，可上传课程大纲、论文、简历、录音）
  → 画像（事实、项目、各主线的个性化描述与长期目标候选、建议的可用时段，每条带出处）
  → 画像报告（可分享的前半部分 + 仅自己可见的建议，导出 PDF / 图片）
  → 文件里的日期整批确认，进入日历
  → AI 尽调（联网、来源逐个打开核对）→ 你接受的建议才变成里程碑草稿
  → 里程碑（3–5 个、有先后、带可量化目标和截止）→ 你批准
  → 每个已批准里程碑倒推出任务（进任务库；所属里程碑进入三周窗口才排程）
  → 收集任务 → AI 自动剥离可自动化部分（有已批准里程碑且额度正常时无需点分析）→ 计划批准
  → AI 为任务做一本手册（流程图 + 每步的资料、分析、教程）
  → 你执行（开始 / 带原因的中断 / 完成）→ 提交证据
  → 里程碑闸门判定 → pass 自动验收，可撤销
  → 周复盘、飞轮发现、候选关系批量批准
```

采访、里程碑、尽调的任何结论在你点头之前都是草稿：系统不能替人选择他在朝什么努力。所有改变状态的操作 24 小时内可撤销（顶栏「撤销」、操作后的提示、Ctrl+Z，或在输入框里写「撤销刚才的…」）。

## 界面

系统文字用 Arial + 等线，模型生成的文字用微软雅黑；五条主线各一个颜色；数字一律配图。顶部四个工作视图，右侧是待确认和设置；文案为第三人称，术语固定为 主线 → 里程碑 → 任务 → 步骤（规范见 [docs/copy-style.md](docs/copy-style.md)）。

- **今日 `/`**：下一步的任务卡（主线与课程、进度与当前步骤、截止日与时长可就地修改、下一时段、「→ 支持」其他主线），点卡片打开任务弹窗（顶部是任务内的小助手，可直接改步骤、时长、日期；下面是步骤、教程、材料、标准、记录）；「开始计时」后出现倒计时浮窗；推迟要选原因，系统按原因调整（精力低记一次精力、时间冲突重排、在等人建等待项）。一个输入框接收一切：新任务、日程指令（先预览影响再应用）、长期目标、里程碑（成为草稿）、新主线（接着做该主线的访谈）、记录、撤销与提问（转给小助手）；＋菜单、`@` 引用、批量由 AI 拆分。纵向的今日时间轴，左侧是快捷操作；非工作时段的预排任务为虚线，开始后转为正式。待决事项。
- **主线 `/milestones`**：顶部是主线卡片（拖动排主次、硬约束、长期目标、颜色、新增与归档）和「新建里程碑」对话框。下面是按日期排列的时间轴——里程碑在截止日上，课程分数线是链尾，里程碑之前的刻度是步骤的阶段结果；链内依赖是带箭头的弧线，跨主线关系按来源主线着色、标出关系类型（候选为虚线），悬停里程碑高亮它的全部关联。右侧抽屉就地修改标题、截止日、重要性与分数线，补验收标准，归档；查看任务与步骤、关系与推导、达成后的回顾。草稿按主线整条批准或撤销，已归档的可恢复为草稿。
- **计划 `/plan`**：日 / 周 / 月三种视图共用一份计划；每周容量图、未来 8 周图、「排程依据」表（排程器的真实排序：优先档、重要性滑块、截止日，未排入的写明原因，任务库单列各任务的排入日）；可用时段刷涂（访谈建议的时段在此确认）、排程参数、重要性与截止日的改动都先预览影响再应用。已批准的计划永不被改写；日历在批准之后变动是**分歧不是更新**，系统开新草稿，差异全部记为冲突。
- **任务 `/workbench`**：所有任务的卡片与详情页（与弹窗同一组面板）；任务被拆成步骤，每个步骤单独排程，可整步交给助手；七天内要做的任务自动生成分步教程，上传的材料逐份解析、可预览原文与分析。「任务库」收着远期里程碑倒推出的任务；已归档的可恢复。
- **画像报告 `/portrait`**：访谈结束时生成，可重新生成：画像与核心矛盾、真问题、指南针与能量地图、主线飞轮与长期目标、言行落差与锚（可分享，敏感信息自动隐去），以及现况洞察与可行建议、下一步（仅自己可见）；导出 PDF 或长图，末尾二维码指向 `CROSSLINE_PUBLIC_URL`。
- **待确认 `/approvals`**：本页可决定的事完整列出（待决事项、任务提案、待验收、助手的产出与请求、最近自动生效可撤销），里程碑草稿、计划差异等以计数链接到各自所在页面；顶栏角标显示数量。
- **设置 `/settings`**：左侧分类——通用、时间与提醒、自动化与助手（每类工作「关闭 / 逐次审阅 / 自动」）、个性化（已学到的偏好、原型扩充）、日历与连接、隐私与屏幕活动、用量与体检；全部为点即生效的分段控件。
- 离线：收集与执行命令进入加密的本地队列，联网后重放；永久被拒的进可见的死信，与另一台设备冲突的进冲突列表，都保留原文和原因。

## AI 能力如何落地

每种能力是一个 Skill，通过隔离的 Codex app-server 以**结构化输出**调用（只读沙箱、无 shell、无 MCP；只有尽调和飞轮被授予联网）。每个 Skill 的输出契约和信任检查放在 `packages/core` 同一处，防止两者漂移。模型按任务分三档（顶档：采访、里程碑设计、手册设计；中档：分析、手册检索与撰写、闸门、尽调；低档：事实压缩、解释、助手），额度紧张时自动降一档（闸门与分析不降），每次调用的用量记入账本并显示在设置页。

| 能力 | Skill | 确定性层守住什么 |
|---|---|---|
| 采访 | `crossline-onboarding` | 每个 `confirmed` 事实必须引用真实存在的 `reply-N` / `src-N` 并带逐字引文；推断的只能标 `inferred`，且不覆盖你已确认的；文件里的日期要带含该日的逐字引文，对不上的丢弃 |
| 自动化剥离 | `crossline-automation-stripper` | 每个拆分的 `quote` 必须是捕获原文的逐字子串；改写、翻译、摘要一律拒收 |
| 里程碑设计 | `crossline-milestone-architect` | 每个里程碑要引用画像里的事实、有可量化目标和截止，先后与依赖自洽，至少一条「结果」型标准；你说得具体的每个项目都得有自己的里程碑；跨主线联系必须连两条不同的线、写明依据和反证条件 |
| 尽调 | `crossline-due-diligence` | 来源必须是公开 https 页面且 worker 真打开并核对标题；结论只能引用已验证来源；投资线不得出现买卖建议 |
| 任务手册 | `crossline-manualbook-designer` → `-material-researcher` → `-material-writer` | 流程必须是无回路的链且覆盖全部必需要求；全文只从开放获取站点下载；正文只能引用给定来源、不得自写网址 |
| 证据验收 | `crossline-milestone-gate` | 每条引用逐字出现在证据里；必须逐项交回作业自己的证据契约；`pass` 与各条判定自洽 |
| 飞轮 / 周洞察 | `crossline-flywheel-scout` / `-weekly-insight` | 发现必须带 URL + 读取日期 + 失效条件；关系必须连接两个不同的已存在里程碑，并带主张与反证条件 |
| 画像报告 | `crossline-portrait-writer` | 只依据访谈、事实与本人上传的文件；主线 id 必须存在；分享版隐去模型列出的全部敏感片段 |
| 输入路由 | `crossline-input-router` | 长期目标与里程碑必须落在已有主线，日程指令必须指向未完成的任务，撤销必须指向 24 小时内的操作；对不上的一律按原话收集，不丢一个字 |
| 其他 | `-background-facts` `-plan-explainer` `-assistant` `-goal-backplanner` `-task-titler` | 同样先过各自的校验再落库 |

输出不合格时，拒收原因会在同一个线程上发回让模型修正（最多两次），修正次数记入审计；反复需要修正的 Skill 说明它的 schema 或提示词有问题。详见 [docs/structured-output.md](docs/structured-output.md)。

- **录音转写在本机**：上传录音后用本地 Whisper 转写，音频与文字不出本机；模型首次下载需你同意。
- **屏幕活动默认关闭**，在设置页「隐私与屏幕活动」选择，分两档：只记每天的活跃分钟数；或再加前台应用名和窗口标题（标题只存本机、不发给任何模型、14 天后抹掉；银行 / 密码管理器 / 无痕窗口完全不记录；可随时暂停，设置里能查看和清除）。
- **成本信号**是厂商中立的：只有「窗口用掉多少 / 何时重置」。读不到就拒绝执行，绝不退化成 0%。预算门 70% 告警、85% 降档、100% 只跑人工逐项批准的核心任务。

## 审批

策略集中在 `requiredApproval(action)` 一处，界面只是渲染它；未知动作按最严的一档处理。

| 档位 | 范围 |
|---|---|
| `automatic` | 只读研究、本地草稿、可撤销的材料准备、开放获取资料下载 |
| `batch` | 计划变化、里程碑、候选关系、文件日期批次 |
| `per_item` | 邮件、发布、科研提交、高风险外部使用 |
| `never` | 券商下单、静默修改源日历、非开放获取下载 |

最后一档是**永久禁区**，不是「暂未实现」。

## 通用性

系统不针对特定的人生主线。身份包（`packages/identity-packs`）是可替换的注册表——换成教学 / 木工 / 乐队，种子、关系、信任检查和首页全都继续工作；这由 `apps/web/lib/generality.test.ts` 真实换包证明。新增一条主线只是增加一个包，不修改调度核心。

## 安全边界

由代码强制，不只是文档：

- Microsoft Graph 写入只能指向字面名为 `Crossline` 的日历 / 列表；**读取用另一个类**（`GraphReadSource`），它根本没有写方法。目前只读同步已启用，写回关闭。
- Longbridge 只允许行情类只读工具；content-ops 只接受幂等 `POST /v1/jobs`。二者目前没有真实端点（见「已知未完成」）。
- 摄像头路径已整体移除，精力 API 只接受 `self_report` 的聚合值。
- 所有会改数据的路由先过同源检查；账号之间按 workspace 隔离，每次请求重新查成员关系；Codex supervisor 的每个路由要 30 秒有效的签名令牌。
- 屏幕活动的窗口标题只在本机：不导出、不进任何模型上下文，由 `activity-privacy.test.ts` 在源码层面守住。

## 数据与恢复

- 事件账本 append-only，按 `(workspace_id, idempotency_key)` 幂等；迁移按版本号在事务里整体执行，并先备份。
- `pnpm export` 导出完整快照；有回归测试对着 `sqlite_master` 断言每张表都在导出里。`pnpm doctor:ledger` 检查孤儿行、半迁移和 WAL 体积。
- `scripts\backup-crossline.ps1`：DPAPI 加密 + SHA-256 校验，连 `auth.db` 一起备份。
- `scripts\restore-crossline-backup.ps1`：**真的重建一个可用的 SQLite 账本**并逐表读回校验；写实时账本会被拒绝。

## 验证

```powershell
pnpm typecheck   # 全部工作区包
pnpm test        # vitest，约 850 个用例
pnpm build
pnpm test:e2e    # Playwright，含视觉回归（生产构建）
pnpm verify      # 以上全部，提交前跑这一条
```

需要真实 Codex 的证据脚本（花真实额度，不会作为副作用运行）：

| 脚本 | 覆盖 |
|---|---|
| `gate-analysis-check.ts` | 真实 Codex 分析并上板 |
| `manualbook-check.ts` | 手册：流程链、来源真实打开、校验和一致 |
| `gate-loop-check.ts` | 手册 → 执行 → 证据 → 闸门自动验收 |
| `gate-flywheel-check.ts` | 联网产出带来源的发现与候选关系 |
| `gate-capacity-budget-check.ts` | 精力读数与 70/85/100% 预算降级 |
| `gate-identity-check.ts` | 两账号互相看不到对方数据、撤销 session 立即失效、含 `auth.db` 的备份恢复 |
| `structured-output-check.ts` | 各 Skill 结构化输出的通过率、修正次数、用量 |
| `graph-readonly-check.ts` | 只读 Graph 接入与令牌持久化 |

`trial-report.ts` 读取试用期账本，汇总吞吐、闸门判定、实测工时、模型修正次数，并明确列出账本回答不了的问题。

## 发布闸门

对外部世界的真实接入，与功能验收是两套编号。

- **Gate 1 本地正确性**：通过，有自动验证。
- **Gate 2 只读外部导入**：完成。worker 用持久化令牌拉取工作日历，增量同步，多账号多日历按来源各自授权。
- **Gate 3 Graph 写回**：关闭。
- **Gate 4 Codex 手册与闸门**：完成（真实运行）。
- **Gate 5 content-ops / 投资**：部分。只读状态端点通过检查，但未配置真实 endpoint / token；投资侧只有调用前 allowlist。
- **Gate 6–7 长期验证**：部分。加密恢复演练已真实完成；14 天比较与 4 周试用仍需真实运行数据。
- **身份与私有部署**：完成。真实登录（邮箱密码 + Google）、workspace 隔离、离线多设备、Tailscale 私网跨设备访问。

## 已知未完成

- Graph 写回（Gate 3）未启用，个人 `Crossline` 日历 / 列表是唯一目标。
- content-ops 与 Longbridge 没有真实 endpoint / token，没有真实报告运行证据；对应的连接器代码目前没有生产调用方。
- 中文录音已自动识别语言，但 Whisper 常输出繁体字、也会听错同音词；转简体需要另装一个转换库（未装，等你同意）。
