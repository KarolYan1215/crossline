# Crossline

跨人生主线执行看板。科研、创业、自媒体、投资共享**同一份任务与证据账本**；健康是容量约束，不是第五条竞争主线。全部运行在本机，数据落在本地 SQLite（WAL）。

系统的设计立场只有一句：**数学只作用于可测量的量，判断只交给 LLM，永远不对 LLM 的输出做数学。** 所以这里没有综合评分、没有贡献度、没有 DAG 求解器——排序依据一律是可数事实（停滞天数、是否复用已有产物、反例条数、实测分钟数）。

---

## 快速开始

```powershell
pnpm install
pnpm build
pnpm dev
```

打开 `http://127.0.0.1:3210`。后台作业（分析、材料准备、日历同步、夜间飞轮）需要 worker：

```powershell
pnpm worker
```

生产常驻用 `scripts\start-crossline.ps1`（可反复执行，健康的不动、死掉的拉起）；`scripts\install-startup.ps1` 注册"登录 + 每 15 分钟"的看门狗任务。

## 完整闭环

```
自然语言收集
  → AI 剥离可自动化部分（crossline-automation-stripper）
  → 计划差异批量批准（B/C/A 三视图）
  → AI 准备材料（crossline-material-preparer，写进 .crossline-materials/）
  → 人工执行（开始 / 带原因的中断 / 完成）
  → 提交证据
  → 里程碑闸门判定（crossline-milestone-gate）
  → 判 pass 自动验收，可撤销
  → 周复盘：自动验收逐条列出、飞轮发现、候选关系批量批准
```

## 功能分述

### Today · 执行台

- **收集**只接受自然语言、补充上下文或链接。**没有身份下拉框，没有时长输入框**——分类和估时是 AI 的工作，不是你的。
- **下一行动**按词典序推荐：硬约束 → 截止 → 输入是否齐备 → 精力匹配 → 稳定性 → 减少碎片。同时给一个**低精力替代**和一个**短空档替代**。
- **精力读数**只有三档或 `uncalibrated`，**从不输出连续分数**。没有观测就显示"未标定"并说明还缺什么，而不是猜一个 medium。
- **CARE / CAPACITY** 是健康容量，不参与身份竞争。
- **本机活动采集默认关闭**，首次进 Today 显式询问。开启后只读"距上次输入的毫秒数"和一个不透明的窗口句柄数字——不读窗口标题、不记录按键、不上传任何内容，只保存每天的活跃分钟数与切换次数。
- **昨夜飞轮跑没跑**以及**为什么没跑**如实显示（配额窗口未刷新、你在用电脑、已经跑过）。

### Plan · B / C / A 三视图

三个视图共用同一个 `PlanVersion`。

- **B · 双轨时间轴**：上轨是你的现实（日历导入的只读块 + 人工核心），下轨是 AI 提前准备。真实导入的块与示例块在视觉上一眼可分（`日历 · 只读` vs `示例数据`）。
- **C · 计划差异**：Added / Moved / Removed / Conflict 逐条列出，可整批批准或逐项**采纳／排除**。
- **A · 日 / 周**：整周视图。计划携带**从今天起 7 天**的现实（`CROSSLINE_PLAN_WINDOW_DAYS` 可调），每个导入块带自己的日期；示例块不带日期，跟随你正在看的那天，所以不会明天就变成过去。真实块是实心墨块，示例块是虚线轮廓 —— 与 B 视图同一套区分。

**冲突处理**：日历在你批准计划之后变动，那是**分歧不是更新**——已批准的计划**永不被改写**，系统开一个新草稿版本，差异全部记为 `conflict`，由你在 C 视图逐条处理。草稿计划则就地更新。

### Milestones · 里程碑

一切的锚点。WorkOrder 挂在里程碑上，飞轮关系连接里程碑，闸门判定的是里程碑标准。

- **星图**展示跨主线关系（`enables` / `reuses` / `informs` / `constrains` / `recurring_feedback`），**允许循环**——媒体→科研的反馈回路是刻意的，不是需要消除的环。
- **增改查**：新建、修改、批准草稿、归档。**修改写入新版本而不是覆盖**（主键是 `(id, version)`），闸门判过的那一版永远可追溯。
- **AI 提议**：`crossline-milestone-architect` 提议的里程碑一律落成**草稿**。分析和闸门只认已批准的，所以草稿天然惰性——**批准是你的动作**，系统不能替人选择他在朝什么努力。
- **产出 vs 结果**：每条达成标准标注衡量的是"产出物"（现在多了一份文件）还是"结果"（有什么真的变了）。这条区分是判断，所以由 LLM 标注、由你复核，**不由系统计算**。全是产出物的里程碑会被标红警告——但**仍然能保存**，标准归你所有。
- **判断型标准必须写明反证条件**（`failsWhen`）。"做得好"不是标准，"读者无法在不追问的情况下复现步骤"才是。

### Workbench · 作业台

- 展示 SQLite 里真实的 WorkOrder、估时区间、材料引用和阻塞原因。
- **被阻塞的收集可以重新分析**，每次尝试有自己的幂等键，不会永久卡死。
- 执行：开始 → 暂停（**必须写中断原因**）→ 恢复 → 完成 → 提交证据。中断分钟数与工作时长分开记录，不会被算成"做得慢"。

### Approvals · 审批

审批策略集中在 `requiredApproval(action)` 一处，界面只是渲染它：

| 档位 | 范围 |
|---|---|
| `automatic` | 只读研究、本地草稿、可撤销的材料准备 |
| `batch` | 计划变化、里程碑、候选关系 |
| `per_item` | 邮件、发布、科研提交、高风险外部使用 |
| `never` | 券商下单、静默修改源日历 |

最后一档是**永久禁区**，不是"暂未实现"。

### Review · 周复盘

- **本周全部自动验收逐条列出**，不折叠成一个数字——看不见的自动化等于没有审计。每条可撤销，撤销后退回证据复核且不丢证据。
- **飞轮发现**：每条必须带真实来源 URL、读取日期和**失效条件**。没有来源、没有日期、没有失效条件的"洞察"不收。
- **候选关系批量批准**：每条摊开显示它**声称什么**、**什么能证伪它**、来源链接，以及可数事实（目标停滞天数、是否复用已有产物、反例条数、历史成本）。没有证据的关系**不能被批准**（可以搁置）；已经决定过的不会被重新决定。
- 停转信号只提示，不自动跑、不自动花配额。

### Connections · 连接

工作日历一行是**观测到的真实状态**（读游标与导入块数），其余各行是声明的目标。声明状态和观测状态是两种不同的断言，只有后者有用。

### 离线

收集在离线时进入 IndexedDB 队列，联网后自动重放。**终端 4xx 不会被永远重试**——进入可见的死信，保留原文、原因和时间，可复制可丢弃。408/429/5xx/网络失败仍然重试；一条坏记录不阻塞它后面的。

## AI 能力如何落地

五种能力各自是一个 Skill，通过隔离的 Codex app-server 调用。每个 Skill 的输入输出契约在 `packages/core`，**契约与信任检查放在同一处**，防止两者漂移。

| 能力 | Skill | 确定性层守住什么 |
|---|---|---|
| 自动化剥离 | `crossline-automation-stripper` | 每个拆分的 `quote` 必须是捕获原文的**逐字子串**；改写、翻译、摘要一律拒收 |
| 材料准备 | `crossline-material-preparer` | 路径必须在作业自己的目录内；媒体类型必须是能真实写出的文本类型；来源必须是真读过的 URL 或本应用提供的 id |
| 证据验收 | `crossline-milestone-gate` | 每条引用必须逐字出现在提交的证据里；`pass` 与各条判定必须自洽，否则 `GATE_VERDICT_INCONSISTENT` |
| 里程碑设计 | `crossline-milestone-architect` | 身份必须存在、标题不得重复、判断型标准必须带反证条件 |
| 长期洞察 / 飞轮 | `crossline-flywheel-scout` | 唯一被授予联网的 Skill。发现必须带 URL + 读取日期 + 失效条件；关系必须连接两个**不同的已存在**里程碑，并带主张和反证条件 |

**成本信号**是厂商中立的——只有"窗口用掉多少 / 何时重置"，没有货币也没有厂商名。读不到就拒绝执行，**绝不退化成 0%**。预算门在 70% 告警、85% 降级（capable 档降为 routine）、100% 只跑人工逐项批准的核心任务。

夜间飞轮锚定真实的配额重置时间，检查你是否在用电脑，**先占位再花钱**。

## 通用性

系统不针对特定的人生主线。身份包（`packages/identity-packs`）是可替换的注册表——换成教学/木工/乐队，种子、关系、信任检查和首页全都继续工作。这条由 `apps/web/lib/generality.test.ts` 真实换包证明，不是声明。

新增一条主线只是增加一个包，**不修改调度核心**。

## 安全边界

这些约束由代码强制，不只是文档：

- Microsoft Graph 写入只能指向字面名为 `Crossline` 的日历/列表；构造函数硬检查，名字不对直接抛出。
- **读取用的是另一个类**（`GraphReadSource`），它**根本没有写方法**——安全性是结构性质而不是条件判断。
- Graph 写入要求显式批准 + ETag 校验；409/412 进冲突中心，禁止后写覆盖。
- Longbridge 只加载行情/新闻/财报/公告/交易日历；账户、持仓、下单接口在暴露给模型之前就被移除。
- content-ops 只接受幂等 `POST /v1/jobs`，通过认证的 `GET /v1/jobs/{id}` 读真实终态。
- 摄像头路径已整体移除。精力 API 只接受 `self_report` 的聚合值，对 `camera_proxy` 直接返回 `CAMERA_ENERGY_PATH_REMOVED`。
- 本机活动采集默认关闭，窗口句柄不落库。

## 数据与恢复

- 事件账本 append-only，按 `(workspace_id, idempotency_key)` 幂等。
- `pnpm export` 导出完整快照（含事件账本）。有回归测试对着 `sqlite_master` 断言**每张表都在导出里**——以后加表忘了加导出会在测试里失败，而不是在某次恢复时才发现。
- `scripts\backup-crossline.ps1` DPAPI 加密 + SHA-256 校验。
- `scripts\restore-crossline-backup.ps1` **真的重建一个可用的 SQLite 账本**并逐表读回校验——能解压只说明文件可读，不说明账本还原得回来。重建只落在 `restored\` 下的新文件，写实时账本会被拒绝。
